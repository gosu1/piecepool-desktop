# DP

> [[알고리즘 스터디]] 2회 주제. 점화식을 세우는 것이 핵심인데, 무엇을 상태로 잡을지가 안 보여서 막혔다. [[태윤]] 선배 말로는 문제 100개를 풀면 보인다고 한다.

## 문제들

1463(1로 만들기)는 풀었다. dp[i] = min(dp[i-1], dp[i/2], dp[i/3]) + 1. 상태가 숫자 하나라 쉬웠다. 11726(2×n 타일링)도 풀었는데 피볼나치와 같다는 걸 알고 나면 쉽다. 2579(계단 오르기)는 스터디 때 못 풀었지만 코테 준비하면서 다시 풀어 이번엔 풀었다 — 다만 [[하은]]이 설명을 기억해서 푼 것이지 스스로 점화식을 세운 건 아니다. 1149(RGB거리)도 풀었는데 계단 문제와 비슷하고, 이전에 어떤 색을 칠했는지가 상태다. 9095(1,2,3 더하기)는 쉬웠다. 12865(배낭)는 못 풀었다 — 2차원 dp가 안 보여서 포기했고, 코테에 나오면 버리기로 했다.

## 하은이의 계단 오르기 설명

마지막 계단을 밟는 경우를 두 가지로 나눈다. 직전 계단을 밟고 왔는지, 안 밟고 왔는지. dp[i] = max(dp[i-2] + s[i], dp[i-3] + s[i-1] + s[i]).

## 이해하지 못한 점

듣고 나면 이핻되는데 왜 스스로 못 세우는지 모르겠다. "상태를 뭐로 잡을지"가 안 보인다. 1463은 상태가 숫자 하나라 쉬웠는데 계단 오르기는 "마지막에 뭘 밟았나"까지 상태에 넣어야 하는 거였다. 계단 문제를 다시 풀어 풀긴 했지만 [[하은]]이 설명을 기억해서 푼 거지 내가 세운 건 아니어서, 근본 문제는 그대로다. 12865(배낭)는 2차원 dp가 아예 안 보인다. [[태윤]] 선배는 DP는 문제 100개 풀면 보인다고 했다. [[김교수님]]께 못 푼다고 했더니 본인도 학부 때 그랬다고 하시며 "점화식은 문제를 작게 만드는 연습이지 공식이 아니다"라고 하셨는데, 뭔가 알 것 같으면서 아직 모르겠다.

결국 [[모두테크 데이터 인턴|모두테크]] 코딩테스트에서 이 약점이 그대로 터졌다 — 점화식 문제에 막혀 하나는 시간 초과였다. 결과가 어떻든 DP는 진짜 잡아야겠다고 결심했다.
