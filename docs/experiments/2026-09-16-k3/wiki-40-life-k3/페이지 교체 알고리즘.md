# 페이지 교체 알고리즘

> 메모리가 꽉 찼을 때 어떤 페이지를 낼지 정하는 알고리즘. FIFO, OPT, LRU, Clock 이 있다. 최적인 OPT 는 미래를 몰라서 못 쓰고 비교 기준으로만 쓰이며, 실제 OS 는 LRU 를 근사한 Clock 을 쓴다.

## 알고리즘

메모리가 꽉 찼을 때 어떤 페이지를 낼지 정한다. [[페이지 폴트]] 를 최소화하는 것이 목표다.

FIFO: 먼저 들어온 것을 낸다. 단순하지만 [[Belady 이상]] 이 있다 — 프레임을 늘렸는데 폴트가 늘어나는 현상.

OPT: 앞으로 제일 안 쓸 페이지를 낸다. 최적이지만 미래를 알아야 해서 불가능하다. 다른 알고리즘의 비교 기준으로 쓴다.

LRU: 가장 오래 안 쓴 것을 낸다. 실용적이지만 정확히 구현하면 비싸다.

Clock: LRU 의 근사다. 참조 비트를 쓴다. 실제 OS 는 이런 근사를 쓴다.

## 최적과 근사의 패턴

[[CPU 스케줄링]] 의 [[SJF]] 가 "최적인데 미래를 몰라서 못 쓴다" 였는데 OPT 도 똑같은 구조다. 최적 알고리즘은 기준으로만 쓰고 실제로는 근사를 쓴다는 패턴이 반복된다.
