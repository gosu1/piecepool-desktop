# CPU 스케줄링

> ready 큐에 있는 [[프로세스]] 중 누구에게 CPU 를 줄지 정하는 일. 알고리즘마다 대기 시간·응답 시간 등이 트레이드오프 관계다.

## 개념

ready 큐에 있는 [[프로세스]] 중에 누구한테 CPU 를 줄 건가를 정하는 문제다.

## 평가 기준

CPU 이용률, 처리량, 대기 시간, 응답 시간, 반환 시간 다섯 가지다. 다 좋게 만들 수는 없고 트레이드오프다.

## 알고리즘

[[FCFS]]: 온 순서대로. 긴 게 먼저 오면 뒤에 다 기다린다(convoy effect).

[[SJF]]: 짧은 것 먼저. 대기 시간이 최소인데 얼마나 걸릴지 미리 모른다는 게 문제다. 이론적으로 최적인데 실제로는 못 쓰고, 다음 CPU 버스트를 예측해서 쓴다(지수 평균, 슬라이드 22쪽 수식).

[[우선순위 스케줄링]]: 우선순위가 낮은 것은 영원히 못 받을 수 있다(starvation). aging 으로 해결한다.

[[라운드 로빈]]: 시간 조각(time quantum)씩 돌아가면서 준다. 보통 10~100ms 인데 너무 짧으면 [[컨텍스트 스위치]]만 하다 끝난다.

멀티레벨 큐는 잠깐 나오고 시간이 없어서 넘어갔다. 다음 주에 이어서 한다고 한다.

## 이해하지 못한 점

[[SJF]] 에서 다음 CPU 버스트를 예측한다는 지수 평균 수식(슬라이드 22쪽)은 아직 보지 못했다.
