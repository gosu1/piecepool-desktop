# 클린 코드

> 로버트 마틴의 책. [[도서관 좌석 알림 앱]] 캡스톤에서 [[지훈]]과 코드 스타일이 달라 기준이 필요해 읽기 시작했다. 1~3장은 깨끗한 코드의 정의, 이름 짓기, 함수를, 4~6장은 주석, 형식, 객체와 자료구조를 다룬다. 4~6장은 자바 기준이라 반박할 부분이 많다.

## 읽게 된 계기

[[도서관 좌석 알림 앱]] 캡스톤을 하면서 [[지훈]]이 코드와 내 코드 스타일이 너무 달라 기준이 필요해서 읽었다.

## 1장 깨끗한 코드란

여러 사람이 정의를 말하는데 다 다르고, 공통점은 "읽기 쉽다"는 것이다. 코드는 쓰는 시간보다 읽는 시간이 10배라고 한다. 실제로 [[지훈]]이 코드를 읽는 데 한 시간 걸렸다.

## 2장 이름

의도를 드러낸다. d 대신 elapsedTimeInDays 처럼 쓴다. 발음할 수 있는 이름, 검색할 수 있는 이름을 써야 한다. 내 코드에는 df, df2, tmp 가 넘쳐서 반성했지만, 데이터 분석 코드에서 df 는 관례라고 생각해 이 부분은 반박하고 싶다. 다만 [[모두테크 데이터 인턴|인턴]] 준비로 판다스를 복습하며 df, df2 같은 이름부터 고쳐보기로 했다.

## 3장 함수

작게, 한 가지만, 인수는 적게 쓴다. 인수는 0개가 최고이고 3개 이상은 피하라고 한다. 인수 3개 이상 피하라는 것은 파이썬 함수를 짜다 볼 자주 어기게 되는데, kwargs 로 넘기는 것도 결국 인수가 아닌가 싶다. 일단 [[도서관 좌석 알림 앱]] 캡스톤 코드에서 get_data() 같은 함수 이름부터 바꿔보기로 했다.

## 이해하지 못한 점

"한 가지만" 이 뭔지 모호하다. 추상화 수준이 하나라는 뜻인데 그 수준을 어떻게 정하는지, 예제를 볼 때는 알 것 같지만 내 코드에 적용하려면 모르겠다. 6장도 어렵다 — [[디미터 법칙]]을 파이썬 데이터 분석 코드에 어떻게 적용하는지 모르겠다.

## 4장 주석

주석은 실패다 — 코드로 의도를 드러내지 못해서 주석을 다는 것이다. 좋은 주석은 법적 주석, 의도 설명, 경고 정도이고, 나쁜 주석은 코드를 그대로 설명하는 것과 주석 처리된 코드다. 주석 처리된 코드를 지우라는 것에는 동의한다 — 깃이 있는데 왜 남겨두는가. [[도서관 좌석 알림 앱|캡스톤]] 저장소에 [[지훈]]이 주석 처리한 코드가 200줄쯤 있다.

## 5장 형식

신문처럼 쓴다. 위에서 아래로 갈수록 세부 내용이 나오고, 관련 있는 것끼리 가까이 둔다.

## 6장 객체와 자료구조

객체는 동작을 공개하고 자료를 숨기고, 자료구조는 자료를 공개하고 동작이 없다. 둘을 섞으면 최악이다(절반 객체). [[디미터 법칙]]이 이 장에 나오는데, 파이썬 데이터 분석의 판다스 체이닝과 어떻게 양립하는지 이해하지 못했다.

## 7장 오류 처리

반환 코드 말고 예외를 써야 한다 — 호출부가 매번 검사하지 않아도 되므로. try-catch-finally 를 먼저 쓰고 시작하고, null 을 반환하지도 넘기지도 말라고 한다. [[도서관 좌석 알림 앱|캡스톤]]에서 알림이 안 간 원인이 딱 이 장 내용이었다 — [[지훈]]이 좌석 조회 실패 시 -1 을 반환했는데 호출부가 -1 검사를 빼먹은 곳이 있었던 것이다. 4~6장보다 7장이 제일 실용적이라고 느꼈다.
