# K3 실측 — 팀이 정한 모델로 실제로 돌려 본 결과 (2026-09-16 ~ 17)

팀은 운영 모델을 Kimi K3 로 정했다. 이 실험은 그 K3 로 우리 파이프라인을 **실제 돈을 쓰며** 돌려, 무슨 일이 생기고 얼마가 들고 무엇을 고쳐야 하는지를 잰 것이다. 쓴 돈 $27.72 (약 3만 8천 원).

## 한 문장으로

K3 로 파이프라인이 그대로 돌고, 값은 노트 한 장 100원, 진짜 노트에서 틀린 사실 0 — 그런데 **한글 낱말을 깨뜨리는 결함이 있어서 출시 전에 이걸 막는 코드가 필요하다.**

## 얻은 것 다섯

1. **K3 에서 파이프라인이 그대로 돈다.** 스키마 통과, 코드가 막는 규칙 위반 0. 논문 PDF 26쪽도 한 번에 들어간다. 위키는 전 모델(무료 Gemini)보다 낫다 — 노트 사이 연결("실험 6 결과가 실험 7 로 이어졌다" 같은 것) 12개 중 11개를 만들고, 같은 노트를 세 번 돌려도 결과가 거의 같다 (전 모델은 돌릴 때마다 페이지가 뒤집혔다)
2. **값을 안다.** 노트 한 장 100–140원 · 1분. 논문 한 편 170원 · 2분. 86장 볼트 11,000원 · 1시간 40분. 500장이면 8–12만 원에 하룻밤 — 인입은 백그라운드로 돌리고 진행률·예산 상한이 있어야 한다
3. **K3 설정도 정해졌다.** 생각 깊이는 low (높이면 값만 두 배), 프롬프트는 지금 것 (줄이면 페이지가 빠짐), 관련 페이지 찾기는 임베딩 없이 낱말 겹침(BM25). 더 싼 k2.6 은 노트에 없는 말을 지어내서 안 됨
4. **진짜 노트 18장으로 돌려 봤다.** 대표 본인의 노션·옵시디언 노트 → 위키 44장. 무작위 10장을 열어 봤더니 틀린 사실 0. 두 날짜의 세마포어 노트가 한 페이지로 합쳐지고, 막혔던 자리("교수님 설명이 내 이해와 반대 같아 다시 봐야")도 남는다
5. **결함 하나 — K3 가 한글 낱말을 깨뜨린다.** 해법→핵볍, 파운데이션→파울데어븐, 아무도→아묵도. 열 장 중 일곱 장에 한두 개. 인용문은 코드가 걸러내지만 본문에는 들어간다. **출시 전 1순위로 막는다** (원문과 대조해 되돌리기 + 사전 검사) + Moonshot 에 보고

덤으로: 돈 쓰기 전에 코드 버그 셋을 잡았고(강조 표시 때문에 맞는 인용을 버리던 것 등), "과목 페이지 금지" 규칙이 실제 노트에서는 틀렸다는 것도 알았고(과목 자체의 사실은 과목 페이지에 두는 게 맞다), 논문 PDF 인용이 쪽 경계에서 깨지는 것도 찾았다.

## 다음에 할 일 (순서대로)

1. 한글 깨짐 막기 — 인용은 원문으로 되돌리고, 본문은 사전으로 검사. Moonshot 에 재현 사례 보고
2. 논문 인용을 쪽 경계 너머까지 찾기
3. 같은 이름을 문단마다 다시 링크하는 것 멈추기 (링크의 1/3 이 반복)
4. 과목 규칙 손질
5. 관련 페이지가 커질수록 비싸지는 것 막기 (페이지 크기 상한)

### 32회차 — K3 low 첫 회차: 67/69

`compare.ts --base 28 30 --test 32`: flash-lite 안정 핵 48 중 **1개만 놓치고**(`한글 수사 정규화` 페이지 — K3 는 exp-007 절에 넣었다), flash-lite 가 두 번 다 못 맞힌 12개 중 **11개를 맞혔다.** 판정 "비열등 · 우월". 새로 맞힌 것은 전부 노트 두 장 이상을 이어야 나오는 것들이다 — `exp-006 ↔ exp-007`, `exp-005 ↔ SummaC`, `AIHub ↔ exp-001`, `박사 진학` 페이지, 논문 제목 "Numbers Lie First". flash-lite 의 천장이 "노트를 가로지르는 연결" 이었는데 K3 는 그것을 한다.

정답 세트 손질 둘 (전 회차 소급, 호출 0):

- `must_not_pages` 를 정확 일치로. 앞부분 일치 때문에 `논문`(그릇) 이 정당한 `논문 초안` 을 잡았다 — 잣대의 버그
- `소연` 에 대안 `소연이`. K3 가 사람 페이지를 조사 붙은 이름으로 만들었다. 같은 사람이므로 이름만 다른 실패이고 계획의 규칙대로 대안에 넣었다. 다만 **이름에 조사가 붙은 것은 보이는 오류**로 남는다 — 규칙 2("이름만") 가 있는데도. 2회차에서 또 나오면 센다

### 33회차 — 같은 설정 두 번째: 64/69, 뒤집힘 3

지적 80건: `quote-없음` 74 (영어 PDF 10 — 쪽 경계·하이픈, 한국어 57 — 대부분 베끼다 낸 오타), `링크-해제` 6. 감사: 본문 링크 755 (장당 6.7), 같은 이름 반복 275, 기록 909, 같은 fact 가 두 장 이상에 15. 알려진 깨진 꼴은 4곳뿐인데 이 목록이 연구자 볼트의 낱말(해법·내년…)로 만든 것이라 실제 수는 모른다 — 41회차가 답한다.

### 41회차 — 실제 노트 18장 (S7): D5 의 답

볼트 주인의 실물 노트 — 노션에서 export 한 일상·독서 12장(2025년, 역행자 독서 기록 5 · 데미안 2 · 대학원 진학 · 정체성 · 생산성 · 실천 선언)과 옵시디언 볼트 `K_TOOK_Study` 의 공부 노트 6장(DETR · VLM · 데이터 마이닝 OT · 데드락 · 세마포어 · Reader-Writer). 노션 export 는 파일명에 32자리 ID 가 붙고 한글이 깨져 나와 정리했고, 날짜 없는 7장은 주인의 답("2025년 전반")대로 2025-06-30 으로 근사했다. 볼트 노트는 원본 mtime 을 썼다. 위키는 개인 노트에서 나온 것이라 저장소에 넣지 않는다.

**돌리기 전에 주인이 적은 정답: 있어야 할 페이지 8개.** 결과 6/8 (DETR · 데드락 · 세마포어 · 역행자 · 데미안 · 대학원 진학). 없는 둘을 주인이 보고 판정했다 — `인정욕구` 는 `에니어그램 유형 3` 이 대신한 것이 맞고, `트랜스포머` 는 DETR 노트가 트랜스포머를 많이 다루지 않아 없는 게 맞다. 미리 적은 숫자(6/8)는 고치지 않고 병기한다. 18장 → 44장, $1.50, 24분, 허브 뺀 밀도 2.0.

**규칙이 실물보다 거칠었던 곳 하나.** K3 가 `데이터 마이닝 수업` 페이지를 만들었다 — 규칙 1 은 과목을 그릇이라 금한다. 그런데 열어 보니 안에 든 것은 배우는 것·목표·평가 규칙, 즉 **과목 자체의 사실**이고, 개념(PySpark · MapReduce · 샘플링)은 따로 페이지로 빼고 링크만 걸었다. 규칙이 막으려던 것("운영체제 한 장에 프로세스·세마포어를 다 넣는 것")과 다르다. 규칙 1 을 이렇게 고친다: "과목은 개념의 그릇이 되면 안 된다. 과목 자체의 사실(범위·평가·일정)은 과목 페이지에, 개념은 링크로". 합성 노트에는 OT 노트가 없어서 못 나왔던 수정이다.

## 실험 뒤 할 것 — 값어치 순

1. **깨진 낱말 (K3 결함).** 인용: 노트에 있는 구절과 받침 하나만 다른 quote 는 통과시키고 기록 줄에는 노트의 글자를 쓴다. 본문: hunspell-ko 로 낱말을 검사해 표시(고치지는 않는다). Moonshot 에 재현 사례 보고 (`해법` → `핵볍`, `파운데이션` → `파울데어븐`)
2. **`findQuote` 를 문서 전체로.** 구간에서 못 찾으면 전체에서 찾고 시작 구간의 앵커를 쓴다. 영어 PDF 10건 + 실물 9건이 이것
3. **`autoLink` 절마다 첫 등장만.** 링크의 1/3 이 반복
4. **규칙 1 손질.** 과목 자체의 사실은 과목 페이지에
5. **후보 페이지 크기 상한** (요약 + 고칠 수 있는 절만, 또는 글자 상한) — 비용 곡선의 손잡이
6. 기록 앵커에서 헤딩의 `**` 제거 · `--no-cache` 의미 변경을 README 에 · 프로토콜 `cp -rp`
7. ADR-0002: 미결 "모델" → 결정 (K3 low, 비용 표), "Structured Outputs (Kimi)" → 확인됨 (타입 배열 통과, k2.6 은 울타리), 결정 8 에 mtime 한계, 결정 11 에 `나` 요약 별도 호출은 K3 에서도 필요, 미결에 "페이지 굵기 손잡이" · "노트 안 출처 구분 불가"
8. `exp/embedding-tuning` PR (본문은 주인이)

## 이 실험이 못 말하는 것

- 500장 이상의 규모 — 외삽만. 후보 페이지 비대와 `나` 허브(119 링크)가 어디까지 가는지
- 합성 노트 131장은 한 사람이 노트·프롬프트·정답을 다 쓴 것. 실물 18장이 그 편향을 일부 상쇄했지만 18장이다
- 두 번째 실물 주인 — 다른 사람의 어휘와 굵기 감각
- 세션(query) 쪽 — 이 위키를 AI 가 읽어 답할 때 얼마나 쓸모 있는지는 B 담당 구간

**1. 링크의 1/3 이 같은 이름의 반복이다 — 코드 문제.** K3 회차의 본문 링크 345–382 중 125–164 가 한 페이지 안에서 같은 이름을 다시 건 것이다. `autoLink` 가 이름이 나올 때마다 걸어서 `[[환각]] 비율이 … 숫자 [[환각]]은 … [[환각]] 14.0%` 처럼 된다. 허브 뺀 밀도 5.5 (flash-lite 2.6) 의 절반이 이것이고 읽기에 거슬린다. 절마다 첫 등장만 거는 것이 맞다 — 정답 세트(두 페이지가 이어졌나)에는 영향이 없으므로 이 실험이 끝난 뒤 코드로 고친다.

**2. 기록은 정확하다 — 눈으로 대조.** 32회차 `교수님` 기록 20줄과 `소연이` 15줄을 노트 원문과 하나씩 맞췄다. **틀린 사실 0.** 날짜가 틀린 것 하나 — `할일` 노트(파일명에 날짜 없음)의 기록이 `2026-09-16` 인데, 볼트를 `cp -r` 로 복사하며 mtime 이 오늘로 바뀐 탓이다(결정 8 의 마지막 폴백). 실험 프로토콜은 `cp -rp` 로 고치고, 제품에서도 "볼트를 옮기면 날짜 미상 노트의 날짜가 바뀐다" 는 것을 결정 8 의 한계로 적어야 한다.

**3. 본문(절)에도 깨진 낱말이 들어간다 — K3 의 한국어 결함.** quote 의 오타는 검문이 막지만 절의 본문은 대조할 원문이 없다. 알려진 깨진 꼴(핵법·핵볍·합법·합병면·합볼·낸년·남년·물난·묵은·자륵·자륾·다륾·개척명·개철명·아묵도)을 세면:

| 회차                      | 깨진 낱말 | 페이지 |
| ------------------------- | --------- | ------ |
| K3 low 32                 | 23 곳     | 14/35  |
| K3 low 33                 | 20 곳     | 14/32  |
| K3 low 35                 | 13 곳     | 8/35   |
| K3 low 축소 38            | 7 곳      | 7/29   |
| **K3 high 39 (13장까지)** | 5 곳      | 4/21   |
| k2.6 37                   | 1 곳      | 1/34   |
| flash-lite 28             | 0         | 0/23   |

꼴이 일정하다: **열린 음절에 받침이 붙는다.** 해→핵·합, 무→묵·물, 르→륵·륾, 내→낸·남, 체→척·철, 아무→아묵·아묘. `해법` 은 32회차에서 8번 `핵법`, 35회차에서 10번 `핵볍` 이 됐다. 같은 낱말이 회차마다 다른 꼴로 깨지는 것을 보면 하위 음절 토큰 위에서의 샘플링(K3 는 온도 1.0 고정)이 원인으로 보인다. **effort high 에서도 같은 오타가 난다** (39회차 quote: 아묘도·다륾면·낸년·합볼). 추론 깊이의 문제가 아니라 디코딩의 문제다. 이 목록은 눈에 띈 것만이라 실제는 더 많다.

이것이 오늘 가장 값나가는 발견이다. 한국어 제품에서 본문에 `핵볍` 이 열 번 찍히는 것은 정답 세트 100% 보다 먼저 보인다. 대책 후보 (이 실험 뒤에):

- 절 본문의 한글 낱말 중 원문(노트+기존 페이지)에 없고, 받침 하나만 다른 낱말이 원문에 있으면 그것으로 되돌린다 — 새 종류의 벽. 모델 글을 고치는 것이라 좁게 (받침 추가만, 원문에 있는 낱말로만)
- quote 대조도 같은 규칙으로 좁게 허용해 기록 10–20줄을 되찾는다
- Moonshot 에 재현 사례를 보낸다 (`해법` 한 단어로 재현될 것이다)

시제품(`batchim.py`): 본문의 한글 어절 중 원문 어휘에 없고 한 음절의 받침을 빼면 원문 어휘에 있는 것을 찾았다. 32회차에서 후보 50곳 중 진짜 깨짐이 20곳(핵법이 6 · 낸년 5 · 낸내 2 · 핵법 2 · 물난해서 · 자륵면 · 다륾면 · 따륵면 · 아묵도), 나머지는 활용형(정했다→정해다)을 잘못 잡은 것이다. **사전 없이는 본문 쪽 벽을 못 세운다** — hunspell-ko 같은 사전이 있어야 한다. quote 쪽은 원문이 곧 사전이라 사전 없이 된다: 노트에 있는 구절과 받침 하나만 다른 quote 는 통과시키고 **기록 줄에는 노트의 글자를 쓴다** (모델 글을 고치는 것이 아니라 원문으로 되돌리는 것). 이 실험 뒤에 만든다.

**4. 주제 페이지가 비대해진다.** `한국어 요약의 환각 측정과 완화`(연구 주제 자체)와 `환각` 이 회차마다 5–8천 자·30–46 기록으로 가장 크다. 30장 볼트가 한 주제이니 자연스럽지만, 이 두 장은 사실상 두 번째 허브다. 축소 프롬프트(38)에서 7,752자로 더 커진 것은 페이지를 덜 만들수록 여기로 쏠린다는 뜻이다. 규모(500장)에서 이 페이지가 어떻게 되는지가 실제 노트 단계에서 볼 것 하나.

**5. 이름은 첫 명명에서만 흔들린다.** K3 세 회차의 페이지 이름 합집합 45 중 셋 다 있는 것은 25. 나머지는 거의 같은 것의 다른 이름이다 — `Roit et al. 2023` / `NLI 보상 RL` / `RLHF 환각 줄이기` (같은 논문), `교수님` / `최교수님`, `소연` / `소연이`, `exp-001` / `exp-001 KoBART 재현`, `부모님` / `가족`. 한 회차 안에서는 같은 것이 두 장이 된 적이 없다 (`이름 겹침 의심` 0–1). 즉 처음 이름을 정할 때만 흔들리고, 한 번 정해지면 이후 노트는 `<관련 위키>` 의 이름을 따라간다. 제품(한 볼트가 시간에 걸쳐 자라는 것)에는 이쪽이 중요하다.

**6. `나` 허브.** K3 세 회차 모두 `나` 에 기록 0–1 (규칙 7 준수, flash-lite 는 6–7), 링크 43–45, 요약은 20장째 갱신에서 현재("exp-007 로 14.0%까지")를 말한다.

## 관찰

- **K3 는 느리다.** effort low 에서 호출당 37–57초 (flash-lite 는 몇 초). 30장이면 25분, 86장이면 한 시간. 제품에서 인입은 백그라운드여야 하고 진행률·재개가 필요하다 — `sync_state` 가 재개를 이미 준다
- **프리픽스 캐시는 가끔만 잡힌다.** 같은 시스템 프롬프트(6,912 토큰)를 매번 보내는데 `cached_tokens` 가 32회 중 4회만 찍혔다. 잡히면 그 몫이 $0.3/1M 로 내려가 호출당 $0.02 (입력의 40%) 가 준다. 어림은 usage 가 말하는 대로 계산하고(안 잡힌 호출은 미스 단가), 실제 청구는 콘솔로 대조한다
- **잔액 반영이 늦다.** 호출 뒤 십여 분이 지나도 `/users/me/balance` 가 그대로다. 실행 끝의 잔액 줄은 참고만, 진짜 값은 다음 실행의 시작 잔액과 콘솔
