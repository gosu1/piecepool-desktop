# 한국어 요약의 환각 측정과 완화

> 한국어 [[추상 요약]]의 [[환각]]을 측정하고 완화하는 것을 목표로 하는 연구 주제. 랩미팅에서 주제 발표를 했고, 다음 랩미팅까지 baseline 재현과 [[환각]] 비율 측정이 목표다.

## 교수님 피드백

주제 발표 후 [[교수님]]이 세 가지를 지적했다. 첫째, 영어 결과가 한국어에서 그대로 될 거라고 가정하지 말 것. 안 되는 걸 보이는 것도 결과다. 둘째, 지표 논문만 읽지 말고 빨리 baseline 을 돌려서 [[환각]]이 실제로 얼마나 나오는지 볼 것. 셋째, 사람 평가 없이는 지표를 믿을 수 없으므로 처음부터 사람 평가 데이터를 만들 것.

## 진행 계획

다음 랩미팅까지 baseline 재현과 [[환각]] 비율 측정을 해 와야 한다. 첫 baseline 재현(exp-001)에서 [[KoBART]] 요약 데모 수치를 맞추지 못했다. [[ROUGE]]-1 0.31 / [[ROUGE]]-L 0.29로 데모의 0.52 / 0.47보다 한참 낮았는데, 원인은 토크나이저였다. 원래 [[KoBART]] 토크나이저를 써서 다시 돌린 [[exp-002 baseline 재현]] 에서는 [[ROUGE]]-1 0.50 / [[ROUGE]]-L 0.46으로 재현에 성공했다. 같은 실험에서 생성 요약 50개를 직접 읽어 [[환각]] 비율 22%를 측정했고, 이 50개가 첫 사람 평가 데이터로 스프레드시트에 저장되어 있다. 첫 지표로 붙인 [[FactCC]] 실험([[exp-003 FactCC|exp-003]])은 실패로 끝났다. 가짜 데이터 valid 정확도 0.94였으나 사람 평가 50개에서 정확도 0.58이었고, "[[FactCC]] 스타일은 한국어 뉴스 요약에서 안 된다"는 것이 결과로 남았다. 랩미팅에서 exp-002 재현 성공([[환각]] 22%)과 exp-003 실패(0.58)를 보고했고, [[교수님]]은 [[FactCC]]가 안 되는 이유를 논문에 적고 실패도 표로 낼하라고 했다. 숫자 [[환각]]이 많다는 것에 관심을 보이며 한국어 특성인지 뉴스 특성인지 물었는데 모르겠다고 답했고, 영어 뉴스 요약에서도 숫자 [[환각]]이 많은지 찾아보기로 했다. 두 번째 지표인 [[SummaC]] 실험([[exp-004 SummaC|exp-004]])은 klue/roberta-large-nli와 kss 문장 분리로 ZS를 그대로 적용했다. 사람 평가 50개에서 임계 0.5 기준 정확도 0.72로 [[FactCC]]의 0.58보다 훨씬 나았다. 다만 숫자가 바뀐 [[환각]]을 NLI가 잘 못 잡고, 50개라 신뢰구간이 넓어 사람 평가를 200개로 늘리기로 했다. 그 파일럿이 [[exp-005 사람 평가 파일럿|exp-005]]다. [[소연]]이 100개를 같이 봤고 겹치는 100개의 동의율은 kappa 0.71이었다. [[환각]] 비율은 23.5%로 22%와 비슷했고, [[환각]]의 62%가 숫자·날짜 변경이었다. [[SummaC]]-ZS는 200개에서 정확도 0.70으로 안정적이었다. 평가자 불일치가 '원문에 명시되지 않았지만 추론 가능한' 경우에 몰려, 논문에서는 '원문에서 추론 가능하면 [[환각]] 아님'으로 정의하고 가이드라인에 예시를 적기로 했다. '한국어 뉴스 요약 [[환각]]의 절반 이상이 숫자'라는 것을 이 논문의 발견 후보로 보고 있었는데, 24일 랩미팅에서 exp-004·exp-005를 보고하자 [[교수님]]이 [[숫자 환각]] 62%는 '발견'이라며 앞세우라고 했다. 그러면 핵법(숫자 규칙)이 자연스럽고, 평가 가이드라인은 논문 부록에 넣으라고 했다. kappa 0.71이면 쓸 만하다고도 했다. 다음으로 exp-006과 exp-007을 시작한다. QA 기반 지표([[QAGS]], [[QuestEval]])도 읽었는데, 느려서 학습에 넣기는 어렵고 평가용으로만 쓸 듯하다. 한국어로 쓰려면 한국어 QG 모델이 필요한데 [[현우]]에게 물어보니 쓸 만한 게 없다고 해 [[QAGS]] 방향은 접었다. [[AlignScore]]도 읽었는데, 7가지 태스크 데이터를 정렬 쌍으로 통일해 470만 쌍으로 학습한 모델로 [[SummaC]] 벤치마크에서 SOTA를 찍었다. exp-006 후보인데 학습 비용이 크고, 한국어 버전을 만들려면 7가지 한국어 데이터가 필요하다. [[교수님]]은 핵볐되 안 돼도 된다고 했다. 검증 디코딩 실험([[exp-007 검증 디코딩|exp-007]])도 마쳤다. 지표는 "일치하나"를 재는 것이고 내 목표는 "일치하게 만드는 것"이라 헷갈렸는데, 지표를 먼저 갖춰야 만드는 것도 평가되니 순서는 맞다. 지표 논문만 읽다가 끝날 것 같다는 걱정이 있었는데, [[교수님]]도 같은 걱정을 하시며 다음 면담 때는 숫자를 가져오라고 하셨다. 산업체 세미나([[김OO]] 박사)에서 현업은 사람 평가와 [[LLM-as-judge]] 를 섞어 쓰고 LLM 심판이 사람과 0.8 정도 상관한다고 들었다. 내 사람 평가 200개에 [[LLM-as-judge]] 를 붙여 상관을 재면 논문에 한 절이 더 생기고, 200개면 API 비용도 얼마 안 든다. 세미나의 "숫자, 날짜, 고유명사가 [[환각]]의 대부분"이라는 말이 내 결과([[환각]]의 62%가 숫자)와 같아, 숫자 [[환각]]이 뉴스 특성이 아니라 일반적인 현상일 수 있다는 실마리를 얻었다. 실험 데이터는 한국어 요약 데이터셋을 조사한 끝에 [[AIHub 문서요약]]의 뉴스 부분만 쓰기로 정했다. 생성 요약 레이블이 사람이 쓴 것이라 [[환각]] 없는 참조로 쓸 수 있지만, 레이블 자체에 [[환각]]이 있을 수 있다는 [[소연]]의 지적이 있어 표본 50개를 직접 검수하기로 했다.

exp-006([[exp-006 AlignScore]])을 마쳤다. 한국어 정렬 데이터 4종(KLUE-NLI, KLUE-STS, KorQuAD, AIHub 요약) 약 40만 쌍, 원논문의 1/10으로 klue/roberta-base를 학습했다. 사람 평가 200개에서 정확도 0.74, 스피어만 0.41로 [[SummaC]]-ZS(0.70, 0.36)보다 조금 나았다. 데이터를 늘리면 더 오를 듯하다. 다만 숫자 [[환각]]은 여전히 못 잡아, 요약의 숫자를 뽑아 원문에 있는지 규칙으로 확인하는 숫자 전용 검사를 지표에 얹는 아이디어를 냈다. [[소연]]이는 지표 논문이 아니라 시스템 논문이 되는 것 아니냐고 해서 [[교수님]]께 여쭤보기로 했다. 이걸 [[exp-007 검증 디코딩|exp-007]]에 넣으면 숫자는 규칙으로, 나머지는 NLI로 검사하는 디코딩이 된다.

## 방향 확정

주제 좁히기 면담에서 범위가 정해졌다. 내가 측정과 완화 둘 다를 가져갔는데 [[교수님]]은 둘 다 하면 둘 다 얕아지니 석사 논문이면 하나라고 했다. 다만 측정 없이 완화를 할 수 없으므로 순서는 측정에서 완화이고, 측정은 완화의 도구이며 학회 논문은 완화 쪽으로 내기로 했다. 주제가 좁아지니 처음으로 할 수 있겠다는 느낌이 들었다.
