### 4회차 — 제품 보증 시나리오 (전체 재실행 대신)

| `달리기 / 훈련 원칙` 을 손으로 고친 뒤 재실행 | 잠금 감지는 됐다(`절-잠김`). **그러나 우회한 새 절이 같은 이름이라 빌더가 사용자 절에 합치고 지문을 새로 찍었다** — 다음 정리에서 덮일 상태 |
| 본문 절이 없는 페이지                         | AI 가 `기록` 을 다시 쓰려 하고 우회 로직이 새 절 `기록` 을 만들었다                                                                         |

**고친 것 (전부 코드, 테스트 `scripts/demo/build.test.ts`)**

1. **노트가 바뀌어 다시 정리할 때는 그 노트에서 나온 기록을 먼저 걷어낸다.** 기록은 출처에서 파생된 것이므로 출처가 바뀌면 다시 파생한다. 출처가 _삭제된_ 경우(표시만 남김)와 다르다. 이번 결과에 없는 페이지도 걷어낸 상태로 다시 쓴다. 사용자가 기록 절을 고친 페이지는 건드리지 않는다 → 재실행 뒤 `헬스` 의 10/08 기록이 정확히 3줄
2. **잠긴 절로 우회할 때는 `(추가)` 를 붙인 별개의 절로 둔다.** 빌더도 잠긴 절에는 합치지 않는다(두 겹). 사용자의 글은 글자 그대로, 지문 없이 남는다
3. **`기록`·`요약` 을 겨냥한 replace/new_sections 는 버린다** (`절-보호`)
4. AI 가 fact 앞에 노트 날짜를 또 붙인 것("2026-10-08 2026-10-08 첫 운동…")은 코드가 뗀다
5. 임베딩이 있었으면 잡았을 것: 10/08 노트("러닝머신", "헬스장")에서 `달리기` 가 후보에 안 들어왔다. 글자 일치의 한계이고 뜻 후보가 필요한 자리다

**프롬프트에 더한 것 (5회차부터)**: 이름은 그것만 보고 무엇인지 알 수 있게(`알고리즘` ✗ `알고리즘 스터디` ✓), 다시 쓴 절이 길어지면 주제별로 나누기.

### 프롬프트에 더한 규칙 (write.md)

과목은 그릇 · 사람 기준 · 두 이름은 별칭 · 이름만 보고 알 수 있게 · 연결 문장 보존 · `나` 에 기록 금지 · 규칙 9 (다시 쓰기, 길면 절 나누기, 기록·요약 불가). 마지막 둘(별칭, 기록 불가)은 6회차가 폐기되어 **실측 전**이다.

### 남은 문제

1. **임베딩 없이 돌렸다.** 2~5회차는 글자 일치만으로 후보를 추렸다. "러닝머신·헬스장" 노트에서 `달리기` 가 후보에 안 든 것이 뜻 후보가 필요한 자리다. 한도가 풀리면(태평양 자정) `--embed` 로 5회차를 다시 돌려 차이를 재야 한다
2. **회차 간 편차.** 같은 노트가 어떤 회차에는 `민지` 를 갱신하고 어떤 회차에는 안 한다. 페이지 이름도 흔들린다(`자취 장보기` ↔ `자취`). temperature 0.2 에서도 이렇다. 포착률을 재는 도구가 없다 — "정답 사실 목록" 없이는 못 잰다
3. **같은 주제 두 장** (`러너스 니` / `장경인대 증후군`). 별칭 규칙을 넣었지만 실측 전. 별칭이 안 잡히면 `wiki:lint` 의 "중복" 보고가 마지막 그물이다
4. **다시 쓸 때 사실이 빠질 수 있다.** replace 는 AI 가 기존 문장을 살려야 한다. `기록` 이 있어 잃지는 않지만 본문에서는 사라질 수 있다. 실측으로는 `민지 / 특징` 이 3회차에 잘 녹았으나 보장은 아니다
5. **quote-없음의 절반은 AI 가 떨어진 문장을 `...` 로 이은 것.** 설계대로 걸리지만 그 사실은 버려진다. "한 문장을 넘기지 마십시오" 가 있는데도 그런다
6. **무료 티어 한도**: flash-lite 500회/일, 임베딩 1000항목/일. 62장 볼트 한 번이 62회 + 임베딩 62 + 요약 바뀐 페이지 수. 개발 중 하루 5~6회 전체 실행이 상한
