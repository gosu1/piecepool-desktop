# 레퍼런스 프로젝트 비교: claude-obsidian vs obsidian-second-brain

두 프로젝트 모두 "LLM + 옵시디언 위키" 조합이지만, 접근 방식이 정반대다.

## 한 줄 요약

| | **claude-obsidian** (13k★) | **obsidian-second-brain** (3.5k★) |
|---|---|---|
| 핵심 | 코드가 조율, LLM은 판단자 | LLM이 파일을 직접 읽고 씀 |
| 안전 | 구조적 강제 (트랜잭션) | 규칙 기반 (프롬프트 + hook) |
| 검색 | 전용 검색 엔진 | 로컬 임베딩 + 키워드 혼합 |
| 근거 관리 | 주장 단위 3중 장부 | 페이지 단위 시간축 |

---

## 1. 쓰기 안전

### claude-obsidian — "금고에 넣어야 저장됨"

LLM이 뭘 쓰고 싶든, 바로 파일에 못 쓴다.

1. LLM이 "이걸 쓰고 싶다"는 내용을 JSON 묶음(번들)으로 만듦
2. 코드가 번들을 검사 — 경로가 허용 범위인지, 기존 파일과 충돌 없는지
3. 파괴적 변경(삭제, 덮어쓰기)이면 사용자에게 확인
4. 승인되면 한 번에 적용. 중간에 실패하면 자동으로 되돌림

**비유**: 은행 금고. 입금 전표(번들)를 작성하고, 창구(코드)가 검증하고, 고객(사용자)이 서명해야 실행됨.

### obsidian-second-brain — "규칙을 붙여놓고 믿음"

LLM이 파일을 직접 읽고 쓴다. 대신 규칙이 7겹:

1. "사용자 파일은 건드리지 마" 같은 규칙을 프롬프트에 넣음
2. git commit 전에 hook이 규칙 위반을 검사
3. 소스 파일은 읽기 전용으로 취급

**비유**: 편의점 무인계산대. "훔치지 마세요" 안내문 + CCTV(hook). 대부분은 잘 작동하지만 구조적으로 막지는 못함.

---

## 2. 근거(출처) 관리

### claude-obsidian — "주장마다 증거 서류철"

장부가 3개:
- **원본 장부**: 어떤 파일을 넣었고, 해시(지문)가 뭔지
- **출처 장부**: 각 출처의 신뢰도(공식/1차/2차/커뮤니티/합성/미확인), 신선도, 검토 상태
- **주장 장부**: 위키에 적힌 각 주장이 얼마나 확실한지 (확정/잠정/논쟁/미지지/폐기)

핵심 규칙:
- 위험한 주장(틀리면 큰일나는 것)은 **독립된 출처 2개** 필요
- 출처끼리 모순되면 **둘 다 보존** — 몰래 한쪽을 고르지 않음
- 증거 없으면 차라리 "모른다"로 표시

### obsidian-second-brain — "페이지에 시간표"

- 각 위키 페이지의 프론트매터에 사실의 시간축(언제 알게 됐고, 실제로 언제 일어난 일인지) 기록
- 출처 파일에 신뢰도/신선도 메타데이터
- 하지만 **주장 단위 추적은 없음** — "이 문장의 근거가 뭔지"를 자동으로 알 수 없음

---

## 3. 인제스트 (자료 넣기)

### claude-obsidian

1. 이미 넣은 자료인지 해시(지문)로 확인 → 중복이면 스킵
2. **가치 판단**: 이 자료로 새 위키 페이지를 만들 가치가 있는지 LLM이 판단
3. 페이지 생성 + 주장 추출 + 증거 기록
4. 인덱스 갱신 + 로그
5. 전부 하나의 번들로 묶어서 한 번에 적용

### obsidian-second-brain

1. LLM이 소스 파일을 읽음
2. LLM이 직접 위키 페이지를 작성하고 기존 페이지와 병합 판단
3. LLM이 Write/Edit 도구로 직접 파일 생성/수정
4. commit hook이 규칙 위반 검증

## 6. 핵심 교훈

### claude-obsidian이 증명한 것
- LLM에게 쓰기를 맡기되 **트랜잭션으로 감싸면** 안전하다
- 주장 단위 추적이 있으면 "근거 없는 문장" 방지가 가능하다
- 하지만 **시스템이 매우 복잡해진다**

### obsidian-second-brain이 증명한 것
- LLM 직접 편집도 **규칙만 잘 세우면** 실용적으로 동작한다
- 다양한 워크플로우를 커버할 수 있다
- 하지만 **규칙 위반을 구조적으로 못 막는다**

### 박서준의 하네스 엔지니어링은 둘의 중간
- claude-obsidian처럼 **구조적 안전**(벽 + 검문)을 갖되
- obsidian-second-brain처럼 **LLM에게 자유도**를 주되
- P2-P7처럼 단계를 고정하지 않음
