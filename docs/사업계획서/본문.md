# 1. 문제 인식 (Problem)

## 1-1. 창업아이템의 배경 및 필요성

### 가. 개발 동기

**주당 수백 페이지의 논문과 기술 문헌을 읽고, 과거에 읽은 것을 다시 엮어 새로운 결론을 만들어야 하는 사람들이 있다.** 연구자와 대학원생이 대표적이며, 같은 방식으로 일하는 지식 노동자가 그 주변에 있다. 본 아이템은 이들이 반복적으로 겪는 **'지식 단절'** 에서 출발했다.

지식 단절이란 **분명히 읽었고 분명히 정리해 두었음에도 그 지식에 다시 닿을 수 없는 상태**를 말한다. 본 팀이 겪은 다음의 경험이 그 전형이다.

> DETR 논문을 읽던 중 그 기반이 되는 트랜스포머 구조가 흐릿해졌다. 3학년 1학기에 "딥러닝" 폴더에 정리해 둔 노트가 있다는 것을 알고 있었으므로 그것을 찾았다. **그러나 몇 주차 몇 페이지인지 알 수 없어 슬라이드를 스크롤하고 키워드로 검색하며 몇 분을 썼다.**
>
> 노트를 열자 필요한 내용은 거기 있었다. **그런데 내가 쓴 글인데도 낯설었다.** 다시 읽어도 얼핏 기억나는 수준에 머물렀다. 결국 원본 강의자료와 블로그와 생성형 AI 를 다시 찾아 이해를 복원했다. **전부 합쳐 약 1시간이 걸렸다. 이미 읽었고 이미 정리해 둔 한 개념을 되찾는 데 든 시간이다.**

본 팀은 소프트웨어 전공 학생으로 구성되어 있으며, 주당 약 300페이지의 강의자료와 2편 내외의 논문을 읽는다. **위 경험이 개인의 부주의에서 비롯된 것이 아니라는 점이 중요하다.** 노트는 주제별 폴더에 정리되어 있었고 위치도 알고 있었다. 그럼에도 노트는 제 역할을 하지 못했다.

이후 본 팀은 이 문제를 직접 해결해 보았다. **보유한 노트 전체를 LLM 에 연결하여 참조하게 하는 방식이었고, 실제로 작동했으며 현재도 사용하고 있다.** 그러나 그 과정이 지나치게 복잡했고, 사용을 이어 가면서 구조적인 위험도 확인했다. **작동하는 방식을 알고 있으면서도 일반 사용자가 그 길에 도달할 수 없다는 사실**이 본 아이템의 직접적 동기다.

### 나. 문제 정의

위 경험을 일반화하면 문제는 세 겹으로 나뉜다.

**첫째, 망각은 개인의 부주의가 아니라 필기 방식의 구조적 결과다.**

Mueller 와 Oppenheimer 는 _Psychological Science_ (2014) 에 게재한 세 차례 실험에서, 노트북으로 필기한 학생이 손으로 필기한 학생보다 **개념 이해 문제에서 일관되게 낮은 점수**를 받았음을 보고했다. 원인은 분량이 아니라 방식이었다.

> 노트북 필기자는 **더 많은 단어를 기록하지만 인지적 처리 없이 그대로 옮겨 적으며(verbatim)**, 이것이 학습을 저해한다.

차이가 가장 두드러진 문제 유형이 **"강의에서 들은 두 정보를 종합해 결론을 도출하는 개념 문제"** 였다. 앞서 기술한 경험에서 노트가 "내 말이 아니었다"는 감각의 정체가 이것이다.

따라서 전제를 분명히 한다. **기억이 사라지는 것은 막을 수 없다. 막을 수 있는 것은 다시 이해하는 데 드는 비용이다.**

**둘째, 복원 비용은 반복적으로 발생하며 측정되지 않는다.**

매킨지 글로벌 연구소(MGI)는 지식 노동자가 **근무 시간의 약 20%** 를 사내 정보를 찾거나 도와줄 동료를 찾는 데 쓴다고 보고했다. IDC 는 하루 2.5시간으로 추정하여 두 수치는 약 40% 차이를 보인다. **이 편차 자체가 시사적이다. 해당 시간이 일상에 스며 있어 당사자조차 정확히 인지하지 못한다는 뜻이기 때문이다.**

**셋째, 복원을 도와야 할 노트가 그 역할을 하지 못한다.**

요약 노트는 결론만 남기고 거기에 이르는 경로를 버린다. 그 결과 **요약본이 원본 행세를 한다.** 사용자는 "이 노트에 내용이 다 있다"고 여기지만, 막상 열어 보면 이해가 복원되지 않는다. 원본이 옆에 있어도 그 사실을 인지하기 어렵고, 인지하더라도 원본의 어느 대목이었는지 알 수 없어 다시 찾는 비용이 발생한다.

정리하면 다음과 같다.

| 단계               | 무엇이 깨지는가                         |
| ------------------ | --------------------------------------- |
| 읽고 노트를 남긴다 | 필사 방식이라 이해가 형성되지 않는다    |
| 시간이 지난다      | 망각한다 (불가피)                       |
| 노트를 찾는다      | 원본의 어느 대목이었는지 추적할 수 없다 |
| 노트를 읽는다      | 요약이라 이해가 복원되지 않는다         |
| 원본으로 돌아간다  | **처음부터 다시 찾아야 한다**           |

> 【인터뷰·설문으로 채울 자리】 복원에 걸리는 평균 시간과 **끝내 찾지 못한 비율**.
> 후자가 이 절에서 가장 강한 한 줄이 된다. 측정 문항은 `설문-문항.md` C2 참조.

### 다. 이 문제를 지금 풀어야 하는 이유

이 문제가 단순한 불편에 그치지 않는 이유는, **연구와 학습의 진전이 개별 자료가 아니라 자료 사이의 연결에서 일어나기 때문**이다.

1986년 시카고대학의 Don R. Swanson 은 **문헌 기반 발견(Literature-Based Discovery, LBD)** 분야를 열며 "이미 공개된 지식 안에 아직 발견되지 않은 것이 있다"는 개념을 제시했다. 그의 ABC 모델은 A 와 B 를 연결한 문헌과 B 와 C 를 연결한 문헌이 각각 존재할 때, **A 와 C 를 직접 다룬 연구가 하나도 없더라도** 새로운 가설을 도출할 수 있음을 보였다.

실증 사례가 이를 뒷받침한다. Swanson 은 식이 생선 기름이 혈액 점도를 낮춘다는 문헌과 혈액 점도가 레이노 증후군에 관여한다는 문헌을 연결해 가설을 세웠고, **당시 두 주제를 직접 연결한 연구는 존재하지 않았으나** 그 가설은 이후 임상 연구로 확인되었다.

앞서 기술한 경험도 같은 구조였다. **DETR 을 이해하기 위해 트랜스포머가 필요했다.** 두 개념은 이어져 있으나 두 노트는 이어져 있지 않았고, 그래서 사람이 그 연결을 매번 다시 만들어야 했다.

본 팀의 실측이 이 단절을 수치로 보여준다.

| 볼트                                         | 문서당 본문 링크 수 |
| -------------------------------------------- | ------------------- |
| 한국어 실물 볼트 (132장, 사람이 손으로 관리) | **1.5**             |
| 자동 생성 방식의 이전 시도                   | **0.1**             |

0.1 은 사실상 고립된 문서 더미이며, 1.5 는 서로 얽힌 그물이다. **그리고 1.5 를 유지하는 비용은 현재 전적으로 사람이 부담하고 있다.**

### 라. 기존 대안의 한계

현재 이 문제에 사용되는 방법은 네 가지이며, 각각 구조적 한계를 갖는다.

**① 수작업 지식관리 도구 (Obsidian, Notion 등): 정리 비용을 사용자에게 전가한다.**

링크와 태그와 폴더 체계를 사람이 유지해야 하며, 자료가 늘수록 비용이 함께 증가한다. 본 팀이 면담한 Obsidian 사용자가 지목한 어려움도 **링크를 직접 달아야 한다는 점**이었다.

**② 검색과 RAG: 조각을 찾아 줄 뿐 전체를 꿰지 못한다.**

마이크로소프트 연구진은 이 한계를 명시했다.

> "RAG fails on global questions directed at an entire text corpus, such as 'What are the main themes in the dataset?', since this is inherently a query-focused summarization (QFS) task, rather than an explicit retrieval task."
> — Edge et al., _From Local to Global: A Graph RAG Approach to Query-Focused Summarization_ (arXiv:2404.16130)

더 근본적인 한계는 **읽은 결과가 남지 않는다**는 점이다. 물을 때마다 처음부터 다시 읽고, 읽은 뒤에는 그 이해를 폐기한다. 후속 연구들은 이를 **"지속적인 전역 상태(persistent global state)의 부재"** 로 지적한다.

**③ 상용 AI 메모리 기능: 문서를 남기지 않는다.**

|                | 상용 AI 메모리     | 필요한 것               |
| -------------- | ------------------ | ----------------------- |
| 저장 위치      | 서비스 제공자 서버 | 사용자 디스크           |
| 입력 대상      | 대화               | **자료 + 노트 + 대화**  |
| 결과물         | 대화 기록          | 다른 도구로 열리는 문서 |
| 서비스 이탈 시 | 소멸               | 잔존                    |

두 번째 항목이 결정적이다. **상용 메모리에는 사용자의 자료가 들어가는 입구가 없다.** 수년간 읽은 논문과 축적한 노트는 그 안에 존재하지 않는다.

> 【제출 직전 재확인】 상용 서비스의 메모리 기능은 자주 갱신된다. 각 항목을 제출 직전에 다시 검증할 것.

**④ LLM 직접 연동 (Obsidian MCP 등): 작동하지만 도달할 수 없고 안전하지 않다.**

본 팀이 실제로 사용 중인 방식이므로 가장 정확하게 기술할 수 있다. **기술적으로는 작동한다.** 그러나 두 가지 한계가 있다.

**첫째, 설정 경로가 개발자 전용이다.** 공개된 설정 가이드가 요구하는 절차는 다음과 같다.

| 요구 사항                                       | 일반 연구자의 수행 가능성 |
| ----------------------------------------------- | ------------------------- |
| 터미널에서 `claude mcp add` 실행                | **불가**                  |
| 경로의 공백을 따옴표 또는 백슬래시로 이스케이프 | **불가**                  |
| npx 패키지 설치 및 Node.js 18+ 환경             | **불가**                  |
| `claude mcp list` 출력으로 등록 확인            | **불가**                  |
| MCP 개념 이해 및 오류 자가 진단                 | **불가**                  |

**둘째, 사용자 데이터를 보호하는 구조가 없다.** 이는 사용 후기가 아니라 **공개된 도구 명세에서 도출한 결론**이다.

널리 쓰이는 MCP 서버는 `patch_content`(내용 삽입), `append_content`(덧붙이기), `delete_file`(파일·디렉토리 삭제)을 제공하며, 고급 변형판은 `write_note`(파일 전체 쓰기)까지 제공한다. **그런데 이들 중 어디에도 사용자가 직접 작성한 내용인지 검증하는 장치가 없다.** 따라서 AI 가 손으로 쓴 문단을 덮어쓰는 것을 **구조적으로 막을 수 없다.**

설정 가이드 자체가 이를 간접적으로 인정한다.

> 아직 활발히 개발 중이라 **Vault 백업은 필수**입니다
> 민감한 정보를 넣으면 **Claude 도 읽을 수 있습니다**

**안전을 사용자 개인의 백업 습관에 의존하는 구조다.**

### 마. 필요성

이상을 종합하면, 필요한 것은 더 나은 검색이나 더 큰 모델이 아니다.

> **근거를 유지한 채 스스로 연결되며 쌓이는, 사용자 소유의 지식 기반.**

네 가지 요건을 동시에 충족해야 한다.

1. **근거가 끊기지 않아야 한다.** 모든 기록이 원본의 어느 대목에서 왔는지 되짚을 수 있어야 한다
2. **연결 비용을 사람이 부담하지 않아야 한다.** 링크를 손으로 다는 순간 문제가 원점으로 돌아간다
3. **사용자가 쓴 글이 보호되어야 한다.** 이를 개인의 백업 습관이 아니라 **시스템 구조**가 보장해야 한다
4. **결과가 사용자의 파일로 남아야 한다.** 서비스에 종속되면 지식 자산이 아니라 임대물이다

마지막으로 범위를 명확히 한다. **본 아이템은 새로운 가설을 생성해 주지 않는다. 가설이 생성될 수 있는 조건을 만든다.** 흩어진 자료가 근거를 유지한 채 연결되어 축적되는 것이 그 조건이며, 현재는 그 조건을 갖추는 데 사람의 손이 든다. **그 손을 대신하는 것이 본 아이템의 목적이다.**
