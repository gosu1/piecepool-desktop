# 사용자 인터뷰 질문지

- 목적: 사업계획서 1-1 의 문제 정의가 우리만의 문제인지 확인한다
- 대상: 논문·강의자료를 주당 여러 편 읽고 다시 찾아야 하는 학부 연구생·대학원생·연구자
- 인원: **5~8명** (같은 말이 세 번 나오면 그건 우리만의 문제가 아니다)
- 시간: 1인당 15~20분
- 기간: 2026-09-12 ~ 09-15

---

## 시작하기 전에

### 이 인터뷰가 실패하는 방법

**의견을 물으면 실패한다.** 의견은 공짜라서 사람들이 친절하게 답해 주고, 그래서 아무 정보가 없다.

| ❌ 물으면 안 되는 것            | ✅ 대신 물을 것                                          |
| ------------------------------- | -------------------------------------------------------- |
| "자료 다시 찾는 게 불편하세요?" | "가장 최근에 예전 자료를 다시 찾았던 일을 떠올려 주세요" |
| "이런 앱이 있으면 쓰시겠어요?"  | "그 문제 때문에 뭔가 해 보신 적 있으세요?"               |
| "AI 가 정리해 주면 좋겠죠?"     | "지금은 어떻게 하고 계세요?"                             |

과거의 행동은 이미 일어난 사실이라 거짓이 섞이지 않는다. 미래의 의향은 전부 추측이다.

### 지켜야 할 것 넷

1. **우리 제품을 설명하지 않는다.** 설명하는 순간 상대가 우리에게 맞춰 답한다. 끝나고 나서 궁금해하면 그때 말한다
2. **침묵을 견딘다.** 상대가 생각하는 중일 때 끼어들지 않는다
3. **"왜요?"를 세 번까지 판다.** 첫 대답은 대개 표면이다
4. **답을 그대로 받아 적는다.** 정리하지 말고 표현 그대로 적는다. 그 표현이 사업계획서에 인용된다

## 섭외 문구 (그대로 복사해서 쓸 것)

> 안녕하세요, ERICA 에서 창업 프로젝트를 준비하고 있는 [이름]입니다.
>
> 연구하시면서 **예전에 읽은 자료를 다시 찾는 경험**에 대해 15분 정도 여쭙고 싶습니다.
> 제품을 홍보하려는 것이 아니라, 저희가 생각하는 문제가 실제로 있는 문제인지 확인하려는 것입니다.
> 편하신 시간에 잠깐만 시간 내 주실 수 있을까요?

## 질문지

### 도입 (2분)

**Q1.** 평소에 어떤 자료를 주로 보시나요? 주당 대략 어느 정도 분량인가요?

**Q2.** 읽으시면서 노트를 남기시나요? 남기신다면 어떤 형태인가요?

---

### 핵심 사건 (8분) — 여기가 인터뷰의 전부다

**Q3.** **가장 최근에** 예전에 읽었던 자료를 다시 찾아야 했던 일을 떠올려 주세요. 언제였나요?

> 상대가 일반론으로 답하면("가끔 그래요") 다시 묻는다.
> "구체적으로 가장 최근 건 하나만 떠올려 주시겠어요?"

**Q4.** 무엇을 찾으려고 하셨나요? 왜 그게 필요했나요?

**Q5.** 어떻게 찾으셨나요? 어디 있는지 바로 아셨나요, 아니면 뒤지셨나요?

**Q6.** 시간이 얼마나 걸렸나요? **결국 찾으셨나요?**

> "못 찾았다"는 답이 나오면 반드시 더 판다.
> "그래서 어떻게 하셨어요?" / "그거 없이 그냥 진행하셨어요?"

**Q7. ⭐ 가장 중요한 질문** — 노트를 보고는 왜 해결이 안 됐나요?

> 상대가 "노트를 봤는데 됐어요"라고 하면 우리 가설이 틀린 것이다. 그대로 기록한다.
> 안 됐다면 파고든다. "뭐가 없었나요?" / "있긴 있었는데 뭐가 문제였나요?"

**Q8.** 결국 어떻게 해결하셨나요? 무엇을 더 보셨나요?

---

### 시도와 포기 (5분)

**Q9. ⭐ 두 번째로 중요한 질문** — 이 문제 때문에 뭔가 해 보신 적 있나요?

- 노트 쓰는 방식을 바꿔 본 적
- 다른 도구를 써 본 적 (Obsidian, Notion, Zotero, 제텔카스텐 등)
- 그러다 그만둔 적

> 아무것도 시도해 본 적이 없다면 **그 고통은 말만큼 크지 않다.** 그것도 중요한 데이터다.
> 도구를 여러 개 갈아탄 사람은 돈을 낼 사람이다.

**Q10.** 그만두셨다면 왜 그만두셨나요?

**Q11.** 혹시 ChatGPT 나 Claude 에 본인 노트나 자료를 넣어서 써 보신 적 있나요?

> "그런 게 되나요?"라는 반응이 나오면, 우리의 "경로가 개발자 전용이다"라는 주장이 확인된다.
> 해 봤다고 하면 어떻게 했는지, 계속 쓰는지, 안 쓴다면 왜인지 판다.

---

### 마무리 (2분)

**Q12.** 미발표 연구 자료나 민감한 내용을 클라우드 AI 서비스에 올리는 것에 대해 어떻게 생각하세요?

**Q13.** 혹시 저희가 여쭤봐야 하는데 안 여쭤본 게 있을까요?

**Q14.** 비슷한 고민 하실 만한 분 한 분만 소개해 주실 수 있을까요?

## 판정 기준 — 돌리기 전에 정해 둔다

**끝나고 나서 해석하면 우리에게 유리한 쪽으로 읽게 된다.** 미리 못 박는다.

### 주 지표: Q7 에서 "근거·출처가 없어서" 또는 "이해가 복원 안 돼서"라고 답한 비율

| 비율               | 판정                 | 조치                                                |
| ------------------ | -------------------- | --------------------------------------------------- |
| **6명 이상 / 8명** | 문제 정의 확인       | 1-1 을 그대로 간다                                  |
| **3~5명 / 8명**    | 문제는 있으나 약하다 | **타겟을 더 좁힌다** (예: 현재 논문 집필 중인 사람) |
| **2명 이하 / 8명** | 문제 정의가 틀렸다   | 그들이 실제로 말한 고통으로 갈아탄다                |

### 보조 지표

| 항목                           | 확인하려는 것                 | 쓰이는 곳              |
| ------------------------------ | ----------------------------- | ---------------------- |
| Q6 에서 "결국 못 찾음" 비율    | 고통의 크기                   | 1-1 의 가장 강한 한 줄 |
| Q6 평균 소요 시간              | 정량화된 고통                 | 1-1 · 1-2              |
| Q9 에서 무언가 시도한 비율     | 지불 의사의 선행 신호         | 1-2 · 3장              |
| Q11 에서 "그런 게 되나요" 비율 | 경로가 개발자 전용이라는 주장 | 1-1 라 절 ④            |
| Q12 거부감 비율                | 로컬 구조의 필요성            | 3장                    |

## 결과 반영

- 1-1 의 【설문으로 채울 자리】 표시를 실제 수치로 교체한다
- 인용할 만한 표현을 1-1 가 절에 **따옴표 그대로** 넣는다
- 판정이 가운데 칸이면 **페르소나를 좁히고 1-2 를 다시 쓴다**
