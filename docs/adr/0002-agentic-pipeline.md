# ADR-0002 — 정리하기를 에이전틱 파이프라인으로 짓는다

- 날짜: 2026-09-07
- 상태: 제안됨
- 대체: [ADR-0001](0001-electron-shell-llm-wiki.md) 의 "LLM 쓰기 = 에이전트가 파일을 직접 편집"

## 맥락

ADR-0001 은 자료를 위키로 편입하는 방식을 **에이전트가 툴로 파일을 직접 편집**하는 것으로 정했다.
그 뒤 `piecepool2` 포크(윤세훈)에서 같은 문제를 **코드가 조율하고 LLM 이 각 단계를 판단**하는
방식으로 다시 설계했고, 프롬프트 명세 6종과 실측 게이트, 노트 13장·위키 3장 픽스처가 나왔다.

두 방식을 비교한 결과 후자를 채택한다.

## 결정

### 1. 조율의 주체는 코드다

정리하기는 단계로 나뉘고, 각 단계는 **입출력이 정의된 순수 함수**다. LLM 은 각 단계의 판단자이지
조율자가 아니다. 단계는 P2(뽑기) · P3(줍기) · P4(같은 것인가) · P5(합치기 제안) · P6(닫기) ·
P7(다시 쓰기)이고, 그 사이의 순서·선택지·검증은 코드가 소유한다.

근거는 넷이고 전부 **단계가 순수 함수라는 성질**에서 나온다.

- **코드가 입력을 좁힌다.** P4 는 코드가 추린 후보 안에서만 고르고, P7 은 코드가 준 링크 목록
  안에서만 링크를 단다. 없는 페이지를 지어내 잇는 경로가 구조적으로 존재하지 않는다
- **코드가 출력을 검증한다.** 목록 밖 답변을 `null` 로 떨어뜨리고, 근거 없는 문장을 버린다
- **코드가 구현을 갈아 끼운다.** 단계마다 다른 모델을 붙일 수 있다. 에이전트 루프는 툴콜
  프로토콜이 대화에 누적되므로 작업 단위로만 모델을 가를 수 있다
- **기록과 요약이 분리된다.** 기록 줄은 append-only 이고 요약·본문만 재생성한다. 에이전트가
  페이지를 통째로 다시 쓰면 재작성마다 LLM 사전지식으로 수렴한다

되돌리기만으로는 부족하다는 점도 근거다. 볼트 git 되돌리기는 **사용자가 손상을 알아차려야**
작동하는데, 이 제품의 목적은 사용자가 위키를 읽지 않아도 되게 만드는 것이다. 공격 지점은
소실이 아니라 **탐지**이고, 파이프라인은 규격 밖 출력을 입구에서 거부해 그 문제를 만들지 않는다.

### 2. 프론트매터 12필드를 마크다운 파일 안에 둔다

`Fm` 을 4필드에서 12필드로 넓힌다 — `title` · `type` · `kind` · `aliases` · `tags` · `relation` ·
`sources` · `created` · `updated` · `compiledAt` · `contested` · `hashes`.

기계용 값을 `.piecepool/` 로 빼는 사이드카 방식은 채택하지 않는다. 근거는 `hashes` 의 성질이다.

- **`hashes` 는 파생 캐시가 아니다.** `.piecepool/index.json` 은 지워도 볼트를 다시 스캔하면
  재빌드되지만, `hashes` 는 "우리가 마지막으로 쓴 글이 무엇이었나"의 기록이라 파일에서 뽑아낼 수
  없다. 잃으면 손편집 보호가 오판해 **사용자 글을 덮는다**
- **되돌리기가 파일 단위다.** 본문과 지문이 다른 파일에 있으면 한쪽만 복원됐을 때 어긋나고,
  안전망이 안전망을 깨뜨린다
- **사이드카가 아끼는 것이 두 필드뿐이다.** `aliases` · `tags` 는 옵시디언 네이티브라 프론트매터가
  아니면 안 먹고, 나머지는 사용자가 읽고 고치는 값이다. 뺄 수 있는 것은 `compiledAt` · `contested`
  둘뿐인데 그것을 위해 두 파일 동기화 비용을 질 이유가 없다

12필드는 **`wiki/` 의 우리가 만든 페이지에만** 붙는다. 사용자 노트에는 붙이지 않으므로
상위 §4.1 의 "임의 옵시디언 볼트를 연다"는 약속은 유지된다.

### 3. 정리 대상은 볼트 안 사용자 노트 전부다

상위 §1.1 이 `processInbox` 의 대상을 `inbox/` 폴더로 좁혔던 것을 되돌린다.

|          | 입력                         | 원본 보관                      |
| -------- | ---------------------------- | ------------------------------ |
| `ingest` | 볼트 **밖** 파일 (PDF·`.md`) | `sources/` 에 남긴다           |
| 정리하기 | 볼트 **안** 사용자 노트 전부 | 없음 — 사용자가 직접 쓴 글이다 |

기준은 그대로 "출처가 볼트 밖이냐 안이냐"이고, **"볼트 안"의 범위만 원래 뜻으로 되돌린다.**
`inbox/` 는 앱에서 쓴 노트가 떨어지는 **기본 자리**로 남고, 정리 대상을 가르는 기준이 아니다.

근거: 기존 노트 뭉치를 볼트로 열었을 때 `inbox/` 만 보면 위키가 하나도 생기지 않는다.
"정리하려면 옮기세요"를 요구하는 것은 이 제품이 없애려는 정리 비용 그 자체다.
`fixtures/vault/` 13장 중 `inbox/` 에 있는 것이 0장인 것이 그 실물이다.

### 4. 검증은 세 층이고 런타임 두 층은 코드가 한다

| 층  | 무엇을 보나                                        | 누가           | 언제             |
| --- | -------------------------------------------------- | -------------- | ---------------- |
| 1   | 형식 — 필드·타입                                   | **코드** (Zod) | 런타임, 매번     |
| 2   | 근거 — `quote` 원문 대조 · `refs` 번호 · 링크 목록 | **코드**       | 런타임, 매번     |
| 3   | 품질 — 요약이 적절한가                             | **LLM 심판**   | **개발 중 eval** |

경계선은 **"정답을 코드가 기계적으로 확인할 수 있나"** 하나다. 확인할 수 있는 것을 LLM 에게
물으면 정확도가 떨어지고 호출이 는다. 무료 한도는 토큰이 아니라 호출 수로 걸린다.

**LLM 도 검증에 한 자리를 갖는다.** P3 이 누락을 줍는다. 코드는 환각을 버리고 LLM 은 누락을
줍는다 — 방향이 반대라 둘 다 필요하다.

실패는 재시도가 아니라 **부분 폐기**로 처리한다. `quote` 가 원문에 없으면 그 사실만 버리고
나머지는 살린다. 출력이 조각나 있어서 가능한 것이고, 파일을 통째로 쓰면 전부 아니면 전무가 된다.

### 5. Zod 를 도입한다

1층 검증이 여기 달린다. LLM 이 낸 JSON 을 손으로 검사하는 코드를 짜지 않는다.
CLAUDE.md §2-2("새 npm 패키지를 설치할 것 같으면 멈추고 물어라")를 이 ADR 이 통과시킨다.

### 6. 뜻 유사 검색(임베딩)이 파이프라인의 기반이다

글자 유사도만으로는 `잠` ↔ `수면` 처럼 뜻이 같고 글자가 다른 쌍을 못 잡는다.
이 한계가 **세 곳에 동시에** 걸린다.

| 어디               | 글자 검색만으로는                                           |
| ------------------ | ----------------------------------------------------------- |
| P4 후보군          | 동의어를 새 이름으로 보고 페이지가 둘 생긴다                |
| P7 의 `search` 툴  | 결정 7 이 준 툴이 글자 검색이면 뜻으로 링크를 못 건다       |
| 쿼리 검색 (B 영역) | `recall@5` 0.40. 놓친 것이 "글자만으로는 닿을 수 없는" 모양 |

셋이 같은 부품을 쓴다. `piecepool2/src/llm/embeddings.ts` 에 Gemini 임베더가 이미 있으므로
**새로 만드는 것이 아니라 연결하는 일**이다.

후보를 추리는 일을 `shortlistCandidates` 한 곳으로 모은다. 4단계는 글자 유사도로 시작하고,
임베딩은 그 한 파일을 고쳐 끼운다. `core/assets.ts` 와 같은 이유다 — 흩어지면 나중에 여러 곳을
고쳐야 하고 하나를 빠뜨린다.

벡터는 `.piecepool/` 아래 **파생 캐시**로 둔다. 지우면 재계산되므로 커밋하지 않는다.
캐시에 모델 이름을 함께 적어, 모델이 바뀌면 버리고 다시 만든다.

**켜기 전에 잰다.** 한국어 2글자 명사의 코사인 유사도가 동의어를 실제로 잡는가,
이름만 넣을 때와 기록 한 줄을 붙일 때 중 어느 쪽이 나은가.

### 7. P7 만 탐색 툴을 갖는다

기계적인 뼈대(형식 검사 · 인용 대조 · 파일 I/O · 세기 · 승격 판정)는 코드가 통제한다.
**본문 작성과 의미적 링크 걸기는 툴을 쥔 에이전트가 한다.**

P7 에만 주는 이유는 **선택지를 미리 좁힐 수 있느냐**다.

| 단계   | 선택지가                                            | 그래서             |
| ------ | --------------------------------------------------- | ------------------ |
| **P4** | 유한하고 미리 안다 — 기존 페이지·후보 전체          | 후보군을 넓힌다    |
| **P7** | 쓰면서 정해진다 — 문장을 써야 무엇을 걸지 알게 된다 | **툴로 찾게 한다** |

P4 는 노트당 1회이고 새 이름 전부를 한 번에 묶어 비용을 아낀 자리다. 툴을 주면 그 최적화가 깨진다.

링크 화이트리스트는 "미리 준 목록"에서 **"실재 확인"** 으로 바뀐다. 없는 페이지에는 여전히
링크를 걸 수 없으므로 환각 방어는 유지된다.

**비용은 는다.** 순수 파이프라인이 속도·비용에서는 이긴다. 이 결정은 링크 밀도라는 구체적 문제
하나를 위해 P7 에만 예산을 쓰는 것이고, 전면 하네스와 달리 **상한이 계산된다** —
페이지당 탐색 턴에 상한을 둔다. 재시도 루프는 몇 번 도는지 알 수 없다.

## ADR-0001 에서 대체되는 것

| 축        | ADR-0001                    | 이 문서                                               |
| --------- | --------------------------- | ----------------------------------------------------- |
| LLM 쓰기  | 에이전트가 파일을 직접 편집 | **코드가 조율하고 LLM 이 단계를 판단**                |
| 환각 방어 | `lint` 가 나중에 관찰       | **입구에서 코드가 거부** + `lint` 는 사후 관찰로 유지 |

유지되는 것: Electron 셸, 타입 없는 `[[]]` 링크, 마크다운이 유일한 진실, 볼트 git 안전망.
**안전망은 그대로 필요하다.** 사용자 편집 봉인과 경로 집합 커밋은 파이프라인에서도 쓴다.

## 기각한 대안

**다시 제안될 것들이므로 근거를 남긴다.**

### 전면 하네스 — 출력 에이전트를 검증 에이전트가 심판하고 통과할 때까지 재시도

- **비용 상한이 없다.** "될 때까지 돌린다"는 몇 번 도는지 모른다는 뜻이다. 무료 한도는 토큰이
  아니라 호출 수로 걸리는데, 지금도 P4 를 이름마다 부르지 않고 한 번에 묶어야 노트 두 장이다
- **코드가 확인할 수 있는 것을 LLM 에게 물으면 정확도가 떨어진다.** 형식·인용 대조·세기는
  코드가 100% 정확하고 0원이다
- **부분 폐기를 못 쓴다.** 파이프라인이 재시도 없이 도는 것은 출력이 조각나 있어서다 —
  `quote` 가 틀린 사실 하나만 버리고 나머지는 살린다. 파일을 통째로 쓰면 전부 아니면 전무가 된다

**다만 개발 중 eval 로는 채택한다**(결정 4 의 3층). 런타임에 품질 점수를 매겨도 사용자가 할 것이
없지만, 개발 중에 재면 프롬프트를 고칠 수 있다.

### 순수 코드 파이프라인 — 어느 단계도 툴을 갖지 않는다

- 속도·비용에서는 이긴다. 그러나 P7 의 링크 가능 목록이 **글자 일치로만** 만들어져
  뜻으로 걸 링크를 놓친다. 링크 밀도 기준선 1.5 를 채울 방법이 없다
- 결정 7 이 P7 에만 툴을 준다. 나머지 단계는 순수 변환으로 남는다

### 사이드카 프론트매터 — 기계용 값을 `.piecepool/` 로 분리한다

- `hashes` 는 파생 캐시가 아니라 **재계산이 불가능한 상태**다. 되돌리기는 파일 단위이므로
  본문과 지문이 다른 파일에 있으면 어긋날 수 있고, 그 순간 손편집 보호가 반대로 작동한다
- **아끼는 것이 두 필드뿐이다.** `aliases`·`tags` 는 옵시디언 네이티브라 프론트매터여야 하고
  나머지는 사용자가 읽는 값이다. 뺄 수 있는 것은 `compiledAt`·`contested` 둘이다

### `inbox/` 한정 유지 — 정리하기가 `inbox/` 폴더만 읽는다

- 설계문서 개정이 가장 적다. 그러나 **기존 노트 뭉치를 볼트로 열면 위키가 하나도 생기지 않는다.**
  "정리하려면 옮기세요"는 `intent.md` 의 제약 2(정리 비용을 요구하지 않는다)를 정면으로 어긴다
- `fixtures/vault/` 13장 중 `inbox/` 에 있는 것이 0장인 것이 그 실물이다

## 결과 — 개정해야 하는 것

| 대상                  | 무엇을                                                  |
| --------------------- | ------------------------------------------------------- |
| 상위 설계 §1.1        | 정리 대상을 `inbox/` 에서 볼트 안 사용자 노트 전부로    |
| 상위 설계 §5          | `Fm` 4필드 → 12필드                                     |
| 상위 설계 §7.2 · §7.3 | 툴 6종과 작업 정의 — 파이프라인 단계로 대체             |
| 0단계 설계 §3 · §8    | 경계면과 동결 등급 재검토                               |
| `src/shared/types.ts` | `Fm` 확장. **동결 파일이므로 합의 필요**                |
| `CLAUDE.md` §2-4      | "4필드는 동결" → "이 ADR 이 정한 12필드 밖으로 나갈 때" |
| `src/core/prompts/`   | 4종 → P2~P7 + query                                     |
| `package.json`        | `zod` 추가                                              |

## 합의가 필요한 안건

- **`agent/tools.ts` 의 동결 등급.** 정리하기에서 툴 6종이 쓰이지 않는다. `query` 가 읽기 전용
  툴을 계속 쓸지는 B 의 결정이고, 그에 따라 이 파일이 반쪽만 남거나 통째로 안 쓰인다 (A·B)
- **수확 경로.** 상위 §8.1 은 "수확 = 대화 로그를 `ingest` 에 넘긴다"인데, 파이프라인이면 그
  로그가 P2~P7 을 탄다. 승격 조건이 "AI 의 답은 출처로 안 센다"이므로 대화 격리는 유지된다 (B)
- **`Fm` 12필드 확장.** 동결 파일 변경 (테크리드)

## 미결

- **임베딩을 4단계에 함께 넣을지, 뒤로 미룰지.** 필요하다는 것은 결정 6 이 확정했다.
  남은 것은 시점이고, P7 의 `search` 툴이 글자 검색만으로 링크 밀도를 얼마나 채우는지에 달렸다
- **단계별 모델 배치.** 한국어 eval 없이 정하지 않는다. 특히 P4 에 싼 모델을 넣으면 `null` 비율이
  올라 이름 동일성 방어가 **조용히** 무력해진다
- **무료 한도를 넘는 지점.** 넘지 않으면 멀티 모델 라우팅의 비용 논거 자체가 성립하지 않는다
