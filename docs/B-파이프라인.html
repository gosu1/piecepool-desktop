piecepool-desktop · B 구간

위키가 답하고, 대화가 위키를 키운다

B 는 wiki → query 의 절반이다. 한 세션이 어떻게 위키를 읽고, 답을 내고, 로그로 남고, 사용자가 고르면 다시 위키로 돌아가는지를 한 장에 그렸다. A 의 ingest 가 어디서 끼어드는지도 함께 표시했다.

B1 → B4 가 각각 그린 것

조각 그림에서 한 일 상태
B1 ask() · 루프 · 세션 로그 검색 → 툴콜 루프 → 답 → 로그. 원래는 답변마다 [[페이지#절]] 을 달고 cite.ts 가 연 절과 대조해 뗐다 PR #11 머지
B2 오른쪽 위 점선 "화면" 쿼리 탭 UI. 답변·참고 줄·[위키에 반영] 버튼이 여기 앉는다. 지금은 CLI 가 대신한다 설계만 · 미착수
B3 [y/N] · harvest() 사용자가 고른 세션만 ingest 에 자료 하나로 넘긴다. 전체 정리가 세션을 자동 흡수하던 길은 닫았다 이 브랜치
B4 점선 cite.ts · 참고 줄 검문을 걷어냈다. 답은 위키를 먼저 찾되 없으면 일반 지식으로, 근거 표시는 답변이 아니라 위키의 (AI) 꼬리표가 맡는다 이 브랜치

B4 는 B2 가 아니라 B1 의 수정이다. renderer/ · ipc.ts 에는 한 줄도 닿지 않았다.

그림이 지키는 세 가지

대화 중에는 읽기만

루프에 쓰기 툴이 없다. "아니 그거 말고" 를 되돌릴 일이 안 생긴다.

쓰기 경로는 ingest 하나

수확은 전용 프롬프트가 아니라 A 의 ingest 를 그대로 부른다. 입력이 PDF 대신 대화 로그일 뿐이다.

사람이 문을 지킨다

창을 닫거나 유휴가 됐다고 반영하지 않는다. y 를 눌러야 들어가고, 안 누른 로그는 남는다.
