## 1. 무엇을 만드나

**위키를 근거로 질문에 답하는 세션을 CLI 로 끝까지 돌린다.**

```bash
npm run query -- fixtures/vault-life "무릎 아픈 거 어떻게 됐지?"
npm run query -- fixtures/vault-life            # 대화 모드
```

AI 가 `search` · `read_note` · `backlinks` · `list_notes` 를 직접 호출해 위키를 탐색하고,
대화가 끝나면 `.piecepool/sessions/<id>.md` 에 로그가 남는다.

**UI 도 수확도 이번 범위가 아니다.** `src/renderer/` 와 `src/shared/ipc.ts` 에 한 줄도 나가지 않는다.

### 1.1 왜 B1 만인가

B(wiki → query)를 한 덩어리로 보면 독립 서브시스템이 아홉이고, 그중 셋이 CLAUDE.md §2("멈추고 물어라")에 걸린다.
분해선은 선행 의존이 결정한다.

| 조각             | 범위                                           | 선행 조건                                                           |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------------------- |
| **B1 (이 문서)** | LLM + 루프 + 읽기 툴 4종 + `ask()` + 세션 로그 | 없음                                                                |
| B2               | UI 배선 — IPC 쿼리 채널 + 대화 화면            | B1 · `shared/ipc.ts` 동결 개봉 합의 · `main/keys.ts` 규정 변경      |
| B3               | 수확 — 세션을 위키에 반영                      | B1 만. **A 이관이 끝나 `ingest.run` 이 구현됐다** (2026-09-18 확인) |

B1 이 첫 조각인 이유는 **유일하게 선행 의존이 없고, 미결(검색 전략·왕복 상한)이 전부 여기 모여 있기 때문**이다.

> **2026-09-18 개정.** 초판(2026-09-17)은 A 이관 전에 썼다. 그 사이 `scripts/demo/` 가
> `src/core/ingest/` 로 옮겨지고 `llm/chat.ts` 가 생겼다. §3 의 전제 하나가 틀렸던 것도 함께 고쳤다 —
> 세션은 위키 증식의 **주 경로**이지 읽기 전용 곁가지가 아니다.

## 3. 제품 원칙과의 관계

| 원칙                                       | 이 설계에서                                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 5. 근거 없는 문장이 위키에 들어가지 않는다 | **B1 이 준비해야 할 것이다.** 세션은 위키 증식의 주 경로이고, 그 경로에서 quote 대조가 무력하다 — §3.1 |
| 6. 사용자 노트가 우리 서버를 거치지 않는다 | 위키 본문이 LLM 공급자로 나간다. 이것은 앱의 전제이지 이 설계의 이탈이 아니다                          |

### 3.1 세션 경로에서는 quote 대조가 무력하다

**초판은 "세션은 읽기 전용이라 위키에 쓰지 않는다"로 원칙 5 를 넘겼다. 경계를 잘못 그은 것이다.**
B1 의 코드가 위키에 쓰지 않는 것은 맞지만, B1 이 만드는 산출물(세션 로그)이 위키로 들어간다.
그리고 **사용자가 노트를 넣는 것보다 대화가 위키를 더 많이 키운다.**

수확은 세션 로그를 자료로 넘기고(`IngestSource = { kind: "session"; log }`),
ingest 는 자료에 대해 quote 대조를 한다.

```ts
// ingest/build.ts — 자료에 그 구절이 실제로 있는가
let hit = findQuote(input.sourceBody, quote);
```

문서를 정리할 때 `sourceBody` 는 **사용자가 쓴 노트**라, "자료에 있는가"가 곧 "근거가 있는가"다.
수확에서는 `sourceBody` 가 **대화 전체 = AI 가 한 말을 포함**한다. 그래서

```
AI 가 지어낸 문장  →  로그 본문에 그대로 있음  →  quote 대조 통과
```

상위 설계 §8.2 가 대화를 ① 사용자가 알려준 새 사실 ② 기존 페이지들의 새로운 종합
③ LLM 이 사전지식으로 채운 것으로 나눈 이유가 이것이다. ①② 는 자산이고 ③ 만 오염인데
**quote 대조는 셋을 구분하지 못한다.**

### 3.2 지금 있는 방어 — 코드로 확인했다 (2026-09-18)

| §8.2 가 규정한 것                      | 지금                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------- |
| 페이지 층 — `sources:` 에 세션 로그    | ✅ ingest 가 `sourceName` 으로 넣는다                                  |
| 문단 층 — 각주 `[^conv-<id>]`          | ❌ **미구현.** `grep -rn "conv-" src/` 가 0건                          |
| `(AI)` 꼬리표                          | ⚠ **기록 줄에만.** 본문 절에는 아무 표시가 없다                        |
| `isAiTurn()`                           | ⚠ **정의만 있고 아무도 쓰지 않는다.** `build.ts` 는 자체 정규식을 쓴다 |
| "AI 턴을 근거로 새 사실을 만들지 마라" | ⚠ 프롬프트 한 줄. 스파이크가 "그것으로는 안 막힌다"고 관측했다         |

**AI 가 지어낸 내용이 본문 절(`new_sections` · `replace_sections`)로 들어가면 흔적이 남지 않는다.**

### 3.3 그래서 B1 이 하는 일

수확이 ①② 와 ③ 을 가르려면 로그에 재료가 있어야 하고, 그 재료를 남기는 것이 B1 이다.

1. **연 경로를 기록한다** — `search` · `read_note` 가 실제로 연 `path#heading` (§9.3)
2. **답변에 근거를 달게 한다** — `[[페이지#절]]`. 프롬프트 규칙이고 **추가 호출은 없다**
3. **코드가 대조한다** — 그 절을 이번 세션에서 실제로 열었는가. 아니면 링크를 떼고 로그에 표시한다

**이것은 증명이 아니라 필터다.**

```
코드가 검증할 수 있는 것    이 링크가 가리키는 절을 실제로 열었는가
코드가 검증할 수 없는 것    이 문장의 내용이 그 절에서 나왔는가
```

잡는 것은 "근거 없이 말하면서 근거 표기도 없는 문단"이고, 못 잡는 것은 "근거를 사칭한 문단"이다.
그래도 값어치가 있는 이유는 **오염의 흔한 모양이 사칭이 아니라 무표기**이기 때문이다 —
스파이크가 관측한 것은 모델이 자연스럽게 아는 것을 말하는 상황이지 출처를 위조하는 상황이 아니었다.
ADR-0002 가 "환각의 런타임 검증 — 절반만 막는다"로 같은 등급의 판단을 이미 했다.

## 5. `search`

### 5.1 색인 단위와 색인 텍스트

```ts
export interface Section {
  path: NotePath; // "wiki/무릎 통증.md"
  page: string; // "무릎 통증"
  heading: string; // "증상" | "요약"
  text: string; // 절 내용 — 반환에 쓰는 표시용
}
```

**색인하는 텍스트와 돌려주는 텍스트를 나눈다.**

```
색인 텍스트 = 페이지 이름 + 별칭 + 절 제목 + 절 내용
표시 텍스트 = 절 내용만
```

이유는 실측이다. `무릎 통증.md` 의 `증상` 절 본문에는 "무릎"이 없다 — 페이지 이름은 파일명에만 있다.
절 본문만 색인하면 `무릎` 질의가 이 절을 찾지 못한다. 이름과 별칭을 모든 절의 색인 텍스트에 넣으면
해결되고, **A 의 `byLiteral`(글자 일치)을 따로 옮길 필요도 없어진다.**

### 5.2 정규화 — 이름을 가른다

| 쓰임                              | 함수                                                 | 규칙                        |
| --------------------------------- | ---------------------------------------------------- | --------------------------- |
| 제목 키 (링크 해석 · 페이지 조회) | `index/links.ts` 의 `normalizeTitle` **그대로 둔다** | NFC + lower + **공백 제거** |
| 본문 폴딩 (검색 대조)             | `index/search.ts` 의 `foldText()` **신규**           | NFC + lower, **공백 유지**  |

CLAUDE.md §4 의 "제목 정규화는 `normalizeTitle()` 하나만 쓴다"는 **제목** 규칙이다.
본문 폴딩은 제목 정규화가 아니므로 이름을 갈라 두면 §4 위반이 아니다.

공백을 지우면 안 되는 이유: 로마자 이름의 단어 경계가 사라진다.
`the OS is` 가 `theosis` 가 되면 별칭 `OS` 가 다시 "cos" · "loss" 에 걸린다
(A 가 PDF 실측으로 막아 둔 것이다).

### 5.3 토크나이저 — 유니그램을 더한다

측정된 실패:

```
"요즘 잠 잘 자?"  → 0건
 요즘 → [요즘]   잠 → [잠]   잘 → [잘]   자 → [자]
 색인: "잠들고" → [잠들, 들고]      ← 만나지 않는다
```

1글자 한글 질의어는 바이그램 색인과 **절대** 만나지 않는다. 자연스러운 한국어 질문인데도 0건이 된다.

**색인과 질의 양쪽에 유니그램 + 바이그램을 넣는다.**

```
"잠들고"  → [잠, 들, 고, 잠들, 들고]
"잠"      → [잠]                      ← 이제 만난다
```

유니그램은 거의 모든 문서에 나와 IDF 가 알아서 점수를 죽인다. 약하게 잡히지만 0건보다 낫다.

**이것은 A 와 B 의 전제가 다르다는 것의 결과다.** A 의 질의는 노트 한 장이라 유니그램은 노이즈만 늘리고,
B 의 질의는 한 줄이라 유니그램이 없으면 못 찾는다. 플래그를 만들지 않는다 — §12 의 이관 시 재측정 항목이다.

### 5.4 BM25

`k1 = 1.2` · `b = 0.75`(교과서 값)를 **그대로 쓴다.** 짧은 질의에서 `b` 를 손볼 근거가 아직 측정으로 없다.
상수로 두고 테스트로 고정한 뒤, 정답 세트가 돌기 시작하면 잰다.

다만 구조는 바꾼다. demo 의 `bm25()` 는 **호출마다 전 문서의 `df` 와 평균 길이를 다시 계산**한다.
A 는 노트당 1회라 괜찮지만 B 는 한 세션에서 여러 번 부른다.
`df` · `tf` · 평균 길이를 **색인 빌드 때 한 번** 계산하고, `search()` 는 질의 토큰만 훑는다.

### 5.5 반환

```ts
export interface Hit {
  path: NotePath;
  heading: string;
  score: number;
  text: string;
}

export function search(ix: WikiIndex, query: string, o?: { limit?: number }): Hit[];
```

| 항목        | 값                          | 왜                                                    |
| ----------- | --------------------------- | ----------------------------------------------------- |
| 기본 개수   | 상위 **5절**                | demo 의 `topN` 5/8 과 같은 자리                       |
| 한 페이지당 | 최대 **2절**                | 한 페이지가 5칸을 다 먹으면 다른 후보가 보이지 않는다 |
| 발췌 길이   | **600자**에서 자른다        | 넘으면 `read_note` 로 가라는 신호                     |
| 0건         | 빈 배열 + 결과에 "0건" 명시 | AI 가 재검색할지 판단할 재료                          |

### 5.6 빌드 시점

`ask()` 가 **세션 시작 시 한 번** 빌드하고 세션 동안 재사용한다.
대화 중에 위키가 바뀔 경로가 B1 에는 없다 (읽기 전용, 수확은 B3).

`backlinks` 는 `index/scan.ts` 의 `scanVault`(구현됨)를 함께 부른다.
`wiki/` 파일을 두 번 읽게 되지만 86장에서 무시할 수준이다 — 합치는 것은 측정 뒤에 한다.

## 6. 툴 4종

```ts
export interface Tool {
  name: ToolName;
  run(args: Record<string, unknown>): Promise<unknown>;
  /** LLM 에게 보낼 툴 정의. args 는 신뢰할 수 없는 JSON 이라 run 이 런타임 검증한다. */
  schema?: { description: string; parameters: Record<string, unknown> };
}
```

`schema` 를 더하는 것은 동결 파기가 아니다 — `tools.ts` 주석이 "4단계에 툴콜 스키마 같은 선택 필드가
추가되는 것은 예정된 증분"이라고 미리 허용했다. 그리고 ADR-0002 가
"B 가 query 를 구현할 때까지 현 상태 유지"로 이 시점을 예고했다.

| 툴                      | 반환                 | 기반                                                                                                          |
| ----------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `search(query, limit?)` | `Hit[]`              | 신규 `index/search.ts`                                                                                        |
| `read_note(path)`       | 원문 문자열          | `vault/notes.ts` 의 `readRaw`(구현됨) + `resolveInVault` 가 경로 탈출 차단                                    |
| `backlinks(path)`       | 들어오는 링크 경로들 | `index/links.ts` 의 `backlinksOf` — **초판이 "이미 구현됨" 이라 적었으나 스텁이었다.** B1 이 구현했다 (§12.3) |
| `list_notes(glob?)`     | 경로 목록            | `vault/tree.ts` 의 `readTree`(구현됨)                                                                         |

**`write_note` · `delete_note` 는 `unimplemented` 로 남긴다.** 쿼리 세션은 위키를 고치지 않는다.

### 6.1 루프가 연 경로를 모은다

`search` 가 돌려준 `Hit` 와 `read_note` 가 연 경로를 루프가 집합으로 쌓는다.
이것이 §3.3 의 근거 대조 기준이자 §9.3 의 로그 재료다.

```ts
/** 이번 세션에서 실제로 본 절. `search` 의 Hit 와 read_note 의 대상. */
type Opened = Set<string>; // "wiki/무릎 통증.md#증상" · "wiki/달리기.md" (전문을 연 경우)
```

`read_note` 는 페이지 전문을 여므로 그 페이지의 **모든 절**이 열린 것으로 친다.
툴이 돌려준 것만 넣는다 — AI 가 인자로 부른 경로가 아니라 **실제로 성공한 호출의 결과**다.
실패한 호출(없는 파일 · 볼트 밖)은 근거가 될 수 없다.

`list_notes("wiki/*")` 가 카탈로그의 절반(이름만, 페이지당 약 1토큰)을 준다.
요약이 없으니 카탈로그를 대체하지는 못하지만, `search` 가 0건일 때 AI 가
"그럼 어떤 페이지가 있지"를 물어볼 길이 된다. 카탈로그 A/B 의 기준선이 이 조합이다.

## 7. 루프

### 7.1 흐름

```
1. 시스템 프롬프트 + 세션 로그 + 질문  →  LLM (tools 첨부)
2. tool_calls 있음  →  실행 → 결과를 메시지에 붙여 → 1 로
3. tool_calls 없음  →  그 텍스트가 답. 종료
4. 왕복 == 상한     →  툴을 떼고 한 번 더 부른다 (이 호출은 상한 밖) → hit_cap: true
```

### 7.2 상한에 걸려도 빈손으로 끝내지 않는다

4번이 이 설계의 핵심이다. 2026-09-09 조회 스파이크에서 관측된 것:

> "답변 실패"는 **왕복 상한 아티팩트**였고(상한을 올리면 답한다), 진짜 근거는 브루트포스 퇴화다.

상한에서 그냥 끊으면 "모델이 못 한 것"과 "상한에 걸린 것"이 로그에서 구분되지 않는다.
툴을 떼고 한 번 더 부르면 답은 나오고, `hit_cap: true` 가 그 답의 성격을 표시한다.
마지막 호출의 지시는 **"지금까지 얻은 근거만으로 답하고, 모자라면 모자란다고 말하라"** 다.

| 항목      | 값                                                                       |
| --------- | ------------------------------------------------------------------------ |
| 기본 상한 | **8 왕복** (검색 2~~3 + `read_note` 2~~3 + 여유)                         |
| 덮어쓰기  | `PIECEPOOL_MAX_TURNS` — demo 가 모델·키를 다루는 방식과 같게             |
| 취소      | **B1 범위 밖.** `loop.ts` 주석의 미확정 항목이고 CLI 에는 Ctrl-C 가 있다 |

상한값은 **측정 대상**이다. 스파이크가 "왕복 상한 값이 실험 결과를 바꾼다"고 남겼으므로
정답 세트를 돌릴 때 이 값을 기록한다.

## 8. LLM 클라이언트

**파일 전환은 A 가 이미 했다** (2026-09-17). `llm/chat.ts` 에 `config()` · `postJson()` ·
`PRICES` · `CallUsage` · `usageLine()` 이 구현돼 있고, 기본 모델은 `kimi-k3`,
기본 base URL 은 `https://api.moonshot.ai/v1` 다. **B 는 그대로 쓴다** —
429 · 5xx 재시도와 Kimi 600초 타임아웃, 캐시 토큰 집계가 공짜로 따라온다.

남은 것은 **`generate()` 하나**다.

```ts
// 지금 — 툴콜을 실을 수 없다
export interface LlmMessage {
  role: "user" | "model";
  text: string;
}
export async function generate(messages: LlmMessage[]): Promise<string>;
```

파일 머리에 A 가 적어 둔 한 줄이 있다.

> 툴콜 없음: AI 는 JSON 하나를 내고 코드가 파일을 쓴다 (ADR-0002 결정 2).

**이것은 정리(ingest)에 대한 서술이지 파일 전체의 규약이 아니다.** 같은 파일이
`generate()` 를 "자유 텍스트 응답. **쿼리(B) 가 쓴다** — 6단계에서 채운다"로 예약해 두었고,
쿼리는 ADR-0002 가 툴을 주기로 한 쪽이다(`ReadOnlyToolName`). B 는 이 자리를 넓힌다.

```ts
export type LlmMessage =
  | { role: "user"; text: string }
  | { role: "model"; text: string; calls?: ToolCall[] }
  | { role: "tool"; callId: string; name: string; result: unknown };

export async function generate(
  messages: LlmMessage[],
  o?: { system?: string; tools?: ToolSpec[] },
): Promise<{ text: string; calls: ToolCall[]; usage: CallUsage }>;
```

### 8.1 ⚠ `model` 변형의 `calls` 를 빠뜨리면 실제 API 가 400 을 낸다 (2026-09-18 수정)

**초판은 `model` 변형을 `{ role, text }` 로만 적었다. 그것이 구현으로 내려가 Critical 이 됐다.**

OpenAI 호환 스펙에서 `role: "tool"` 메시지는 **직전 assistant 메시지의 `tool_calls` 에 같은 id 가
있어야** 한다. `calls` 를 담을 자리가 없으면 2회차 요청이 이렇게 나간다.

```
[system, user, {assistant, content: ""}, {tool, tool_call_id: "c1", …}]
                            ↑ tool_calls 가 없다 → 400
```

**AI 가 툴을 한 번이라도 부르면 세션이 죽는다.** 브랜치 전체 리뷰가 잡을 때까지
7번의 태스크 리뷰가 전부 통과시켰다 — 각 부품은 명세대로였고 **명세가 틀렸기** 때문이다.

테스트도 같은 이유로 못 잡았다. 변환 함수를 **한 턴짜리 입력**으로만 쟀고
(`toApiMessages([{ role: "model", text: "안녕" }])`), 루프 테스트의 가짜 LLM 은
메시지 배열을 **받기만 하고 검사하지 않았다.** 왕복 전체를 한 번도 조립해 보지 않은 것이다.

**교훈: 외부 API 와의 계약은 부품 테스트로 안 잡힌다.** `chat.test.ts` 에
"툴콜을 낸 assistant 턴과 그 결과가 한 요청에 짝으로 실린다" 를 두어 같은 구멍을 막았고,
이 브랜치의 진짜 통과 조건은 테스트 수가 아니라 **툴을 부르는 대화가 한 번 끝까지 도는 것**이다.

`ToolSpec` 을 따로 둔 것도 초판과 다르다 — 초판은 `o?: { tools?: Tool[] }` 로 `llm/` 이
`agent/Tool` 을 알게 했는데, 그러면 계층이 뒤집힌다. 구현이 고른 쪽이 옳다.

`llm/` 은 CLAUDE.md §1 의 **공유 구역**이고 `chat.ts` 는 `OWNER: A`(가배치)라 합의 절차 없이 진행한다.
다만 머리 주석이 "툴콜 없음"이라 **읽는 사람이 오해할 수 있으므로 그 줄을 정리 한정으로 고친다.**
§12 에 A 통보 항목으로 남긴다.

## 9. 세션 — B1 의 주 산출물

**세션 로그는 부산물이 아니다.** §3 에서 정리한 대로 대화가 위키를 가장 많이 키우므로,
로그의 모양이 곧 수확이 쓸 수 있는 재료의 한계다. 초판이 이 절을 계기(instrumentation)로만
다룬 것이 §3 의 잘못된 전제에서 나온 결과였다.

### 9.1 멀티턴

`ask(v, session, question)` 이 `session.log` 에 턴을 누적하고 답을 돌려준다.
지금 `cli/query.ts` 는 단발이라 **대명사를 시험할 수 없다.**
질문 인자가 없으면 대화 모드로 들어가 `ask` 를 반복 호출하도록 고친다. `src/cli/` 는 작업 구역이다.

`그거` 같은 대명사는 **코드가 풀지 않는다.** 세션의 AI 가 대화 로그를 보고 실제 이름으로 복원한 뒤
자기가 검색어를 정해 `search` 를 부른다. `그거` 라는 글자가 `search` 에 들어가는 일은 없다.

### 9.2 로그 형식 — A 가 이미 고정했다

본문 형식은 B 가 정하는 것이 아니라 **A 의 코드·프롬프트·테스트가 이미 전제**하고 있다
(`src/core/ingest/source.ts` · `src/core/prompts/write.md` 입력 절 · `src/core/ingest/tx.test.ts`).
다르게 쓰면 나중에 수확이 조용히 깨진다.

```markdown
---
id: 2026-09-18-1432-11-204Z
model: kimi-k3
turns: 3
tool_calls: 4
hit_cap: false
tokens: { in: 12043, cached: 9120, out: 812 }
usd: 0.0412
opened:
  - wiki/무릎 통증.md#증상
  - wiki/무릎 통증.md#요약
  - wiki/달리기.md
unsourced: 1
---

## 1턴 (사용자)

무릎 아픈 거 어떻게 됐지?

## 2턴 (AI)

9월에 달리기를 시작한 뒤 왼쪽 무릎 바깥쪽에 통증이 왔고, 5km 를 넘기면 시큰거린다.
[[무릎 통증#증상]]

쉬면 나아지는 패턴이라 당분간 거리를 줄이는 게 좋겠다.
```

**계기는 프론트매터에만 둔다.** 본문에 섞으면 수확이 이 파일을 "자료"로 읽어
왕복 수나 토큰이 위키에 "사실"로 들어간다.

`cached` 를 따로 찍는 이유는 카탈로그 A/B 에 캐시 히트율이 필요하기 때문이다 —
스파이크가 "프롬프트 캐싱은 전제"라고 한 값이고, K3 는 캐시 히트가 10배 싸다
(`in: $3` 대 `hit: $0.3` / 1M).

경로는 `.piecepool/sessions/<id>.md` 이고 **커밋 대상**이다 (상위 설계 §8.1).

### 9.3 근거 표기와 대조

`src/core/prompts/query.md` 가 AI 에게 요구하는 것은 한 가지다.

```
답변의 각 문단 끝에 근거를 [[페이지#절]] 로 답니다.
연 적 없는 절을 가리키지 마십시오. 근거가 없으면 링크 없이 그렇게 말하십시오.
```

**추가 호출은 없다.** 같은 답변 턴에 링크가 붙을 뿐이고, 늘어나는 것은 문단당 링크 한 줄이다.

대조는 순수 코드다. §6.1 의 `Opened` 집합과 맞춰 본다.

| 판정                     | 처리                                                |
| ------------------------ | --------------------------------------------------- |
| 링크가 연 절을 가리킨다  | 그대로 둔다                                         |
| 연 적 없는 절을 가리킨다 | **링크를 뗀다.** 글자는 남긴다 — 정보를 잃지 않는다 |
| 문단에 링크가 없다       | 그대로 두되 `unsourced` 를 센다                     |

`unsourced` 가 프론트매터에 남으므로 수확이 "근거 표기 없는 문단이 있는 세션"을 알 수 있고,
사람이 §10.6 에서 볼 때도 어디를 봐야 할지 안다.

**`parseLinks` 를 그대로 쓸 수 없다.** `index/links.ts` 는 `#page=N` 만 남기고
헤딩 fragment 를 버린다(`to = to.slice(0, hash)`). `LinkRef` 는 `shared/types.ts` 의
**FROZEN** 이라 필드를 더하려면 합의가 필요하다. **B1 은 fragment 만 자체 정규식으로 읽고**,
페이지 이름 해석은 기존 `resolveLink` 를 쓴다 — 동결을 건드리지 않는다.

## 10. 오류 처리와 검증

### 10.1 원칙 — 툴 실패는 예외가 아니라 툴 결과다

```
루프를 죽이는 것      LLM 호출 자체가 실패 (재시도 10회 후)
툴 결과로 돌려주는 것  그 밖의 전부
```

| 상황                                     | 반환                                       |
| ---------------------------------------- | ------------------------------------------ |
| LLM 이 준 args 가 불량                   | `{ error: "path 는 문자열이어야 합니다" }` |
| 볼트 밖 경로 (`resolveInVault` 가 throw) | `{ error: "볼트 밖 경로입니다" }`          |
| `read_note` 대상 없음                    | `{ error: "없는 파일입니다" }`             |
| `search` 0건                             | `{ hits: [], note: "0건" }`                |

예외로 죽이면 사용자는 답을 받지 못한다. 툴 결과로 주면 **AI 가 스스로 복구한다** —
툴 기반 설계를 고른 이유가 이것이다.

### 10.2 단위 테스트 (LLM 없이, CI)

| 대상              | 무엇을 고정하나                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `index/search.ts` | 토크나이저(유니그램+바이그램), BM25 랭킹 순서, 페이지당 2절, 발췌 600자, 0건               |
|                   | **회귀: `"요즘 잠 잘 자?"` 가 `수면` 을 찾는다**                                           |
|                   | **회귀: `"무릎"` 이 `무릎 통증` 의 절을 찾는다** (이름이 색인 텍스트에 있어야 통과)        |
| `agent/loop.ts`   | 가짜 LLM 으로 — 툴콜 없으면 종료, **상한 도달 시 툴 없이 한 번 더 부르고 `hit_cap: true`** |
|                   | 성공한 툴 결과만 `Opened` 에 들어간다 (실패한 호출은 안 들어간다)                          |
| `agent/tools.ts`  | args 검증 실패가 throw 가 아니라 결과가 된다, 볼트 밖 경로 거부                            |
| 근거 대조         | 연 절의 링크는 남고, **연 적 없는 절의 링크는 떨어진다** (글자는 남는다)                   |
|                   | 링크 없는 문단이 `unsourced` 로 세어진다                                                   |
|                   | `[[페이지#절]]` 의 fragment 를 읽는다 — `parseLinks` 가 버리는 부분                        |
| 세션 로그         | `## N턴 (사용자)` · `## N턴 (AI)` 형식이 `ingest/tx.test.ts` 의 기대와 일치                |

마지막 항목이 **A↔B 계약 테스트**다. 위키 파싱은 `ingest/wiki.ts` 를 쓰므로 A 의 테스트가 덮는다.

### 10.3 정답 세트 — `eval-query.json`

A 의 `eval.json` 옆에 같은 형식(`|` 로 대안)으로 둔다.

```json
{
  "설명": "질문마다 세션이 열어야 할 페이지. 이름은 | 로 대안을 적는다.",
  "questions": [
    { "q": "무릎 아픈 거 어떻게 됐지?", "must_open": ["러너스 니|장경인대 증후군|무릎"] },
    { "q": "요즘 잠 잘 자?", "must_open": ["수면"] }
  ]
}
```

**채점은 검색 재현율만 자동으로 한다** — 세션이 `search` · `read_note` 로 실제 연 페이지에
`must_open` 이 들어 있는가. 답변 문장의 옳고 그름은 채점하지 않는다.

### 10.4 선행 조건 — 위키가 0장이다

```
vault-lab:  노트 30장 · 위키 0장
vault-life: 노트 87장 · 위키 0장
vault-pm:   노트 15장 · 위키 0장
```

B1 은 위키를 읽는 코드라 검증하려면 위키가 있어야 한다.
`vault-life` 를 **날짜순 앞 30장**으로 만든다.

```bash
node --env-file=.env scripts/demo/index.ts --vault fixtures/vault-life --bm25 --top 8 --limit 30
```

**`npm run ingest` 를 쓰지 않는 이유**: 이관된 `EngineOptions` 는 `force` · `topN` · `meEvery` ·
`maxChars` 만 받고 **`--limit` 도 `--budget` 도 없다.** `npm run ingest -- fixtures/vault-life` 는
87장 전부를 돌려 약 11,000원이 나간다. `scripts/demo/index.ts` 는 이관 뒤에도 남아
`src/core/ingest/` 를 import 하며 그 두 안전장치를 들고 있다 (§12.2).

| 폴더             | 장수 | 성격            |
| ---------------- | ---- | --------------- |
| 강의 10 · 논문 2 | 12   | 학술            |
| 일기 8 · 건강 1  | 9    | 일상            |
| 팀플 5 · 취업 1  | 6    | 인간관계 · 협업 |
| 독서 3           | 3    | 취미            |

**한 성격에 갇히지 않는 것이 요점이다.** `vault-lab` 30장은 전부 학술이라
절 길이 분포가 한쪽으로 쏠린다. 비용은 같다 (약 3,000~4,200원 · 35분, K3 실측 단가 기준).

나중에 `--limit 60` 으로 다시 돌리면 `sync_state` 가 앞 30장을 건너뛰고 31~60장만 처리한다.
개인기록 성격이 짙어지는 뒷부분(요리 · 여행 · 돈)이 그때 들어온다.

### 10.5 통과 조건

1. `npm ci && npx prettier --check . && npm run lint && npm run typecheck && npm test` 전부 통과 (CLAUDE.md §6)
2. `npm run query -- fixtures/vault-life "질문"` 이 답을 내고 `.piecepool/sessions/<id>.md` 가 남는다
3. 대화 모드에서 **`그거` 가 이전 턴으로 해소된다**
4. `eval-query.json` 검색 재현율이 **측정된다**
5. 세션 로그에 `opened` 와 `unsourced` 가 남고, **연 적 없는 절을 가리킨 링크가 떨어져 있다**

4번에 목표 수치를 적지 않는다. **기준선이 없기 때문이다.** 첫 측정이 기준선이고
카탈로그 A/B 가 그것과 비교한다. 지금 숫자를 지어내면 스파이크가 겪은
"1회 측정으로 결론" 실수를 되풀이한다.

### 10.6 사람에게 넘길 것 (CLAUDE.md §7)

- **답변이 옳은가** — 위키와 눈으로 대조한다. 자동 채점하지 않는다
- **근거를 사칭한 문단이 있는가** — §3.3 이 코드로 못 잡는 쪽이다.
  링크는 붙어 있는데 그 절에 없는 말을 한 문단은 사람만 알아본다.
  `unsourced` 가 0 이어도 안전하다는 뜻이 아니다

## 11. 이 설계가 미룬 것

**결정만 적고 미룬 것을 적지 않으면, 나중에 발견한 사람이 버그인지 의도인지 알 수 없다.**

### 11.1 카탈로그 조회

2026-09-09 조회 스파이크는 카탈로그(페이지당 한 줄 요약을 세션 시작 시 주입)를 채택했었다.
보고서 원본은 소실됐고 결론만 남아 있다: 전량 주입은 수천 장에서 실패하고,
`search` 는 없앨 수 없으며, 프롬프트 캐싱이 전제이고, 카탈로그에 `created` 를 넣는 안은 기각 쪽이다.

**그러나 스파이크가 재지 않은 것이 있다 — "카탈로그 없이 `search` 만".**
잰 것은 `전량 주입 대 카탈로그` 와 `카탈로그에서 search 를 뺐을 때` 였다.

그래서 B1 은 `search` 단독으로 짓고, **동작하는 세션으로 카탈로그 A/B 를 잰다.**
그것이 소실된 보고서를 제대로 대체하는 길이다. §9.2 의 계기(`turns` · `tool_calls` · `tokens.cached`)가
그 측정의 재료다.

### 11.2 그 밖

| 미룬 것                                 | 어디로                                                             |
| --------------------------------------- | ------------------------------------------------------------------ |
| 스트리밍 (`llm/stream.ts`)              | B2 — CLI 에는 필요 없다                                            |
| 취소 (`loop.ts`)                        | B2 — CLI 에는 Ctrl-C 가 있다                                       |
| 색인 영속화 (`saveIndex` · `loadIndex`) | 측정으로 필요가 드러나면                                           |
| `sources/` 색인                         | 측정으로 필요가 드러나면                                           |
| BM25 파라미터 조정                      | 볼트 두 성격이 생긴 뒤 (§5.4)                                      |
| 왕복 상한 기본값 확정                   | 정답 세트 반복 측정 뒤 (§7.2)                                      |
| **점수 하한**                           | 첫 정답 세트 측정 뒤 — 아래                                        |
| **프론트매터 계기의 누계화**            | **해소 (2026-09-18, B3 브랜치)** — `SessionStats` · `accumulate()` |
| **`scanVault` 이중 실행 제거**          | **해소 (2026-09-18, B3 브랜치)** — `createTools` 옵션 `index?`     |

**점수 하한 (2026-09-18 발견).** 유니그램을 넣은 탓에 **한국어 질의는 사실상 0건이 나오지 않는다** —
어떤 한글 질문이든 한 글자는 볼트 어딘가와 겹친다. 게다가 작은 코퍼스에서는 희귀한 한 글자가
**오히려 높은 IDF** 를 받아 무관한 절을 끌어올린다(구현 중 `"양자역학"` 0건 테스트가 실패하며 드러났다).

영향 둘: ① §6 의 "`list_notes` 가 `search` 0건의 탈출구" 논리가 약해진다
② 0건 대신 **낮은 점수의 무관한 절**이 나와 AI 가 근거로 삼을 수 있다.

**지금 하한을 두지 않는다** — 근거 없이 숫자를 지어내는 것이고, 이 문서가 "측정 없이
파라미터를 바꾸지 않는다"고 했다. 첫 측정이 실제로 문제인지 드러낸다.

**프론트매터 계기의 누계화.** `session.turns` 는 누적인데 `turns`·`tool_calls`·`tokens`·`usd`·
`opened`·`unsourced` 는 **이번 `ask()` 호출분**이다. 5턴 대화의 로그를 열면 본문에는 10개 턴이 있는데
`usd` 는 마지막 한 턴의 비용이고 `opened` 에는 앞 턴들이 연 절이 빠져 있다.
**B3(수확)이 `opened` 를 근거 재료로 쓰면 앞 턴들의 근거를 잃는다.** `QuerySession` 에 누계 필드를
얹으면 된다(가배치라 자유롭다).

**`scanVault` 이중 실행.** `agent/tools.ts` 안의 `links` 캐시와 `tasks/query.ts` 의 `session.index` 가
**같은 `VaultIndex` 를 각자 만든다.** `backlinks` 를 한 번이라도 부르면 볼트 전체 마크다운을 두 번 읽는다.
§5.6 이 양해한 것은 `buildIndex` + `scanVault` 의 위키 이중 읽기이지 `scanVault` 이중 실행이 아니다.
`createTools` 옵션에 `index?: VaultIndex` 를 더하는 것이(`schema?` 와 같은 가산적 증분) 가장 싸다.

## 12. A 에게 알릴 것 · 이관 시 할 일

**합의가 아니라 통보다** — 전부 `OWNER` 이거나 공유 구역이다.

- **`chat.ts` 머리 주석의 "툴콜 없음" 을 정리 한정으로 고친다.** 파일이 `generate()` 를
  쿼리용으로 예약해 두었는데 머리 주석은 파일 전체 규약처럼 읽힌다 (§8)
- **PIE-64 방어는 닫혔다.** 이관하며 `normalizeTitle` 이 `index/links.ts` 한 벌로 합쳐졌다.
  초판의 통보 항목은 해소됐다

### 12.1 ⚠ 이관이 만든 회귀 — 영어 문맥에서 로마자 이름이 안 잡힌다

`ingest/prompt.ts` 의 `byLiteral` 이 `index/links.ts` 의 `normalizeTitle`(**공백 제거**)을
쓰게 됐는데, `appears()` 는 공백이 남아 있는 전제로 짜인 함수다.

```ts
const hay = normalizeTitle(note.body); // "the DETR model" → "thedetrmodel"
appears(hay, "detr"); // /(^|[^a-z0-9])detr($|[^a-z0-9])/ → 실패
```

실제 코드로 측정했다 (`wiki/DETR.md` · `wiki/달리기.md`, 2026-09-18).

| 본문                                     | 결과                                     |
| ---------------------------------------- | ---------------------------------------- |
| `We evaluate the DETR model on COCO.`    | ❌ 후보 없음                             |
| `the DETR, which uses transformers`      | ❌ 후보 없음                             |
| `DETR 은 객체 검출에 트랜스포머를 쓴다.` | ✅ DETR — 한글이 옆이라 경계가 선다      |
| `오늘 달리기를 5km 했다.`                | ✅ 달리기 — 한글은 부분 일치 경로라 무관 |

**영어 논문을 정리할 때 `DETR` · `ResNet` · `CNN` 이 글자 일치에서 빠진다.**
BM25 가 일부 메우지만, 주석이 "비용이 0 이고 확실하다"고 한 층이 무력해진 상태다.
A 구간이라 이 문서는 보고만 한다 — §5.2 가 B 에서 `foldText` 로 이름을 가르는 이유가 같은 문제다.

### 12.2 실비 안전장치가 `npm run ingest` 에 없다

demo 에 있던 `--limit` · `--budget` · `--expect` 가 `EngineOptions` 로 넘어오지 않았다.
`npm run ingest -- <볼트>` 는 **볼트 전체를 끝까지 돌린다** — 87장이면 약 11,000원이다.
앱의 정리 탭도 같은 엔진을 쓰므로 중간에 멈출 수단이 없다.
K3 실측 기록이 "인입은 백그라운드로 돌리고 **진행률·예산 상한이 있어야 한다**"고 적은 항목이다.

### 12.3 구현하며 드러난 것 (2026-09-18)

- **`backlinksOf` 는 스텁이었다.** 초판 §6 표가 "이미 구현됨" 이라 적었는데 `links.ts` 의
  유일한 스텁이었다. 동결 범위가 `parseLinks` 뿐이고 `index/` 는 공유 구역이며 호출자가
  하나도 없어 **B1 이 첫 소비자로서 구현했다.** 규칙은 `scan.ts` 의 `toGraph` 와 같게 —
  깨진 링크·자기 링크 제외, 중복 제거, 정렬
- **`agent/tools.ts`(FROZEN)에서 `globToRe` 를 export 했다.** 테스트용이다 — Windows 가 `?` 를
  파일명에 못 써서 `list_notes` 경유로는 `?` 이스케이프를 시험할 수 없다.
  **근거: 이 브랜치가 만든 함수라 동결 당시 계약에 없던 심볼이고, 동결이 지키는
  A↔B 경계면(`ToolName`·`ReadOnlyToolName`·`Tool`·`createTools`)은 그대로다.**
  최종 리뷰도 같은 판단이었고, `tools.ts` 머리 마커에 이 예외를 한 줄 적어 두기를 권했다
- **`flatten`(`index/scan.ts`) 과 `blankCode`(`index/links.ts`) 를 export 로 바꿨다.**
  둘 다 B1 이 같은 로직을 복제하려다 리뷰에서 잡혀 공유로 올린 것이다

**hunspell 리스너 누수 (A 에게 넘길 것).** `npm test` 의 `MaxListenersExceededWarning` 은
`ingest/spell.ts` 의 `loadDictionary()` 가 부르는 `hunspell-asm` 이 `uncaughtException` 리스너를
붙이고 떼지 않아서다. 테스트만의 문제가 아니다 — **Electron 처럼 오래 사는 프로세스에서
정리를 반복하면 회당 14MB WASM 과 리스너가 샌다.** 모듈 레벨에 한 번만 로드하면 닫힌다.

**이관 시 재측정할 항목:** A 가 `index/search.ts` 로 갈아탈 때 **유니그램을 유지할지**
62장 볼트로 잰다 (§5.3). A 의 질의는 길어서 유니그램이 노이즈일 수 있다.
다만 `ingest/prompt.ts` 의 `tokens()` 는 **B 가 실측으로 잡은 것과 같은 결함**을 안고 있다 —
바이그램만 쓰므로 1글자 질의어가 색인과 만나지 못한다. 후보 추리기의 재현율 측정값이
그 결함 위에서 나온 숫자다.

## 13. 기각한 대안

- **`scripts/demo` 안에서 먼저 짓기.** 초판이 기각했고, 그 사이 A 이관이 끝나 근거가 더 분명해졌다 —
  옮길 자리가 이미 `src/core/` 다
- **`ingest/prompt.ts` 의 BM25 를 export 시켜 쓰기.** A 구간을 건드려야 하고, 단위(페이지 대 절)와
  토크나이저가 이미 갈라져 한 벌로 묶으면 둘 다 나빠진다 (§4.0.1)
- **카탈로그와 `search` 를 둘 다 짓고 플래그로 전환.** 측정에는 가장 좋지만 두 경로를 동시에 지어
  B1 이 가장 커지고, 플래그가 끝까지 남아 죽은 코드가 될 위험이 있다
- **`list_notes` 를 빼고 툴 3종.** `ReadOnlyToolName` 이 4종으로 동결돼 있고,
  `list_notes` 가 `search` 0건의 탈출구라 뺄 이유가 없다
- **근거 추적을 프롬프트로만 하기** ("지어내지 마라"). 스파이크가 그 한 줄로는 안 막힌다고
  이미 관측했다. 코드가 확인할 수 있는 형태(`[[페이지#절]]` 대조)로 바꾸는 것이
  ADR-0002 가 일관되게 쓴 방법이다
- **근거 추적을 B3 로 미루기.** 미루면 그때는 이미 쌓인 세션 로그에 재료가 없어
  소급해서 복원할 수 없다. 로그는 한 번 쓰면 끝이다
