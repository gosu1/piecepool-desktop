# PiecePool Desktop — 탭과 위키 읽기 — 설계

- 날짜: 2026-09-15
- 상태: 설계 승인됨 (구현 계획 대기)
- 상위 문서: `2026-09-05-electron-rebuild-design.md` — 재구축 전체 설계. 이 문서는 그 **8단계(편집 UI)의 읽기 절반**을 다룬다.
- 선행: `2026-09-14-real-vault-design.md`(트리를 그린다) · `2026-09-15-frameless-chrome-design.md`(상단 드래그 띠)

## 1. 무엇을 만드나

트리에서 파일을 누르면 **탭이 열리고 그 글이 보인다.**

지금은 누르면 본문 영역에 경로 문자열만 뜬다. 파일 내용을 읽는 길이 아예 없다 —
앞 조각이 "파일 내용 읽기·에디터" 를 명시적으로 범위 밖에 뒀기 때문이다.

**읽기만 한다.** 편집·저장·인박스 쓰기는 다음 조각이다.

## 2. 결정 다섯

| 항목      | 결정                              | 기각한 것                      | 근거                                                       |
| --------- | --------------------------------- | ------------------------------ | ---------------------------------------------------------- |
| 읽는 모양 | **원문 문자열**                   | `readNote` 로 `Note` 를 받는다 | `Fm` 4필드가 실제 노트와 안 맞는다 (§2.1)                  |
| 본문 표시 | **프론트매터만 접고 원문 그대로** | 원문 통째 / 마크다운 렌더      | 다음 조각이 CodeMirror 다 — 렌더러는 버리는 일이 된다      |
| 탭 위치   | **본문 영역 위에만** (옵시디언식) | 상단 띠 전폭 (구 레포식)       | 사이드바 위를 덮지 않는다                                  |
| 탭 기능   | **열기·닫기·전환만**              | 재정렬 · dirty · 재시작 복원   | 셋만으로 제품이 쓸모 있게 동작한다                         |
| 탭의 내용 | **탭이 자기 원문을 쥔다**         | 전환할 때마다 다시 읽는다      | 파일 감시가 범위 밖이라 다시 읽어도 최신이라는 보장이 없다 |

### 2.1 `readNote` 를 쓰지 않는 이유

`Note.frontmatter` 는 `Fm` 인데 `Fm` 은 네 필드다 — `title`·`created`·`updated`·`sources`.
그런데 실제 볼트의 위키 노트는 이렇게 생겼다.

```yaml
aliases: [달리기, 조깅] # Fm 에 없다
sources: [...] # 있다
created: 2025-10-03 # 있다
compiledAt: 2026-09-06T09:00:00 # Fm 에 없다
hashes: { 요약: 2751f267 } # Fm 에 없다
```

`readNote` 를 구현하면 `frontmatter.parse` 도 구현해야 하고, 그러면 **실제 노트의 필드 절반이 조용히 버려진다.**
CLAUDE.md §2-4("`Fm` 에 필드를 더해야 할 것 같을 때 멈춘다")에 정확히 걸리는 자리다.

읽기 전용 화면은 그 구조가 필요 없다. `Note`·`Fm` 은 에이전트 파이프라인이 구조를 다루려고 만든 타입이고,
**화면은 글자만 보여 주면 된다.** 다음 조각의 CodeMirror 도 마크다운 **원문**을 편집하므로 같은 모양을 쓴다.

`Fm` 과 실제 노트의 불일치는 **이 조각에서 해결하지 않는다.** 위키 포맷 설계(`docs/adr/legacy/` 옆 2026-09-08 문서)와
함께 다뤄야 할 별개 문제이고, 읽기 전용 뷰어는 그것을 건드리지 않고 지나갈 수 있다.

### 2.2 프론트매터를 접는 이유

`hashes` 블록은 **사용자가 쓴 글이 아니라 도구가 남긴 것**이다. 읽을 때 방해가 된다.
상단 `---` 블록만 잘라내면 되고, 파서가 필요 없다 — 첫 줄이 `---` 일 때 다음 `---` 까지 버린다.

## 3. 경계가 바뀐다 — 이 조각의 무게중심

앞 조각이 세운 불변식이 여기서 깨진다.

> **"renderer 는 경로를 보내지 않는다."** `pickVault()`·`lastVault()` 는 둘 다 인자가 없었다.

`note:read(path)` 는 **renderer 가 고른 경로**를 main 에 보낸다. 두 가지가 따라온다.

### 3.1 `resolveInVault` 를 채운다

`src/core/vault/paths.ts` 는 FROZEN 이고, 주석이 그 자리의 성격을 이미 규정해 뒀다.

> 볼트 밖 경로 탈출을 막는 단일 방어 지점이다. resolve 후 루트 접두사 검사 + realpath 로
> 심볼릭 링크 우회까지 차단한다. **경로 검증을 여기 말고 다른 곳에 두지 않는다.**

앞 계획이 이 스텁을 건드리지 않은 이유가 "renderer 가 경로를 보내지 않으므로 검증할 입력이 없다" 였다.
이제 입력이 생기므로 채운다. **스텁의 본문을 채우는 것은 FROZEN 이 막는 대상이 아니다** —
FROZEN 은 시그니처(계약)를 보호한다. 시그니처는 그대로 둔다.

`assertAgentWritable` 은 **채우지 않는다.** 이 조각에 쓰기가 없다.

### 3.2 main 이 열린 `Vault` 를 쥔다

`resolveInVault(v, p)` 의 `v` 가 필요하다. 앞 조각은 재구축 설계 §3 이 지시한 모듈 변수를
"지금 읽는 곳이 없다" 는 이유로 만들지 않았고(YAGNI), **그 조각의 최종 리뷰가 "다음 조각이 이것을 필요로 한다" 고 예고했다.**
지금이 그때다.

`main/ipc.ts` 가 볼트를 열 때(`open()`) 그 `Vault` 를 모듈 변수에 둔다.
볼트가 없는 상태에서 `note:read` 가 오면 실패로 떨어뜨린다 — 트리가 없으면 누를 것도 없으므로 정상 경로에서는 일어나지 않는다.

### 3.3 왜 이것이 무게중심인가

탭과 본문 표시는 틀리면 **바로 보인다.** 경로 검증은 틀려도 **화면에 아무 표시가 없다** —
볼트 밖 파일을 열어도 그냥 글자가 뜰 뿐이다.

지금은 renderer 가 우리 트리에서 온 경로만 보내므로 안전해 _보인다._
하지만 renderer 는 신뢰 경계 밖이고, "preload 화이트리스트가 공격 표면 전체" 라는 전제가
**main 이 받은 경로를 검증한다**에 걸려 있다.

## 4. IPC 계약

`src/shared/ipc.ts` 에 채널 하나를 더한다. 이 파일은 FROZEN 이며 **2026-09-15 대화에서 합의했다.**

```
note:read  —  (path: NotePath) => Promise<Result<string>>
```

`PiecePoolApi` 에 `readRaw(path: NotePath): Promise<Result<string>>` 을 더한다.

**이름을 `readNote` 로 하지 않는다.** `core/vault/notes.readNote` 가 이미 있고 그것은 `Note` 를 돌려준다 —
같은 이름이 두 가지를 가리키면 CLAUDE.md 맨 앞의 그 표에 한 줄이 더 늘어난다.

`invoke`/`handle` 을 쓴다 — 창 조작 셋과 달리 **돌려줄 값이 있다.**

`core` 쪽 함수도 `notes.ts` 에 `readRaw(v, p): Promise<string>` 으로 더한다.
`notes.ts` 는 FROZEN 이고 이것은 **새 export 를 더하는 변경**이다 — 같은 합의에 포함한다.
기존 시그니처는 하나도 바꾸지 않으므로 상대 개발자의 코드가 멈추지 않는다.

## 5. 탭 모델

스토어(`src/renderer/store/workspace.ts`)에 더한다.

```
tabs: Tab[]            // { path, title, body, error }
activeTab: NotePath | null
openTab(path, title)   // 이미 있으면 activeTab 만 바꾼다
closeTab(path)         // 닫으면 이웃이 활성, 마지막이면 null
```

**탭의 키는 `NotePath` 다.** 볼트 안에서 유일하므로 별도 id 를 만들지 않는다.
구 레포는 `space:path` 조합 키를 썼는데, 우리는 볼트가 하나뿐이라 필요 없다.

**탭이 자기 원문을 쥔다.** 전환할 때 다시 읽지 않는다 — 파일 감시가 없어 다시 읽어도 최신이라는 보장이 없고,
"방금 본 것과 다른 글이 뜬다" 가 "조금 오래된 글이 뜬다" 보다 나쁘다.

기존 `selected` 는 **남긴다.** 트리에서 어느 행이 선택됐는지 표시하는 상태이고, `activeTab` 과 역할이 다르다.
둘은 같이 움직인다(트리 클릭이 둘 다 바꾼다).

## 6. 레이아웃

탭 스트립은 **본문 영역 위**에 놓는다. 사이드바 오른쪽에서 시작해 창 오른쪽 끝까지다.

```
┌───┬──────────┬──────────────────┐
│ □ │          │ 러닝 ✕ │ 번아웃 ✕ │  ← 탭 (높이 32px)
│   │──────────┼──────────────────│
│   │ ▸ inbox  │                  │
│   │ ▸ wiki   │  # 러닝          │
```

### 6.1 드래그 띠와의 충돌

탭은 상단 32px 안에 들어간다. 프레임리스 설계 §4.1 의 함정이 **탭 하나하나에** 그대로 적용된다.

- 탭과 ✕ 버튼은 `app-no-drag` **와** 띠보다 높은 `z`, **둘 다** 받아야 한다
- 안 그러면 탭이 보이는데 **안 눌린다.** 콘솔 경고도 렌더 예외도 없다
- 탭 **오른쪽 빈 공간에는 `no-drag` 를 붙이지 않는다** — 거기가 창을 끄는 자리다

창 조작 버튼(`z-20`)이 탭 스트립 오른쪽 끝과 겹친다. 탭 스트립은 그만큼 오른쪽 여백을 둔다.

## 7. 에러

| 상황                | 동작                                                                  |
| ------------------- | --------------------------------------------------------------------- |
| 볼트 밖 경로        | `resolveInVault` 가 throw → `wrap()` 이 `Result` 실패 → 탭에 메시지   |
| 파일이 사라짐       | 같다. **탭은 열린 채** 에러를 보여 준다 — 닫아 버리면 이유가 사라진다 |
| 볼트가 안 열린 상태 | `note:read` 가 실패로 떨어진다. 정상 경로에서는 일어나지 않는다       |
| 읽기 권한 없음      | 같다. 조용히 빈 글로 떨어뜨리지 않는다                                |

"실패는 화면에 보인다" 는 앞 조각들과 같은 규칙이다.

## 8. 범위 밖

편집·저장 · 인박스 쓰기 · CodeMirror · 마크다운 렌더 · `[[링크]]` 클릭 · 파일 감시 ·
탭 드래그 재정렬 · dirty 표시 · 오버플로 드롭다운 · 재시작 시 탭 복원 · 검색 · 그래프 ·
`Fm` 과 실제 노트의 필드 불일치 해소 · `assertAgentWritable`

## 9. 통과 조건

**테스트가 늘어난다.** 이 조각은 앞 둘과 달리 `environment: "node"` 로 검증할 수 있는 것이 있다.

- **`resolveInVault` 를 반드시 덮는다** — 볼트 안 정상 경로 · `../` 탈출 · 절대경로 · 심볼릭 링크 우회.
  이것이 이 조각에서 유일하게 "틀려도 화면에 표시가 없는" 부분이다
- 프론트매터 자르기 — `---` 가 없는 파일, 첫 줄이 아닌 `---`, 닫히지 않은 `---`
- 스토어의 `openTab`·`closeTab` — 중복 열기, 마지막 탭 닫기, 가운데 탭 닫을 때 이웃 활성

정적 검사 넷(`prettier --check` · `lint` · `typecheck` · `test`)이 통과해야 한다.

**사람이 확인할 것** (CLAUDE.md §7 — 화면은 사람이 본다):

- 트리에서 파일을 누르면 탭이 열리고 글이 보이나
- 같은 파일을 다시 누르면 새 탭이 생기지 않고 그 탭으로 가나
- ✕ 로 닫히나. 가운데 탭을 닫으면 이웃이 활성이 되나
- **탭이 눌리나** (§6.1 — 실패하면 화면상 아무 표시가 없다)
- 탭 오른쪽 빈 곳을 잡아 창이 끌리나
- 프론트매터가 안 보이고 `# 제목` 부터 보이나
