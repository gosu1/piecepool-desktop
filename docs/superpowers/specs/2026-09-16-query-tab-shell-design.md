# PiecePool Desktop — 쿼리 탭 껍데기 — 설계

- 날짜: 2026-09-16
- 상태: 설계 승인됨 (구현 계획 대기)
- 상위 문서: `2026-09-05-electron-rebuild-design.md` — 재구축 전체 설계. 이 문서는 그 **8단계(UI)** 에서 쿼리 세션이 앉을 자리를 미리 만드는 일이다.
- 선행: `2026-09-15-tabs-and-wiki-read-design.md` (탭 union) · `2026-09-16-graph-view-design.md` (파일이 아닌 탭의 선례)
- 관련 (이번 범위 밖): `docs/adr/0002-agentic-pipeline.md` — 쿼리가 실제로 하는 일

## 1. 무엇을 만드나

리본의 그래프 버튼 **아래**에 쿼리 버튼 하나. 누르면 `쿼리` 탭이 열리고, 그 안에 대화 화면의
뼈대가 뜬다 — 배너 하나와 비활성 입력창 하나.

**LLM 은 붙지 않는다.** 이 조각은 `src/renderer/` 밖으로 한 줄도 나가지 않는다.

### 1.1 왜 껍데기만 만드나

"사용자가 LLM 과 대화하는 탭" 을 끝까지 지으려면 **4·6·7·8단계를 세로로 관통**해야 한다.
그 길에 CLAUDE.md §2("멈추고 물어라")가 넷 걸린다.

| 무엇                                                                 | 왜 멈추나                                                    |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| `src/shared/ipc.ts`                                                  | `// FROZEN: 파일 전체`. 쿼리 채널을 더하려면 합의가 필요하다 |
| `src/main/keys.ts`                                                   | CLAUDE.md §1 이 **"스텁 유지"** 로 못 박았다                 |
| `core/llm/*` · `agent/loop.ts` · `agent/tools.ts` · `tasks/query.ts` | 전부 `unimplemented`. 소유자가 A/B 로 갈리고 4·6단계 범위다  |
| LLM 공급자                                                           | §9 는 Kimi K3, 실험은 Gemini. **ADR-0002 미결**              |

그 넷을 여는 것은 별개의 결정이다. 이 조각은 **화면 계약만 먼저 못 박는다** —
`GraphTab` 이 갔던 순서 그대로다(탭 union 에 자리 → 화면 → 나중에 IPC).

## 2. 결정 넷

| 항목        | 결정                       | 기각한 것              | 근거                                                                              |
| ----------- | -------------------------- | ---------------------- | --------------------------------------------------------------------------------- |
| 범위        | **`renderer/` 만**         | IPC·keys·core 까지     | FROZEN 둘과 "스텁 유지" 하나를 개봉하지 않는다 (§1.1)                             |
| 탭 수       | **상수 하나** `"query"`    | 세션별 `query:N`       | 담을 상태가 없어 여럿일 이유가 없다. 여러 탭이 전부 같은 배너면 잡음이다          |
| 대화 상태   | **없다**                   | `messages[]`           | 보내기가 막혀 있어 쌓일 것이 없다. 더미 답변은 동작하는 것처럼 보여 오해를 낳는다 |
| 그리는 자리 | **`NoteView` 안에서 분기** | `Shell` 에 상시 마운트 | 그래프와 달리 지킬 상태(배치·pan/zoom)가 없다 (§5)                                |

## 3. 파일 배치

```
src/renderer/features/query/
  QueryView.tsx                        배너 + 비활성 입력창          (새 파일)

src/renderer/store/workspace.ts        QueryTab · QUERY_TAB_ID · openQueryTab()
src/renderer/app/Ribbon.tsx            버튼 하나
src/renderer/app/NoteView.tsx          kind === "query" 분기
src/renderer/store/workspace.test.ts   쿼리 탭 4건
```

`features/graph/` 옆에 `features/query/` 를 둔다. 재구축 설계 §4.1 의 배치 그대로다.
`ds/` 는 이번에도 만들지 않는다 — 배너 하나와 입력창 하나를 위해 디자인 시스템 폴더를 열지 않는다.

## 4. 타입 변화 — 이것이 이 조각의 계약이다

```ts
/** 쿼리 탭은 하나뿐이라 id 가 곧 상수다. */
export const QUERY_TAB_ID = "query";

/** 쿼리 세션 탭. 그래프처럼 파일이 아니라 경로가 없다. */
export interface QueryTab {
  kind: "query";
  id: "query";
  title: "쿼리";
}

export type Tab = NoteTab | GraphTab | QueryTab;
```

`openQueryTab()` 은 `openGraphTab()` 과 같은 모양이다 — 이미 있으면 활성으로만 옮기고,
없으면 만들어 붙이고 활성으로 둔다.

### 4.1 컴파일러가 빠뜨린 자리를 알려 준다

`NoteView.noteBody()` 는 지금 `tab.kind === "graph"` 만 걸러낸 뒤 나머지를 노트로 보고
`tab.error` 를 읽는다. union 에 `QueryTab` 이 들어오는 순간 그 자리가 `tsc` 에서 에러가 된다.
**빠뜨릴 수 없는 구조다.**

`focusTab` 의 `t.kind === "note" ? … : …` 는 고치지 않아도 맞다 — 쿼리 탭은 경로가 없으므로
`selected` 를 건드리지 않는 쪽으로 떨어진다. `closeTab` 도 id 만 보므로 그대로다.

### 4.2 세대 카운터(`seq`)가 필요 없다

`NoteTab.seq` 는 "닫았다 곧바로 다시 연 탭에 옛 응답이 덮어쓰는 것" 을 막는다.
쿼리 탭은 **비동기 응답을 담지 않으므로** 덮어쓸 것이 없다. 다음 조각에서 대화가 들어올 때
다시 판단한다.

## 5. 왜 그래프처럼 상시 마운트하지 않나

`NoteView` 는 그래프 탭을 `graphOpen && <GraphView hidden={…} />` 로 **계속 마운트해 둔다.**
언마운트하면 d3-force 배치와 pan/zoom 을 잃기 때문이다(그 버그를 고친 것이 커밋 `1216511` 이다).

`QueryView` 는 잃을 상태가 없다. 배너와 비활성 입력창뿐이라 매번 새로 그려도 같다.
그래서 분기해서 렌더한다 — **없는 문제를 위한 장치를 미리 두지 않는다.**

다음 조각에서 대화가 생기면 이 판단을 다시 한다. 다만 그때도 스크롤 위치 정도라
`hidden` 이 아니라 상태를 스토어로 올리는 쪽이 먼저다.

## 6. 화면

```
┌ 쿼리 ─────────────────────────────────┐
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ ⚠  LLM 이 아직 연결되지 않았다.    │  │
│  │    대화는 다음 조각에서 붙는다.     │  │
│  └──────────────────────────────────┘  │
│                                        │
│             (본문 영역은 빈 채)          │
│                                        │
│  ┌──────────────────────────┬──────┐   │
│  │ 물어보기…        (비활성)  │  ↑   │   │
│  └──────────────────────────┴──────┘   │
└────────────────────────────────────────┘
```

- **배너** — 위쪽에 고정. `border-hairline` · `text-ink-muted`
- **입력창** — `disabled` 로 두되 **자리를 실제로 차지한다.** 다음 조각에서 `disabled` 를 떼면
  그대로 살아난다. 글자색은 `text-ink-faint`
- **보내기 버튼** — `disabled`, 같은 이유

비활성 전용 토큰은 만들지 않는다. `--ds-ink-faint` 가 탭 닫기 버튼에서 이미 쓰는 가장 흐린
글자색이고, `tokens.css` 는 구 레포에서 발췌한 시각 언어라 토큰 추가는 이 조각의 일이 아니다.

### 6.1 리본 아이콘

말풍선 하나(16×16, `stroke-width` 1.3). 그래프의 점-선 아이콘과 헷갈리지 않고,
나중에 세션이 여럿이 돼도 뜻이 바뀌지 않는다.

`RibbonButton` 은 이미 있다 — `label` · `active` · `onClick` 만 넘기면 된다.
`active` 는 `activeTab === QUERY_TAB_ID` 다.

## 7. 볼트가 없을 때

그래프 버튼과 **같게** 둔다 — 볼트 없이도 눌리고 탭이 열린다.
`openGraphTab()` 도 볼트를 검사하지 않고, 실패 표시는 `GraphView` 가 한다.
쿼리는 지금 표시할 실패조차 없으므로 배너만 뜬다.

볼트를 바꾸면 `applied()` 가 `tabs: []` 로 비우므로 쿼리 탭도 함께 닫힌다.
담고 있던 대화가 없으니 잃는 것이 없다. 이것도 다음 조각에서 다시 판단할 자리다.

## 8. 통과 조건

```bash
npm ci && npx prettier --check . && npm run lint && npm run typecheck && npm test
```

### 8.1 기계가 볼 것

`workspace.test.ts` 에 `describe("쿼리 탭")` 4건. 기존 `describe("그래프 탭")` 과 같은 모양이다.

1. 연 적 없으면 새로 만들고 활성으로 둔다
2. 두 번 눌러도 탭이 둘이 되지 않는다
3. 노트 탭·그래프 탭과 키 공간이 겹치지 않는다
4. 볼트를 바꾸면 쿼리 탭도 함께 닫힌다 (`applied()`)

`vitest.config.ts` 의 `include` 가 **`.test.ts` 만** 잡으므로 `QueryView` 자체는 테스트하지
않는다. `include` 를 넓히지 않는다 — 그 줄의 주석이 이유를 적어 뒀다.

`eslint.config.js` 의 `no-restricted-paths` 가 `renderer/` → `core/`·`main/` import 를 막으므로,
이 조각이 `renderer/` 안에서만 끝난다는 것은 **lint 가 물리적으로 보증한다.**

### 8.2 사람이 볼 것

CLAUDE.md §7 — 화면은 사람이 본다.

- 리본에서 그래프 **아래**에 말풍선 버튼이 보이나
- 누르면 `쿼리` 탭이 열리고 활성이 되나. 다시 눌러도 탭이 하나인가
- 배너가 읽히고, 입력창을 클릭해도 글자가 써지지 않나
- 그래프 탭과 오가도 **둘 다 멀쩡한가** (그래프의 pan/zoom 이 유지되나)
- 볼트를 바꾸면 쿼리 탭이 함께 사라지나

## 9. 이번에 하지 않는 것

**연결** — `shared/ipc.ts` 채널 · `main/keys.ts`(safeStorage) · `core/llm/gemini.ts` ·
`core/llm/stream.ts` · `agent/loop.ts` · `agent/tools.ts` · `tasks/query.ts ask()` ·
`prompts/query.md` · LLM 공급자 결정(ADR-0002).

**화면** — 세션별 탭(`query:N`) · `messages[]` · 스트리밍 · 답변 마크다운 렌더 ·
세션 로그(`.piecepool/sessions/`) · 수확(`[위키에 반영]`).

**탭 분할** — 탭을 끌어 오른쪽 칸에 띄우는 기능은 **별개 조각이다.** 쿼리 전용이 아니라
노트·그래프 탭에도 걸리는 크롬 기능이고, `tabs` + `activeTab` 모델 자체를 바꾼다.
그리고 §5 가 적은 그래프의 상시 마운트가 칸을 옮길 때 깨지므로, 그 문제를 그 설계에서 풀어야 한다.
