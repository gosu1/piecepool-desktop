## 1. 배경과 결정

현재 PiecePool은 Tauri + Rust(4,811줄) 백엔드에 React 프론트엔드를 얹은 구조다.
지식 모델은 **타입이 붙은 관계 그래프** — `RelationType` 12종 + 노드 호환성 매트릭스,
`relations.json` 저장소, LLM 출력을 `LlmWikiResult`로 받아 스키마 검증 후 반영하는 파이프라인.

이번 재구축은 셸과 지식 모델을 **동시에** 바꾼다.

| 축 | 기존 | 신규 |
|---|---|---|
| 셸 | Tauri + Rust | Electron + Node/TS |
| 지식 모델 | 타입 관계 그래프 (`RelationType` 12종) | 타입 없는 `[[]]` 링크 (카파시 LLM Wiki) |
| LLM 쓰기 | JSON 제안 → 스키마 검증 → 앱이 반영 | **에이전트가 파일을 직접 편집** |
| 진실의 소재 | `relations.json` + 마크다운 | **마크다운 파일만** |
| 안전망 | 저장 전 검증 게이트 | **볼트 git 커밋 + 되돌리기** |

참고한 패턴: 카파시의 LLM Wiki — "Obsidian이 IDE, LLM이 프로그래머, 위키가 코드베이스".
자료를 색인만 하는 게 아니라 에이전트가 읽고 기존 페이지를 갱신·교차링크·중복제거한다.

### 1.1 v1 범위

v1의 목적은 **LLM이 위키를 만들고 · 위키를 근거로 답하고 · 위키가 계속 관리되는 흐름**이다.
UI는 그 흐름을 확인한 뒤에 붙인다(11절).

핵심(먼저): **인제스트(PDF · 마크다운)** · 에이전트 위키 유지보수 ·
위키를 참조하는 쿼리 세션.

껍데기(나중): Electron 셸 · 위키 열람/편집 UI · 옵시디언식 그래프 시각화.

제외:

- 학습 기능 전부 — 파인만 · 정보 간극 메우기 · 우선순위 스코어링
- **URL 인제스트** — 웹페이지를 받아 위키로 넣는 경로
- **OCR 전체** — 이미지 · 스캔본 · 손글씨. 텍스트가 0자면 `parse_failed`로 실패한다(7.1)
- **GitHub 원격 동기화** — 볼트를 git 저장소로 두므로(4.3) 원격만 붙이면
  기기 간 동기화·백업이 가능해지지만, **앱이 그 기능을 제공하지는 않는다.**
  인증(토큰·SSH)·원격 설정 UI·`pull` 충돌 해결이 전부 딸려오고 안전망과 공유하는 코드가 없다.
  다만 볼트는 사용자 폴더의 진짜 git 저장소이므로, 원하는 사용자가
  터미널이나 GitHub Desktop으로 직접 원격을 붙이는 것을 앱이 막지 않는다

#### `ingest`와 `processInbox`의 경계

둘 다 "자료를 위키로 편입"이라 보이므로 기준을 명시한다. **출처가 볼트 밖이냐 안이냐다.**

| | `ingest` | `processInbox` |
|---|---|---|
| 입력 | 볼트 **밖** 파일 (PDF·`.md`) | 볼트 **안** `inbox/`의 단편 메모 |
| 원본 보관 | `sources/`에 남긴다 | 없음 — 사용자가 직접 쓴 글이다 |
| 트리거 | 사용자가 파일을 넣을 때 | 사용자가 정리를 요청할 때 |

즉 외부 `.md`를 들여오는 것은 `ingest`다 — `sources/`에 원본이 남는다.
사용자가 앱 안에서 끄적인 메모는 `inbox/`로 가고 `processInbox`가 다룬다.
같은 일을 하는 두 경로를 만들지 않는다.

### 1.2 승계하지 않는 것

새 저장소를 파므로(12절) 이들은 "지우는 작업"이 아니라 **"가져오지 않는 목록"**이다.
기존 레포에 그대로 남아 있으므로 언제든 되짚을 수 있다.

| 가져오지 않는 것 | 이유 |
|---|---|
| `relation-types.md` (12 enum + 호환성 매트릭스) | 타입 없는 `[[]]` 링크로 통일 |
| `relations.json` | 링크는 본문에서 파생 |
| `llm-output-schema.md` (`LlmWikiResult`) | 에이전트가 파일을 직접 편집 |
| ImportJob 8단계 상태머신 (`ADR-0007`) | 인제스트가 단순해짐 |
| `entities.md` 11개 엔티티 | `Note` · `LinkRef` · `GraphData`로 축소 |
| Rust `graph/` `priority/` `notes/` `seed/` | 학습 기능 제외 + 그래프는 파생물 |
| Liner API (`LINER_API_KEY`) | 정보 간극 메우기·fact-check가 학습 기능과 함께 제외 |
| `ADR-0005` · `ADR-0010` (PDF 2단계 추출) | 7.1이 단일 추출기로 대체 |

**내용은 승계하되 새로 쓰는 것** — 옛 파일을 복사하지 않고 새 이름으로 다시 쓴다(2.3):
`vault-layout.md`(← `workspace-layout.md`) · `frontmatter.md`(4필드로 축소) ·
`wikilink.md`(옵시디언 규칙으로).

**결정만 승계하는 것** — 원문은 12.3으로 옮겨 참고 자료로 두되, 새 ADR 번호를 받지 않는다:
`ADR-0004`(CodeMirror 6 에디터) · `ADR-0006`(Cytoscape 그래프) · `ADR-0009`(Gemini 단일 공급자).

보류: `ADR-0003`(OCR) — 결정은 유효하나 **v1 범위 밖**이다(7.1 참조).
스캔본뿐 아니라 **이미지·손글씨 인식 전체**가 여기 포함된다.

계승하는 교훈은 1.3에, 저장소 운영은 12절에 적는다.

## 2. 레포 구조

### 2.1 선택 근거

세 가지를 검토했다.

- **A. npm workspaces 모노레포** (`packages/{main,preload,renderer,shared}`) —
  프로세스 경계가 패키지 경계라 물리적으로 격리되지만, package.json 4개와 빌드 배선 비용이 든다.
  모노레포의 진짜 이득(독립 배포·버전)은 단일 데스크톱 앱에 없다. 비채택.
- **B. 단일 패키지 + `src/{core,cli,main,preload,shared,renderer}` (electron-vite)** — 채택.
  electron-vite가 이 폴더 구조를 규약으로 삼아 3개 빌드 타깃을 처리한다. 설정 하나, package.json 하나.
  경계는 ESLint `no-restricted-imports`로 강제한다.
- **C. 단일 패키지 + Vite 수동 설정** — main/preload 번들링·HMR·네이티브 모듈 externalize를
  직접 관리해야 한다. 아낀 의존성보다 잃는 시간이 크다. 비채택.

### 2.3 `core/`는 호출자를 모른다

11.2의 규칙을 폴더 경계로 강제한다.

```
cli/  ──┐
        ├──▶  core/     (역방향 import 금지)
main/ ──┘
```

- `core/`는 `cli/` · `main/` · `renderer/` · `electron`을 import하지 않는다
- 진행 상황은 `onProgress` 콜백으로 나간다. `console.log`·`process.exit`·`process.argv` 금지
- ESLint `no-restricted-imports`로 검사한다 — 관습이 아니라 규칙이다

이 경계가 지켜지면 7단계의 Electron 래핑은 **호출자를 하나 더 붙이는 일**로 끝난다.
`cli/ingest.ts`가 `console.log`를 넘기던 자리에 `main/ipc.ts`가 `webContents.send`를 넘긴다.

### 2.4 런타임 로드 자산은 두 곳뿐이다

`core/prompts/*.md`와 pdf.js의 `cmaps/*.bcmap`은 **코드가 아니라 실행 중에 읽는 파일**이다.
번들러가 자동으로 챙기지 않으므로 `electron-builder.yml`에 명시해야 하고,
asar로 묶이면 경로가 `app.asar/…`로 바뀐다(10절의 스모크 테스트가 겨누는 지점).

CLI로 도는 0~6단계에서는 문제가 드러나지 않는다 — 소스 트리에서 그냥 읽히기 때문이다.
**7단계에서 처음 깨진다.** 두 자산을 한 규칙으로 다루고 함께 검사한다.

### 2.5 계약 문서는 처음부터 제대로 명명한다

새 저장소이므로(12절) 기존 레포의 명명을 물려받을 이유가 없다.

- `docs/contracts/` — 번호 접두사(`10-contracts`)를 붙이지 않는다.
  접두사는 문서가 수십 개일 때 정렬을 위한 장치인데, v1 계약은 4개다
- `vault-layout.md` · `frontmatter.md` · `wikilink.md` · `ipc.md` —
  옛 이름(`workspace-layout` · `markdown-frontmatter` · `wikilink-embed`)을 쓰지 않는다.
  "workspace"는 폐기된 개념이고 지금 서술 대상은 볼트다

기존 레포에서는 `ssot-check.mjs`의 경로 하드코딩과 lychee가 검사하는 링크 184곳 때문에
이 개명이 CI를 깼다. 그 제약은 새 레포에 존재하지 않는다 — 자세한 것은 12.1에 적는다.

`00-overview`…`70-roadmap` 같은 번호 디렉터리 체계도 승계하지 않는다.
문서가 그만큼 쌓이면 그때 나눈다.

### 2.6 `shared/`의 규율

core·main(Node)과 renderer(브라우저)가 함께 import하는 유일한 폴더다.
`fs`나 `window`를 건드리는 코드가 한 줄이라도 들어가면 반대편 빌드가 깨진다.
**타입과 순수 상수만 둔다.** ESLint로 강제한다.

## 3. 프로세스 아키텍처

```
┌─ renderer (React) ──────┐   UI·상태만. fs·API키·직접 네트워크 없음
│  editor·graph·query     │
└──────────┬──────────────┘
        preload  ← contextBridge 화이트리스트 (공격 표면 전체)
┌──────────┴──────────────┐
│  main (Node)            │   볼트 I/O·인덱스·인제스트·에이전트·LLM·git
└─────────────────────────┘
```

에이전트 루프를 main에 두는 이유:

1. 파일 툴이 `fs`를 필요로 한다
2. Gemini API 키가 renderer로 내려가면 안 된다
3. main에는 CORS가 없다
4. renderer가 HMR로 재시작돼도 진행 중인 인제스트가 살아남는다

Tauri와의 결정적 차이: renderer는 `contextIsolation`으로 Node 접근이 차단돼 있고
**preload가 화이트리스트로 열어준 것만** 쓸 수 있다. `preload/index.ts`가 앱의 공격 표면 전체이므로
여기서 `fs`를 통째로 노출하면 격리가 무의미해진다. 경로 검증은 반드시 `core/vault/paths.ts`에 둔다.

### 3.1 API 키를 main으로 옮긴다

현행 앱은 Gemini 키를 `localStorage["gemini-key"]`에 둔다 — 즉 **renderer에 있다.**
위 원칙과 정면으로 어긋나므로 이전이 필요하다.

- **저장소**: Electron `safeStorage`로 암호화해 `app.getPath('userData')`에 둔다.
  OS 키체인(Windows DPAPI / macOS Keychain)을 쓰므로 평문으로 남지 않는다.
- **접근**: renderer는 키 값을 절대 받지 않는다. "키가 설정됨/안 됨" 불리언과
  설정용 쓰기 채널만 preload가 노출한다. LLM 호출은 전부 `core/`에서 일어난다.
- **기존 사용자 이전**: 첫 실행 시 `localStorage["gemini-key"]`가 있으면 main으로 옮기고
  renderer 쪽 값을 지운다. 1회성 마이그레이션이며 실패해도 설정 모달에서 다시 입력하면 된다.

CLI 스크립트(`.env`의 `GEMINI_API_KEY`)는 앱과 별개 경로이며 그대로 둔다.

## 4. 볼트 — 유일한 진실

### 4.1 위치

**사용자가 폴더를 고른다 (옵시디언 방식).** 앱이 기억하는 상태는 최근 볼트 경로 목록뿐이고
`app.getPath('userData')`에 둔다. 코드 레포와 볼트는 완전히 별개의 두 디렉터리,
별개의 두 git 저장소다.

이 규율이 지켜지면 개발용 볼트와 사용자 볼트를 코드가 구분할 필요가 없다.

#### 기존 옵시디언 볼트를 열면 어디까지 되나

"연다"의 범위를 명확히 한다. 임의의 옵시디언 볼트에는 4.2의 `wiki/`·`inbox/`·`sources/`가 없다.

- **열람·편집·링크·그래프는 볼트 전체에 대해 동작한다.** 이들은 폴더 구조를 가정하지 않고
  `.md` 파일과 `[[]]` 링크만 본다. 즉 기존 옵시디언 볼트가 그대로 보이고 편집된다.
- **에이전트의 쓰기 대상은 `wiki/`·`inbox/`로 한정한다.** 폴더가 없으면 첫 작업 때 만든다.
  기존 노트를 임의로 재배치하지 않는다 — 남의 볼트 구조를 앱이 무단으로 바꾸면 안 된다.
- **기존 노트를 에이전트 사정권에 넣고 싶으면** 사용자가 `wiki/`로 옮기거나,
  설정에서 "에이전트 쓰기 루트"를 볼트 루트로 바꾼다. 기본값은 `wiki/`다.

읽기(`read_note`·`search`·`backlinks`)는 처음부터 볼트 전체를 본다.
즉 **에이전트는 볼트 전체를 근거로 삼되 정해진 곳에만 쓴다.**

### 4.2 레이아웃

```
<사용자가 고른 폴더>/
├─ .git/                 ← isomorphic-git이 관리. 앱에 동봉, 계정 불필요
├─ wiki/                 ← 위키 페이지 .md
├─ inbox/                ← 미정리 단편 메모
├─ sources/
│  ├─ files/             ← 원본 파일 (에이전트 쓰기 금지)
│  └─ text/              ← 추출 텍스트
└─ .piecepool/
   ├─ index.json         ← 파생 캐시. 지우면 재빌드. **커밋하지 않는다**
   └─ sessions/          ← 쿼리 세션 로그. **커밋한다**
```

#### `sources/files/`에 들어가는 것

**보관 대상과 추출 대상이 다르다.**

- **PDF·마크다운** — 보관하고 텍스트를 추출해 위키로 편입한다 (v1 인제스트 대상)
- **이미지** — 보관하고 `![[]]`로 임베드해 볼 수는 있으나 **텍스트 추출 대상이 아니다.**
  OCR이 v1 밖이므로 이미지를 넣어도 위키에 내용이 들어가지 않는다

즉 이미지는 볼트에 존재하고 노트에서 참조되지만, 인제스트 파이프라인을 타지 않는다.

#### `.piecepool/`의 git 취급

두 하위 경로의 운명이 반대다.

- **`sessions/`는 커밋한다.** 8.2의 프론트매터 `sources:`와 각주가 이 파일을 가리킨다.
  커밋되지 않으면 되돌리기·이력에서 각주 대상이 사라져 8.3의 출처 검증이 헛돈다.
  세션 로그는 툴이 아니라 main이 직접 쓰므로, 수확 커밋에 그 경로를 **명시적으로 포함**한다.
- **`index.json`은 커밋하지 않는다.** 파생 캐시이고 매 스캔마다 바뀌어 이력을 오염시킨다.

볼트를 처음 열 때 `.piecepool/.gitignore`에 `index.json`을 쓴다.
볼트 루트의 `.gitignore`는 건드리지 않는다 — 사용자 소유 파일이다.

두 가지를 빠뜨리면 무력해진다.

- **`.gitignore` 자체를 첫 커밋에 포함한다.** 이 파일은 에이전트 툴이 아니라 main이 쓰므로
  4.3의 "쓴 경로 집합"에 자동으로 들어오지 않는다. `sessions/`와 같이 명시적으로 추가한다.
- **이미 추적 중인 `index.json`은 `.gitignore`가 걸러내지 못한다.** git은 tracked 파일에
  ignore 규칙을 적용하지 않는다. 이전 버전이나 다른 기기가 커밋해 둔 볼트를 열 수 있으므로,
  볼트를 열 때 추적 여부를 확인하고 추적 중이면 인덱스에서만 제거한다(`git rm --cached` 상당).
  파일 자체는 지우지 않는다.

### 4.3 안전망 — 볼트 자체 git

[isomorphic-git](https://isomorphic-git.org/)을 쓴다. 네이티브 바이너리 의존성이 없는
순수 JavaScript 구현체로 진짜 `.git` 디렉터리를 읽고 쓴다.
npm 의존성 하나로 앱에 동봉되므로 **사용자 PC에 git이 설치돼 있지 않아도 된다.**

`git init` / `add` / `commit`은 네트워크를 쓰지 않는다. 계정·로그인·인터넷 연결이 필요 없다.
계정이 필요한 것은 `push`뿐이고 v1은 하지 않는다.

#### 워킹트리 소유권 — 커밋 대상은 "에이전트가 쓴 경로"뿐

볼트 저장소는 **앱 전용이 아니다.** 사용자가 옵시디언으로 같은 폴더를 편집하고,
Obsidian Git 같은 플러그인을 쓸 수도 있다. 따라서 "변경된 `.md` 전부 `add`"는 쓸 수 없다 —
사용자의 미커밋 편집이 에이전트 커밋에 딸려 들어가고,
그 커밋을 [되돌리기]로 revert하면 **사용자 작업이 함께 날아가** 안전망이 정확히 반대로 작동한다.

그래서 `agent/written.ts`가 이번 작업에서 `write_note`/`delete_note`가 실제로 건드린
**경로 집합**을 모으고, 커밋은 그 경로만 `add`한다. 경로 집합은 커밋 단위의 1급 개념이다.

작업 시작 시 워킹트리에 사용자의 미커밋 변경이 이미 있으면
`chore(vault): 사용자 편집 봉인` 커밋으로 먼저 분리한다.
에이전트 커밋과 사용자 편집이 한 커밋에 섞이지 않게 하는 전제다.

| 단계 | 동작 | 사용자가 보는 것 |
|---|---|---|
| 볼트 최초 열기 | `.git` 없으면 `git init` | 없음 |
| 작업 시작 | 사용자 미커밋 변경이 있으면 봉인 커밋 | 없음 |
| 에이전트 작업 1회 | **쓴 경로만** add + commit 1개 | "자료 3건 반영됨" |
| 결과 불만족 | 해당 커밋의 경로만 이전 상태로 복원 | **[되돌리기]** 버튼 |
| 에이전트 커밋 작성자 | `PiecePool Agent <agent@piecepool.local>` 고정 | — |
| **봉인** 커밋 작성자 | 볼트의 `git config` 값을 따른다 | — |

봉인 커밋 작성자를 나누는 이유: 그 커밋의 내용은 사용자가 옵시디언으로 쓴 것이다.
에이전트 명의로 남기면 사용자 자신의 볼트 이력에서 자기 작업이 남의 것으로 보인다.

**볼트에 git 신원이 없으면 봉인할 수 없다.** isomorphic-git의 `commit()`은
`author.name`이 필수이고, 인자에도 `.git/config`에도 없으면 커밋을 만들지 않는다.
"작성자를 비운 커밋"은 만들 수 없다. 앱이 임의 신원을 지어내 사용자 작업에 서명하는 것도
4.3이 피하려는 월권과 같은 종류다. 따라서:

- 미커밋 변경이 **없으면** 봉인이 불필요하므로 그대로 진행한다
- 미커밋 변경이 **있는데** 신원이 없으면 작업을 시작하지 않고 사용자에게 신원 설정을 요청한다 —
  *"볼트에 git 신원이 없어 기존 변경을 분리할 수 없습니다. 이름을 설정해 주세요."*
  기본값을 제안하되 사용자가 확정해야 진행한다

안전망 문서이므로 "일단 진행하고 나중에 수습"이 아니라 "분리할 수 없으면 시작하지 않는다"를 택한다.

이미 `.git`이 있는 옵시디언 볼트를 열면 그것을 그대로 쓴다.

#### 되돌리기의 실패 모드

에이전트 커밋 이후 사용자가 같은 파일을 고쳤다면 단순 `revert`는 충돌한다.
자동 병합을 시도하지 않는다 — 대신 **경로별 복원**으로 처리한다.

1. 커밋에 담긴 경로 각각에 대해, 그 커밋 이후 변경 여부를 확인한다
2. 변경이 없는 파일은 조용히 이전 내용으로 복원한다
3. 변경이 있는 파일은 목록으로 보여주고 사용자가 파일 단위로 고른다 —
   *"이 파일은 그 뒤 직접 수정하셨습니다. 되돌리면 그 수정도 사라집니다."*
4. 사용자가 아무것도 안 고르면 그 파일은 건드리지 않는다

부분 복원이 끝나면 그 자체가 새 커밋이 된다. 이력을 다시 쓰지 않으므로
사용자의 다른 git 도구와 충돌하지 않는다.

성능: isomorphic-git이 네이티브 git보다 느리지만 그것은 수십만 파일 저장소 얘기다.
개인 위키(수천 개 마크다운)에서는 체감 차이가 없다.

### 5.1 검증은 게이트가 아니라 관찰

기존 계약은 "저장 전 6가지를 검증하고 실패하면 거부"였다.
카파시 방식에서는 **파일이 진실이므로 저장을 막을 근거가 없다** —
사용자가 옵시디언으로 직접 고친 파일도 똑같이 유효해야 한다.

따라서 검증은 `lint()`가 나중에 보고하는 관찰로 내려간다.
깨진 링크는 에러가 아니라 할 일 목록의 한 줄이다.

## 6. 링크 — 옵시디언 규칙 그대로

### 6.1 문법

- `[[제목]]` — 볼트 안에서 제목 또는 파일명 매칭
- `[[제목|표시 텍스트]]`
- `![[sources/files/x.pdf]]` — 임베드
- `![[sources/files/x.pdf#page=N]]` — PDF 특정 페이지. **N은 1-indexed 정수** (기존 계약 계승)
- 타입 없음

해석 실패는 "깨진 링크"로 표시하고, 클릭하면 새 문서 생성을 제안한다(옵시디언과 동일).
그래프는 이 링크에서 **파생**되며 저장하지 않는다.

`#page=N`을 계승하는 이유: 에이전트가 위키 문장에 PDF 근거를 달 때 페이지 단위 인용이 필요하다.
N이 총 페이지 수를 넘으면 첫 페이지를 렌더링하고 경고를 표시한다 — 죽지 않는다(기존 규칙 유지).

관계의 의미론은 스키마가 아니라 산문이 담는다 —
`[[열역학 제2법칙]]은 이 논증의 전제다`처럼 링크 주변 텍스트가 관계를 설명한다.

### 6.2 인덱스와 파일 감시

`index/`는 볼트를 스캔해 링크·백링크·제목 맵을 만들고 `.piecepool/index.json`에 캐시한다.
`watch.ts`가 파일 변경을 감시해 증분 갱신한다 — 사용자가 옵시디언에서 고쳐도 반영된다.

**자기 쓰기 루프를 막아야 한다.** 에이전트의 `write_note`도 외부 편집과 똑같은 fs 이벤트를 낸다.
인제스트 1회에 수십 파일을 쓰면 그만큼 인덱스 재빌드가 연쇄한다.

- 에이전트가 쓴 경로는 `written.ts`가 이미 알고 있으므로 **감시 이벤트에서 억제**한다
- 억제는 경로+내용 해시로 대조한다. 시간 기반 억제창은 느린 디스크에서 새는 만큼,
  해시가 일치할 때만 무시하고 다르면 외부 편집으로 취급한다
- 외부 편집은 300ms debounce 후 **변경된 파일만** 증분 갱신한다
- 에이전트 작업이 끝나면 그때 한 번 인덱스를 갱신한다 — 파일마다가 아니다

캐시가 깨지면 지우고 재빌드한다. 파생물이므로 복구 절차가 따로 없다.

### 6.3 rename — 링크를 따라 고친다

`NotePath`가 신원이므로 파일명이 바뀌면 그 파일을 가리키던 `[[링크]]`가 전부 끊긴다.
ULID `id`를 버린 대가다.

**옵시디언과 동일하게 처리한다** — 파일명이 바뀌면 그 문서를 가리키는 모든 링크를 자동으로 갱신한다.
앱 안에서 일어난 rename은 앱이 갱신하고, 갱신은 하나의 커밋이 된다(4.3의 경로 집합에 포함).

앱 밖(옵시디언·탐색기)에서 일어난 rename은 감지할 수 없다.
이 경우 끊긴 링크는 `lint()`가 "깨진 링크"로 보고하고, 사용자가 고르면 일괄 수정한다.

기존 `src/lib/retitleSync.ts`가 같은 문제를 다뤘으므로 로직을 발췌해 재사용한다.

## 7. 인제스트와 에이전트

### 7.1 PDF 텍스트 추출 — pdf.js 단일 경로

v1 통과 조건이 "PDF 1개 인제스트"이므로 추출기를 여기서 확정한다.
이 프로젝트는 이 문제에 이미 두 번 값을 치렀다.

`ADR-0005`는 Rust `pdf-extract` 단독으로 정했고, `ADR-0010`이 실측으로 뒤집었다 —
`pdf-extract` 0.10.0은 CID 폰트의 predefined CMap 중 `Identity-H`/`Identity-V` 외를
지원하지 않고 `Err`가 아니라 **`panic!`으로 죽는다**. 한국 학술지가 흔히 쓰는
`UniKS-UTF16-H`가 여기 걸린다. 사용자 PDF 14개 중 2개(둘 다 한글 논문)가 실패했고,
같은 2개를 pdf.js `getTextContent()`는 원문과 일치하게 추출했다(실측 5,765자).
그래서 현행은 Rust 1차 + pdf.js 2차 폴백이라는 이중 경로다.

**Rust를 버리면 그 이중 경로의 존재 이유가 사라진다.** 2단계는 pdf.js가 부족해서가 아니라
1차가 부족해서 생겼고, 측정 표본에서 pdf.js는 100%를 처리했다.

결정: **`pdfjs-dist`의 legacy 빌드를 `core/`(순수 Node)에서 단독 추출기로 쓴다.**

- legacy 빌드(`pdfjs-dist/legacy/build/pdf.mjs`)를 쓰는 이유 — 기본 빌드는 브라우저 전용
  API를 전제하므로 Node에서 그대로 돌지 않는다. legacy는 Node 실행을 지원한다.
- CMap 자산을 함께 번들하고 `cMapUrl`/`cMapPacked`를 지정한다.
  `ADR-0010`이 해결한 한글 CID PDF가 여기에 달려 있다 — **빠뜨리면 그 14%가 그대로 돌아온다.**
- page 1-indexing과 빈 페이지 `""` 보존은 기존 규약을 그대로 유지한다(`#page=N`이 여기 의존).
- 텍스트가 0자면 스캔본·손글씨로 보고 **`parse_failed`로 사용자에게 알린다.**
  OCR(`ADR-0003`)은 v1 범위 밖이며 후속으로 남긴다 — 1.1의 v1 목록에 OCR이 없고,
  구축 순서(11절)에도 자리가 없다. 방침만 계승하고 구현은 미룬다.
  이미지 파일도 같다 — 보관·임베드는 되지만 추출하지 않는다(4.2).

얻는 것: `catch_unwind` panic 방어, 이중 경로, 원본 bytes를 renderer로 base64 전송하는
`ADR-0010`의 단점이 전부 사라진다. 추출이 `core/ingest/pdf.ts` 한 곳에서 끝난다.

비용 각주: renderer의 미리보기(`react-pdf`)와 main의 추출이 pdf.js를 **각각 번들**한다.
`ADR-0010`이 pdf.js를 고른 근거 하나가 "이미 번들돼 있다"였는데, 프로세스가 갈리며
그 이점이 절반만 남는다. 앱 용량이 늘지만 추출 정확도와 맞바꿀 만하다.

대안으로 `pdfium-render` 계열 네이티브 바인딩도 있으나,
`ADR-0010`이 이미 "네이티브 바이너리 번들로 빌드·패키징 복잡도 증가"를 이유로 기각했다.
Electron에서도 같은 비용이 들고, pdf.js로 충분하다는 측정이 있으므로 재검토하지 않는다.

### 7.2 툴 6종

`list_notes(glob?)` · `read_note(path)` · `write_note(path, content)` ·
`search(query)` · `backlinks(path)` · `delete_note(path)`

`write_note` / `delete_note`는 `vault/paths.ts`를 통과해야 하고 `.md`만 허용한다.
`sources/files/`는 쓰기 금지다.

### 7.3 작업 3종 + 세션 1종

| 작업 | 하는 일 | 커밋 |
|---|---|---|
| `ingest` | 새 자료를 읽고 기존 페이지 갱신·생성·교차링크 | 1개 |
| `processInbox` | `inbox/` 단편을 위키로 편입 | 1개 |
| `lint` | 깨진 링크·고아·중복·모순·미검증 문단 보고 | 수정 시 1개 |
| `query` | 위키를 근거로 답변 — **읽기 전용 툴만 부여** | 없음 |

`query`가 위키를 못 고치는 것은 대화 *중*의 얘기다. 대화 내용은 8절의 수확 단계에서
`ingest`를 거쳐 들어간다 — 즉 쓰기 경로는 언제나 `ingest` 하나뿐이다.

## 8. 쿼리 세션이 위키를 키운다

### 8.1 시점 — 세션 끝에 수확

대화 중에는 읽기 전용이다. 사용자가 **[위키에 반영]**을 누르면 그 시점까지의 대화 로그를
*하나의 자료*로 보고 `ingest`를 돌린다.
기존 인제스트 파이프라인을 그대로 재사용하고 커밋도 1개로 깔끔하다.

**수확은 사용자가 누를 때만 일어난다.** 창을 닫거나 세션이 유휴 상태가 됐다고 자동으로
반영하지 않는다 — 반영 여부는 대화의 가치를 본 사람만 판단할 수 있고,
자동 반영은 8.2의 오염 위험을 사용자 모르게 키운다.
반영하지 않은 세션 로그는 `.piecepool/sessions/`에 남아 나중에 수확할 수 있다.

**전용 프롬프트를 두지 않는다.** 수확은 `ingest` 프롬프트를 그대로 쓰고,
입력이 PDF 텍스트 대신 대화 로그일 뿐이다. 출처가 세션 파일이라는 사실만
호출부가 인자로 넘겨 8.2의 각주를 달게 한다. 프롬프트는 4종(`ingest`·`inbox`·`lint`·`query`)이다.

실시간 반영을 택하지 않은 이유: 답변이 느려지고, 사용자가 "아니 그거 말고"라고 해도
이미 쓴 것이 남아 되돌리기가 잦아진다.

### 8.2 출처 표시 — 대화 출신 내용의 오염 차단

대화에는 세 종류가 섞인다. ① 사용자가 알려준 새 사실, ② 기존 페이지들의 새로운 종합,
③ **LLM이 자기 사전지식으로 채운 것**. ①②는 자산이지만 ③은 오염이다.
볼트에 들어가는 순간 출처가 지워지고, 다음 인제스트 때
"이미 위키에 있는 사실"로 취급돼 스스로를 강화하기 때문이다.

따라서 대화 출신 내용에는 두 층의 꼬리표를 붙인다.

- **페이지 층** — 프론트매터 `sources:` 에 `.piecepool/sessions/<id>.md` 를 추가
- **문단 층** — 마크다운 각주 `[^conv-<sessionId>]` 를 붙이고
  문서 하단에 `[^conv-<sessionId>]: 출처: 대화 세션 2026-09-05` 를 둔다

각주를 쓰는 이유: 옵시디언이 네이티브로 렌더링하고, 평문이라 사람이 읽을 수 있고,
lint가 grep으로 찾을 수 있다.

### 8.3 lint의 출처 검증

`lint()`에 규칙 하나를 추가한다 — **출처가 대화뿐인 문단**을 검증 대상 목록으로 보고한다.
사용자는 그 목록을 보고 실제 자료를 인제스트해 뒷받침하거나 삭제할 수 있다.
자동으로 지우지 않는다.

## 9. 에러 처리

Electron IPC는 예외를 삼킨다. main에서 `throw`하면 renderer에는 스택도 타입도 없는
밋밋한 문자열만 도착한다. Tauri의 `Result<T, String>`이 강제하던 규율이 Electron에는 없다.

따라서 **IPC 핸들러는 절대 throw하지 않고 `Result` 객체를 반환한다.**

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: AppError }
interface AppError { kind: ErrorKind; message: string }
type ErrorKind = 'vault_not_found' | 'path_escape' | 'parse_failed'
               | 'llm_failed' | 'git_failed'
```

`kind`가 직렬화를 견디는 유일한 타입 정보이므로 renderer는 문자열 매칭이 아니라 `kind`로 분기한다.

경로 방어는 `vault/paths.ts` 한 곳에 모은다 —
`path.resolve` 후 볼트 루트 접두사 검사 + `realpath`로 심볼릭 링크 우회 차단.

## 10. 테스트와 통과 조건

- **vitest (순수)** — 링크 파서, 프론트매터, 인덱스 빌더, 경로 샌드박스
- **vitest (통합)** — 임시 디렉터리에 볼트 픽스처를 만들고 vault·index·git 실동작
- **에이전트** — LLM 호출은 스텁. 툴 호출 시퀀스를 검증
- **Playwright (e2e)** — 볼트 열기 → 노트 편집 → 백링크 표시

반드시 회귀 테스트로 고정할 두 가지:

- **CMap 배선** — `ADR-0010`이 0%로 낮춘 실패율의 회귀 방지선. 단 **PDF 픽스처를 쓰지 않는다.**
  pdf.js의 추출 실력은 `ADR-0010`이 이미 실측했고(5,765자 정확 추출),
  재구축에서 새로 깨질 수 있는 것은 실력이 아니라 **배선**이다.

  검사는 **`cMapUrl`이 가리키는 경로에서 `.bcmap` 파일 하나를 런타임에 실제로 읽는다.**
  파일 존재와 설정값 문자열만 대조하면 부족하다 — electron-builder는 앱을 기본적으로
  `asar`로 묶으므로, 소스 트리에 파일이 있고 설정값이 맞아도 런타임 경로가
  `app.asar/…`가 되어 로드에 실패할 수 있다. **dev에서 통과하고 패키징 후에만 깨지는**
  전형적 함정이고, 하필 7.1이 "빠뜨리면 그 14%가 그대로 돌아온다"고 경고한 지점이다.
  실제 읽기 한 번이면 asar 함정까지 잡힌다. PDF는 여전히 필요 없다.

  이 스모크 테스트는 **패키징된 앱에서도 돌린다.** dev 빌드에서만 돌리면 잡으려는 것을 놓친다.
- **되돌리기가 사용자 편집을 삼키지 않는다** — 에이전트 커밋 → 사용자가 같은 파일 편집 →
  [되돌리기] 시 사용자 편집이 살아남는지. 4.3의 실패 모드를 직접 겨눈다.

### 10.1 자동화하지 않는 검증

한글 학술 PDF의 **추출 품질**은 CI가 흉내낼 수 없다. 실제 논문을 그때그때 가져와
사람이 눈으로 원문과 대조하는 편이 낫다 — `ADR-0010`도 사용자 실제 PDF 14개를 손으로 재서
결론에 도달했다. 재배포 가능한 논문을 골라 픽스처로 만드는 비용보다,
필요할 때 손에 있는 논문으로 확인하는 쪽이 싸고 정확하다.

검증용 PDF는 커밋하지 않는다. 볼트가 앱 밖 폴더이므로 그냥 볼트에 넣고 인제스트하면 된다.

**v1 통과 조건 (엔진, 11.3의 4~6단계):** 빈 폴더를 볼트로 지정하고 →
PDF 1개를 인제스트하면 `wiki/`에 페이지가 생기고 커밋 1개가 남는다 →
그 위키를 근거로 질문에 답한다 → 답변을 수확하면 위키가 갱신되고 각주가 붙는다 →
`lint`가 깨진 링크·미검증 문단을 보고한다 → 되돌리면 원복된다.

**전 과정을 화면 없이 확인한다.** 결과는 `git diff`로 읽고,
만들어진 위키는 옵시디언으로 볼트를 열어 눈으로 본다.

**셸 통과 조건 (7단계):** 같은 흐름이 앱 안에서 동작한다 —
볼트 선택, 파일 넣기, 작업 실행, 진행 상황 표시, 되돌리기.

## 11. 구축 순서 — 엔진 먼저, 셸은 나중

### 11.1 UI는 v1의 목적이 아니다

당장 필요한 것은 **LLM이 위키를 만들고 · 위키를 근거로 답하고 · 위키가 계속 관리되는 흐름**이다.
화면은 그 흐름이 도는 것을 확인한 뒤에 붙인다.

그리고 이 세 가지는 **화면 없이 만들고 검증할 수 있다.** 에이전트가 다루는 것은 파일과 폴더뿐이고,
그 코드는 어차피 전부 `core/`(순수 Node)에 산다. Electron을 띄우지 않고 `node`로 돌릴 수 있다.

- LLM 호출은 느리고 비결정적이라 반복 실행이 잦다. 앱 재시작보다 스크립트 재실행이 훨씬 빠르다
- 결과 검증은 `git diff`로 끝난다 — 위키가 마크다운이므로
- 만들어진 위키를 눈으로 보려면 **옵시디언으로 볼트 폴더를 열면 된다.** 뷰어를 만들 이유가 없다

### 11.2 엔진과 셸의 경계 — 래핑을 싸게 유지하는 규칙

엔진은 **라이브러리**로 짓고 CLI는 얇은 호출자로 둔다.
그래야 나중에 Electron이 "호출자를 하나 더 붙이는 일"로 끝난다.

**진행 상황은 콜백으로 받는다.** `ingest`는 LLM을 여러 번 부르며 수십 초가 걸리므로
진행 보고가 필요한데, 여기에 `console.log`를 박으면 Electron 이전이 리팩터가 된다.

```ts
ingest(file, { onProgress: (msg) => void })
// CLI      → console.log 를 넘긴다
// Electron → win.webContents.send 를 넘긴다
// 엔진은 어느 쪽인지 모른다
```

엔진 안에서 금지: `process.argv` 직접 읽기 · `process.exit()` ·
`console.log`를 결과 전달 수단으로 쓰기. 셋 다 실행 환경을 엔진에 심는 행위다.

### 11.3 순서

각 단계는 그 자체로 실행 가능해야 하고, 앞 단계가 뒤 단계의 전제가 되도록 배열한다.

| 단계 | 내용 | 이 단계가 끝나면 |
|---|---|---|
| 0 | 새 레포 초기화 — 골격, 최소 CI, 12.3의 이식 | `npm run` 으로 뭔가 돈다 |
| 1 | `vault/` + `paths.ts` | 볼트 폴더를 읽고 쓴다 |
| 2 | `index/` — 링크 파싱·백링크·watch | `[[]]`에서 그래프가 파생된다 |
| 3 | `git/` + 경로 집합 + 되돌리기 | 되돌릴 수 있다 — **에이전트를 붙이기 전 필수** |
| 4 | `ingest/pdf.ts` + `llm/` + `agent/` | **PDF를 넣으면 위키가 생긴다** |
| 5 | `lint` · `processInbox` | **위키가 스스로를 정리한다** |
| 6 | 쿼리 세션 + 수확 + 출처 각주 | **답하고, 그 대화가 위키를 키운다** |
| 7 | Electron 셸 — 창·preload·IPC·최소 화면 | 앱에서 같은 일을 한다 |
| 8 | 편집 UI · 그래프 뷰 | 사람이 위키를 직접 다룬다 |

3단계를 4단계보다 앞에 두는 것이 중요하다. 안전망 없이 에이전트에게 쓰기 권한을 주면
첫 실수에서 볼트를 복구할 방법이 없다.

**4~6단계가 끝나면 제품의 핵심은 이미 동작한다.** 7단계부터는 같은 엔진에 얼굴을 붙이는 일이다.

## 12. 저장소 운영

**새 저장소를 판다.** 현재 레포(`C:\Users\dhkda\dev\piecepool`)는 손대지 않고 그대로 보존한다.

- 위치: `C:\Users\dhkda\dev\piecepool-next`
- 패키지·앱 이름: **`piecepool`** 그대로. 폴더명만 구분용이다
- 현재 레포는 읽기 참조용으로 남는다 — 삭제·개명하지 않는다

### 12.1 새 레포이므로 사라지는 제약

이 결정이 앞선 설계의 일부를 무효로 만든다. **기존 레포의 CI 배선은 새 레포에 존재하지 않는다.**

| 제약 | 기존 레포 | 새 레포 |
|---|---|---|
| `ssot-check.mjs`의 `docs/10-contracts/` 하드코딩 | 경로 고정 강제 | **없음** |
| lychee가 검사하는 계약 파일 링크 184곳 | 파일명 고정 강제 | **없음** |
| contracts owner 승인 + `contracts-change` 라벨 | 계약 변경 시 필수 | 폐기할 계약이 없음 |
| `CLAUDE.md`·`docs/20-backend/` 등 갱신 의무 | 방치하면 CI 적색 | 처음부터 새로 작성 |

따라서 2.2 트리의 `docs/contracts/{vault-layout,frontmatter,wikilink,ipc}.md`처럼
**처음부터 제대로 명명한다.** 번호 접두사(`10-contracts`)와 옛 파일명을 물려받지 않는다.

### 12.2 CI는 최소로 시작한다

`lint` · 타입체크 · 테스트만 둔다. `ssot-check` · `docs-check`(lychee) · `release-please`는
가져오지 않는다 — **지킬 계약이 쌓인 뒤에 의미가 생기는 장치**이고,
계약이 아직 한 줄도 없는 시점에 이식하면 반칙 보대가 더 크다.

필요해지는 시점의 신호를 미리 적어 둔다.

- `ssot-check` — 계약 문서가 3개를 넘고, 그 내용이 코드나 다른 문서에 복사되기 시작할 때
- lychee link-check — 문서 간 상대경로 링크가 늘어 수동으로 못 쫓을 때
- `release-please` — 배포를 시작할 때

### 12.3 현재 레포에서 가져오는 것

복사는 파일 단위로 하고, 가져온 것은 커밋 메시지에 출처를 남긴다.

| 대상 | 현재 레포 경로 | 비고 |
|---|---|---|
| 이 설계문서 | `docs/superpowers/specs/2026-09-05-*.md` | 새 레포의 첫 커밋 |
| ADR 원문 3건 | `docs/adr/000{3,5,7}·0010` | 근거 보존용. 상태는 `대체됨`으로 |
| 시각 언어 | `src/ds/primitives/` · `theme/` · `icons/` | 그대로 이식 (8단계에서) |
| 순수 파서 | `src/lib/` (callout·math·wikilink·retitleSync 등) | 발췌 후 `core/`로 재배치 |
| 에디터 설정 | `.editorconfig` · `.prettierrc.json` · `.nvmrc` | 그대로 |
| 라이선스 | `LICENSE` | 그대로 |

가져오지 않는 것: `src-tauri/` 전체 · `docs/10-contracts/` · `scripts/ssot-check.mjs` ·
`.github/workflows/` · `CHANGELOG.md` · `release-please-*`.

**`src/ds/`는 통째로 오지 않는다.** 두 층이 섞여 있다.

- `primitives/`(Button·Input·Card·Tabs…) · `theme/` · `icons/` — 기능과 무관하므로 그대로 온다
- `components/` — `ConceptGraph` · `GraphLegend` · `SubjectCard` 등은
  폐기되는 개념(`Concept` · `Subject` · 관계 타입 12종)에 묶여 있다. 오지 않는다

**화면(`src/app/` · `src/screens/`)도 오지 않는다.** `FeynmanPanel` · `RelationQuality` ·
`StudyHome`은 제거되는 기능이고, 남는 화면도 v1 구성이 달라 새로 짠다.
정리하면 **시각 언어는 상속, 화면은 새로**다.

### 12.4 새 레포의 ADR 번호

기존 ADR 이력을 승계하지 않으므로 **`0001`부터 다시 시작한다.**
첫 ADR이 이 재구축 결정 자체다 — `docs/adr/0001-electron-shell-llm-wiki.md`.
기존 `ADR-0005`·`ADR-0010`은 12.3으로 원문을 옮겨 두되, 새 번호 체계 밖의 참고 자료로 둔다.
