# PiecePool Desktop — 답변의 근거 표시를 위키 쪽으로 옮긴다 (B4) — 설계

- 날짜: 2026-09-18
- 상태: 구현·실측 완료 (2026-09-18). §8.3 참조
- 상위 문서: `2026-09-05-electron-rebuild-design.md` §8 · `intent.md` "답한다"·"자란다" 기준
- 선행: `2026-09-17-query-session-design.md` (B1) · `2026-09-18-query-harvest-design.md` (B3)
- 대체: B1 §3(근거 대조)·§11.2 · B3 §2 결정 1(③ 측정 뒤 거르기)

## 1. 무엇을 바꾸나

**답변은 위키를 먼저 찾되 위키에 매이지 않고, 근거 표시는 답변이 아니라 위키(수확)에서 남긴다.**

B1 이 얹은 문단 링크 `[[페이지#절]]` · `cite.ts` · `unsourced` 계기를 걷어낸다.
화면에만 코드가 "본 페이지" 한 줄을 붙인다. 로그와 수확 입력은 바뀌지 않는다.

### 1.1 왜 — "위키에 없으면 모른다" 는 원칙이 아니었다

`intent.md` 의 "묻는다 — 위키를 열지 않고 대화로 답을 얻는다" 와 여섯 원칙 어디에도 "위키에 있는 것만 답한다" 는 없다.
그 규칙은 B1 §3.1–3.3 이 밝힌 대로 **수확이 대화 전체를 자료로 보고 `quote` 대조를 하는데, 대조가 ①②③ 을 못 가르니
애초에 ③(AI 사전지식)이 답변에 안 나오게** 프롬프트로 막은 것이다. 그 위에 문단 링크와 `cite.ts` 를 얹었다.

인과가 거꾸로였다. "수확이 AI 턴을 먹는다 → AI 가 위키 밖 말을 못 하게 하자" 가 사용자 경험(새 질문에 답 못 함)을 희생시켰다.
원칙 5 는 "위키에 안 들어간다" 이지 "AI 가 입에 못 올린다" 가 아니다.

### 1.2 원칙 5 는 "자란다" 가 지킨다

수확에서 AI 턴의 문장은 셋 중 하나이고, **처리가 갈리지 않는다.**

| 문장의 정체     | 수확에서                               | 문단 링크가 필요한가                    |
| --------------- | -------------------------------------- | --------------------------------------- |
| ① 위키 되풀이   | 기록 중복 검문이 막는다 (B3 §7.4 실측) | 아니오                                  |
| ② AI 의 새 종합 | `(AI)` 달고 들어간다                   | 아니오 — 턴 헤딩으로 충분               |
| ③ 일반 지식     | `(AI)` 달고 들어간다                   | 아니오 — **②와 같은 꼬리표, 같은 처리** |

`(AI)` 는 답변의 링크가 아니라 **세션 로그의 `## N턴 (AI)` 헤딩**에서 온다 (`build.ts` 의 앵커 판정 · `write.md` "AI 턴을 근거로 새 사실을 만들지 마라").
B1 이 "수확이 ①②와 ③을 가르려면 로그에 재료가 있어야 한다" 고 했는데, **가를 필요가 없었다.** 턴 단위 `(AI)` 가 이미 그 재료다.

그러니 일반 지식 답변을 허용해도 원칙 5 는 `intent.md` "자란다 — 대화 출신 문장은 표시가 남는다" 쪽에서 그대로 지켜진다.
"답한다" 는 원칙 5 의 짐을 내려놓는다.

## 3. 프롬프트 — `prompts/query.md`

- 규칙 1 → **"먼저 위키를 찾으십시오. 있으면 그것으로 답하십시오."** 사용자가 적어 둔 것이 있는데 일반 답을 주는 것을 막는 것이 이 규칙의 남은 역할이다
- 규칙 2(문단마다 근거) → **삭제.** `[[페이지#절]]` 문법 설명과 "연 적 없는 절을 가리키지 마십시오" 도 나간다. 코드 블록 예외가 생긴 원인이 이 문법 설명이었다
- 규칙 3(다른 말로 다시 찾기) · 4(대명사) · 5(짧게) 는 그대로

## 5. 문서

- **`intent.md` "답한다"** → _"위키를 먼저 찾아 답하고, 답 끝에 어느 페이지를 봤는지 붙는다"_. 기계로 확인 가능한 것만 남긴다 — "먼저 찾는다" 는 툴 호출 로그, "붙는다" 는 코드가 만든다
- **B1 설계 상태 줄**에 "§3(근거 대조)·§11.2 는 `2026-09-18-query-answer-grounding-design.md` 로 대체" 한 줄

## 6. 두 설계문서 충돌 기록

상위 §8.2 는 대화를 ①②③ 으로 나누고 ③ 을 "오염" 이라 부르며, B1 은 그것을 "답변에서 ③ 이 안 나오게 한다" 로 읽었다.
이 문서는 **세 분류와 `(AI)` 꼬리표 논리는 그대로 두고, "답변에서 막는다" 는 읽기만 폐기한다.** ③ 은 위키에 `(AI)` 달고 들어가며
다음 정리가 근거로 못 쓴다 — 그것이 §8.2 가 원래 규정한 방어("문단 층 꼬리표")이고, 답변 링크는 거기 없었다.
0단계 §15 이탈 목록에 없던 것이라 여기 적는다.

## 7. A 에게 알릴 것

**세션 출신 본문 절에 표시가 없다** (B1 §3.2 표: `(AI)` 는 기록 줄에만 붙고, `new_sections` · `replace_sections` 로 들어가면 흔적이 없다).
답변에 일반 지식이 자유롭게 나오면 이 구멍이 전보다 넓어진다. 기록 줄의 `(AI)` 를 본문 절에도 남기는 것은 `ingest/build.ts` 일이라
요청만 적는다. 이번 범위에서 A 구역 코드를 건드리지 않는다.

### 8.3 첫 실측 (2026-09-18, K3, 실비 $0.04)

`fixtures/vault-life` 를 임시 폴더로 복사해 돌렸다.

| 통과 조건 (§8.2)   | 결과                                                                                                                                                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 위키에 있는 질문 | "무릎 아픈 거 어떻게 됐지?" → `툴: search {"query":"무릎"}` 있음. `참고: [[가설검정]] · [[달리기]] · [[민지]] · [[앱 아이디어]] · [[키 (데이터베이스)]]`. 답변 본문: "위키에 따르면, 9월 15일에 괜찮아져서 다음 날 다시 뛸까 고민 중이라고 적혀 있습니다. 9월 13일에는 달리기를 쉬었고요." — `[[` · `#절` 잔해 없음 |
| ② 위키에 없는 질문 | "러닝에서 10% 규칙이 뭐야?" → 답은 나왔다(모른다고 하지 않음). 그런데 `참고: [[달리기]] · [[딥러닝]] · [[모두테크 데이터 인턴 지원]] · [[앱 아이디어]]` 가 떴다 — `달리기.md` 에 "10% 규칙"이 앱 아이디어 메모로 이미 있어 "위키에 없는 질문"이라는 전제가 깨졌다 (§ 함께 드러난 것)                                |
| ③ ②를 수확         | `y` → `git -C "$VAULT" show --stat HEAD` 커밋 1개(`372ac9b2`, 6개 경로). `grep -rn "(AI)" wiki/` 로 `wiki/10% 규칙.md` 두 줄·`wiki/달리기.md` 한 줄에 `(AI)` 확인. 수확 자체의 ingest LLM 호출은 $0.0476 (세션 `usd:` 와 별도 — 아래 실비 계산에서 뺐다)                                                            |
| ④ 본문 잔해        | 있음. ①의 답변은 깨끗했지만, ②의 답변 첫 문장 "위키 `[[달리기]]` 노트에도 관련 내용이 있네요 — …" 에 `[[...]]` 잔해가 그대로 남았다                                                                                                                                                                                 |
| ⑤ 자신에 관한 질문 | "작년에 어디 여행 갔지?" → 지어내지 않았다. "위키에서 여행 관련 기록을 찾지 못했어요… 혹시 '작년 여행'을 노트에 적어두신 적이 있나요?" 로 되물었다                                                                                                                                                                  |

**함께 드러난 것 (범위 밖, 보고만):**

- **참고 줄이 관련성과 무관하게 뜬다.** ②에서 위키에 진짜 관련 내용이 조금이라도 있으면(앱 아이디어로 스친 메모라도) 그 페이지가 열려 참고 줄에 오른다. ⑤(여행 질문, 위키에 전혀 없음)에서도 `search` 가 훑고 지나간 무관한 페이지 11개(`CPU 스케줄링`·`가설검정`·`탄력성` 등)가 참고 줄에 그대로 올랐다 — 참고 줄은 "답에 쓴 근거"가 아니라 "이번 턴에 연 페이지 전부"를 반영한다
- **대화 모드 CLI 는 실제 LLM 지연(수십 초) 동안 입력을 놓친다.** `printf '...\n\ny\n' | node ...` 처럼 한 번에 stdin 을 밀어 넣으면, `ask()` 가 도는 동안 `rl.question()` 이 대기 중이 아니라서 그 사이 도착한 줄(빈 줄·`y`)이 유실되고 `readline was closed` 로 죽는다. 응답이 끝난 뒤 그때그때 입력을 흘려보내야 재현된다 — 브리핑의 재현 명령을 문서 그대로 실행하면 실측이 한 번 실패한다
- **첫 수확은 볼트 git 초기화 커밋을 하나 더 만든다.** 이 임시 볼트가 처음 git 통제 아래 들어가면서 `91deb11 chore(vault): 사용자 편집 봉인` 이 `372ac9b` 앞에 따로 찍혔다. `git show --stat HEAD` 로 보는 "수확 커밋 1개"는 변함없지만, 새 볼트의 첫 수확은 로그에 커밋이 2개 남는다

- 참고 줄의 UI 표현 · 세션 이어하기 — B2
- 본문 절 `(AI)` 표시 — A (§7)
- **위키 + 일반 지식 섞기** — 규칙 1 은 아직 "있으면 위키로만, 없으면 일반 지식" 의 양자택일이다. 위키를 먼저 말하고 일반 지식을 덧붙이는 쪽으로 바꾸려면 프롬프트 엔지니어링과 실측이 따로 필요하다. 별도 세션 (2026-09-19 논의). 지킬 것: 사용자가 적어 둔 사실을 일반 지식으로 바꿔치기하지 않는다

## 10. 기각한 대안

- **사용자 턴만 수확.** 답변 링크 없이도 ③ 이 위키에 못 들어가는 가장 단순한 길이었으나, 상호작용의 정보(AI 제안에 사용자가 동의한 것)를 잃는다. 사용자 결정
- **참고 줄을 답변 텍스트에 남김.** 로그만 읽어도 어느 턴이 어느 페이지를 봤는지 보이지만, 프론트매터 `opened:` 가 그 정보를 이미 갖는다
- **규칙 1 유지 + 문단 링크만 제거.** "위키에 없으면 모른다" 가 남으면 새 질문에 답 못 하는 사용자 경험이 그대로다. 규칙 1 의 존재 이유가 §1.1 대로 사라졌으므로 같이 뺀다
- **"위키에 없다" 고 말하게 함.** 프롬프트 행동은 확인이 안 되고 소음 위험이 있다. 사람이 답을 읽으면 안다
- **답변의 `[[페이지]]` 를 코드로 뗌 (실측 ④ 뒤, 2026-09-19).** K3 는 규칙 없이도 위키 문법을 따라 링크를 쓴다. 떼지 않는다 — B2 UI 에서 클릭 가능한 링크가 되고, 수확되면 `(AI)` 기록 줄의 살아 있는 링크다. ingest 는 `[[` 를 파싱하지 않아 해가 없고, 없는 페이지를 가리키면 `lint` 의 `broken_link` 가 잡는다 (상위 §5.1 "검증은 관찰"). `cite.ts` 의 축소판을 다시 만들 이유가 없다
