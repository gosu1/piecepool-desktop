# ingest 합의 안건 — 4단계 착수 전에 팀이 정할 것

작성 2026-09-15. 근거는 [ADR-0002](adr/0002-agentic-pipeline.md) 와 [밤샘 실험](experiments/2026-09-15-밤샘실험/README.md). 이 문서는 회의용이다 — 결정되면 ADR 과 CLAUDE.md 를 고치고 이 문서는 지운다.

**결정 없이는 4단계를 시작할 수 없는 것이 1·2·6 이다.** 나머지는 시작 뒤에 정해도 된다.

---

## 1. `Fm` 4필드 → 5필드 (동결 파일 · 테크리드)

`src/shared/types.ts` 의 `Fm` 은 위키 페이지와 사용자 노트가 함께 쓴다. 위키 페이지가 쓰는 5필드(ADR 결정 5)를 더하고, 우리가 쓰지 않는 두 필드는 **지우지 않고** 표시만 한다 — 사용자 노트에 있는 `title` · `updated` 는 그대로 보존해야 하고, B 가 읽을 수도 있다.

```diff
 export interface Fm {
+  /** 사용자 노트에만. 위키 페이지는 파일명이 식별자라 쓰지 않는다 (ADR-0002 결정 5). */
   title?: string;
   created?: string;
+  /** 사용자 노트에만. 위키 페이지는 쓰지 않는다 — 앱 편집기와 AI 가 번갈아 건드리면 신뢰도를 잃는다. */
   updated?: string;
   /** append-only. 덮어쓰지 않는다 — core/vault/frontmatter.addSource 참조. */
   sources?: string[];
+  /** 같은 것을 가리키는 다른 표기. 링크 해석은 파일명 > 단일 별칭 > 충돌 시 해제 (결정 9). */
+  aliases?: string[];
+  /** AI 가 마지막으로 정리한 시각. ISO 8601. 코드만 쓴다. */
+  compiledAt?: string;
+  /** H2 절 이름 → 내용 sha256 앞 8자리. 일치 = 우리 글, 불일치 = 사용자 편집, 없음 = 지킨다 (결정 5). */
+  hashes?: Record<string, string>;
 }
```

- 전부 optional 이라 기존 코드는 깨지지 않는다.
- `hashes` 는 중첩 YAML 이다. 파서(`core/vault/frontmatter`)가 이것을 읽고 써야 한다 — A 의 일.
- 출처 페이지(`sources/@원본.md`)의 프론트매터(`type` · `raw` · `raw_hash` · `date` · `created`)는 **별개 타입**으로 둔다. `Fm` 에 섞지 않는다 — 규칙이 다른 파일이다(결정 6).

## 2. `Vault.agentWriteRoot` 단일 → 셋 (동결 파일 · 테크리드)

에이전트가 쓰는 경로가 `wiki/` 하나가 아니다. 결정 6 이 출처 페이지를 `sources/` 에, 파생 캐시를 `.piecepool/` 에 둔다.

```diff
 export interface Vault {
   root: string;
-  /** 에이전트가 쓸 수 있는 루트. 기본값은 "wiki". 설정에서 바꿀 수 있다. */
-  agentWriteRoot: string;
+  /**
+   * 에이전트가 쓸 수 있는 루트들. 기본값은 ["wiki", "sources", ".piecepool"] (ADR-0002 결정 6).
+   * wiki/ 는 위키 페이지, sources/ 는 원본 복사본과 출처 페이지, .piecepool/ 은 파생 캐시.
+   * 출력 벽 4 (경로 제한) 가 이 목록으로 판정한다.
+   */
+  agentWriteRoots: readonly string[];
 }
```

`vault/paths.ts` 의 경로 검증이 이 목록을 본다. 사용자 노트 폴더는 여전히 못 쓴다.

## 3. 수확 경로 — A 가 열어두고 B 가 꽂는다 (B)

ADR "합의가 필요한 안건 → 수확 경로" 에 넷을 적었다. 요약만.

| A 가 준비하는 것                                                                                                                    | B 가 정하는 것                                                                                                  |
| ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 볼트 노트가 아닌 입력 진입점 — `ingest({ kind: "session", id, log })` 가 "본문 + 출처 이름 + 날짜" 를 받는다                        | 언제 부르나 ([위키에 반영] 버튼), 로그를 어떤 형태로 넘기나                                                     |
| **세션 로그의 `quote` 대조는 사용자 발화에서만.** 승격 조건을 없앴으므로 "AI 의 답은 출처로 안 센다" 를 검문의 대조 범위가 보장한다 | role 이 붙은 로그를 넘길지, 사용자 턴만 본문으로 넘길지                                                         |
| 같은 빌더와 `hashes` 로 쓴다                                                                                                        | —                                                                                                               |
| —                                                                                                                                   | 세션 로그에 출처 페이지(`sources/@session-<id>.md`)를 만들지. 기록 줄의 `← [[출처]]` 가 살아 있으려면 만드는 쪽 |

## 4. 앱 편집기는 위키를 저장할 때 `hashes` 를 건드리지 않는다 (A·B, 8단계 전 확정)

갱신하면 사용자가 고친 절이 "우리 글"로 판정되어 다음 정리에서 덮인다. 사용자 글이 정리 한 번만 버틴다. 편집기는 프론트매터를 읽은 그대로 다시 쓴다.

CLAUDE.md §4 에 한 줄 추가 제안: **"앱 편집기는 `hashes` 를 갱신하지 않는다. 갱신은 ingest 빌더만 한다."**

## 5. `agent/tools.ts` 의 동결 등급 (A·B)

정리하기(ingest)는 툴 6종을 쓰지 않는다 — AI 는 JSON 을 내고 코드가 파일을 쓴다(결정 2). 그러면 이 파일은 query 의 읽기 3종(`read_note` · `search` · `backlinks`)만 남거나 통째로 안 쓰인다. **B 가 query 에서 툴을 계속 쓸지 정하면 등급이 정해진다.** A 는 어느 쪽이든 상관없다.

## 6. 모델 (팀)

### 채팅 — Kimi 로 갈 때 확인된 것

|                    | 사실                                                                                                                                                                                                                                                                                                            | 출처                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 엔드포인트         | OpenAI 호환 `https://api.moonshot.ai/v1`. 우리 `llm.ts` 는 `PIECEPOOL_LLM_BASE_URL` · `PIECEPOOL_LLM_MODEL` 만 바꾸면 된다                                                                                                                                                                                      | 공식 문서            |
| 모델               | `kimi-k3` (2026-07 출시, 2.8T, 컨텍스트 1M, **추론 항상 켜짐**) · `kimi-k2.6` (추론 켜고 끌 수 있음)                                                                                                                                                                                                            | 공식 문서            |
| Structured Outputs | `response_format: {type: "json_schema"}` 지원. 단 스키마가 **MFJS**(Moonshot Flavored JSON Schema)를 따라야 한다 — 모든 노드에 명시적 `type`, 최상위는 객체. **우리 스키마의 `summary: { type: ["string", "null"] }` (타입 배열) 이 통과하는지 확인 필요.** 안 되면 `anyOf: [{type:"string"},{type:"null"}]` 로 | 공식 문서, MFJS 명세 |
| 가격               | K3: 입력 $3 / 출력 $15 / 캐시 히트 $0.30 (per 1M tokens). K2.6 은 더 쌈                                                                                                                                                                                                                                         | 공개 가격표          |
| 임베딩             | **없다.** 별도 공급자 필요                                                                                                                                                                                                                                                                                      | 공식 문서            |

**비용 추정 (62장 볼트 한 번)**: 입력 62 × 5k = 310k → $0.9, 출력 62 × 2k = 124k → $1.9, 추론 토큰이 출력으로 과금되므로 K3 는 여기에 더 붙는다. **한 번에 $3~6.** 사용자가 달에 60장 넣으면 그 정도. 개인 무료 티어(PLG 1단)에서는 부담이다.

**결정할 것**: 정리하기(ingest)에 K3 를 쓸지 K2.6(추론 끔)을 쓸지. ingest 는 구조화된 추출이라 추론이 꼭 필요하지 않다. ADR 미결 "단계별 모델 배치"가 이것이다 — **정하고 5회차를 그 모델로 한 번 돌려 지표를 다시 받는다.**
