## 왜 이 문서가 있나

`piecepool2` 는 팀 레포에서 갈라져 나온 실험 포크다. 거기서 **세컨드 브레인 방향을 다시 설계하고
실제로 돌려 숫자를 냈다.** 이 레포를 새로 시작하면서 그 조사와 자산이 흩어지면 아깝다.

**코드를 옮기라는 문서가 아니다.** 스택도 구조도 다르다. 옮길 값이 있는 것은 **판단의 근거**와
**실측 숫자**, 그리고 **프롬프트 명세**다.

## 1. 바로 쓸 수 있는 것 (입력·위키 구간)

### P2·P7 프롬프트 명세 — 가장 값나가는 것

```
piecepool2/docs/30-llm/prompts/p2-extract.md   22KB
piecepool2/docs/30-llm/prompts/p7-rewrite.md   12KB
```

노트에서 **이름과 사실을 뽑는 프롬프트**(P2)와 **기록 전체에서 요약·본문을 다시 쓰는
프롬프트**(P7)의 완성된 명세다. 각각 입력 스키마 · 출력 스키마 · 종류별 블록 · 예시 · eval 지표를
갖췄고, **실측으로 게이트를 통과한 상태**다.

> **이 레포의 방향과 다른 점:** 여기 ADR-0001 은 "에이전트가 파일을 직접 편집" 인데, P2·P7 은
> "코드가 조율하고 LLM 은 구조화된 JSON 만 낸다" 는 다른 접근이다. **그대로 쓸 수는 없다.**
> 다만 **프롬프트 안의 규칙들**은 접근과 무관하게 값이 있다. 예를 들어 이런 것들이다.
>
> - `quote` 를 원문에서 그대로 복사하게 하고 **코드가 대조하는 것**이 유일한 환각 방어다
> - 기록에 없는 문장을 금지하고, **문장마다 근거 기록 번호**를 달게 한다
> - "그릇(회의·강의·책 자체)은 중심 이름이 아니다" — 이걸 안 적으면 회의록 자체가 페이지가 된다
> - 종류(회의록·일기·레시피·감상·참고자료)마다 지침 한 줄만 갈아 끼운다. 프롬프트를 복제하지 않는다

### 검색층 — BM25 + 한국어 n-gram

```
piecepool2/src/lib/search/     순수 함수 (bm25, chunk, tokenize)
piecepool2/src/lib/search.ts   파사드
piecepool2/docs/superpowers/specs/2026-09-02-search-index-design.md
```

한국어를 **1·2·3 글자 n-gram** 으로 잘라 색인한다. 형태소 분석기 없이 조사가 붙은 말을 잡는다.
claude-obsidian(12,144★)이 같은 방식으로 고친 것을 확인하고 가져온 것이다.

첫 실측 `recall@5` 0.40. 놓친 것 중 여럿이 **링크를 지우면 정답 단서가 질의에서 함께 사라지는**
모양이라 글자만으로는 닿을 수 없다 — 뜻 검색(임베딩)을 켤지는 아직 미결이다.

### eval 하네스

```
piecepool2/scripts/evals/core.ts       러너
piecepool2/scripts/evals/adapters/     p2·p4·p5·p6·p7·search·ocr·chunk …
piecepool2/docs/30-llm/evals/          픽스처 · 정답지 · 실측 결과
```

**게이트를 깨졌다고 낮추지 않는다**는 규칙과, 지표가 없거나 `NaN` 이면 실패로 판정하는 규칙이
들어 있다("0건 측정하고 초록불" 을 막는다).

### 샘플 위키 세 장

```
piecepool2/fixtures/wiki/{김대리, 재귀, 듄 파트2}.md
```

**형식은 이 레포와 다르다**(프론트매터 12필드 vs 여기 `Fm` 4필드). 하지만 **내용과 서술 방식**은
참고가 된다. 종류를 셋으로 갈라 각각 다른 것을 시험하게 만들었다.

- **김대리**(사람): 닫힌 기록(`~날짜`), 할 일(`[ ]`), 대화가 출처, **요약이 메타를 이기는 자리**
  (`relation` 은 "같은 팀" 인데 기록에 이동이 있어 과거형으로 씀)
- **재귀**(주제): 생각이 시간에 따라 바뀌는 서술. 교과서와 다른 점이 여기다 — "재귀란 무엇이다"
  가 아니라 **이 사람이 언제 무엇을 알았는지**가 남는다
- **듄 파트2**(작품): 창작자·별점·다시 본 기록. 관련 링크가 하나뿐인 **얇은 페이지**

## 2. 실측 숫자 (다시 재지 않아도 되는 것)

### OCR — 별도 엔진 없이 vision LLM 하나로

| 지표       | 실측       | 허용   |
| ---------- | ---------- | ------ |
| 인쇄체 CER | **0.0000** | ≤ 0.15 |
| 손글씨 CER | **0.1163** | ≤ 0.30 |

손글씨는 **태블릿에 직접 쓴 필기**로 잰 것이다. Tesseract 계열이 가장 못하는 영역인데 vision LLM 이
CER 0.12 로 읽었다. (표본 2건이고 재실행 시 손글씨가 0.0465→0.1163 으로 흔들렸다 — 모델 우열을
가리는 데는 못 쓰지만 "별도 OCR 엔진이 필요한가" 를 가리는 데는 충분하다.)

**정확도보다 중요한 이유가 따로 있다.** 저장 형태가 3-블록이다 — [텍스트 그대로] · [사용자 설명] ·
**[그림 설명 — AI 해석]**. 세 번째는 글자를 읽는 일이 아니라 **이해하는 일**이라 OCR 로는 원리적으로
만들 수 없다. 도표가 그려진 판서 사진이면 글자만 뽑아서는 쓸모가 없다.

## 3. 판단의 근거 (조사 노트)

```
piecepool2/docs/00-overview/research-2026-08-26-page-model.md
```

LLM 위키 레포 12개와 세컨드 브레인 실패 사례를 훑은 것이다. **가장 값나가는 부분은 실패 원인
분류표 10가지**와, 각각에 대해 "우리 안은 취약한가" 를 판정해 둔 칸이다.

| 실패 패턴                                                           | 판정                                                                             |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **수집가의 오류** — 저장을 이해로 착각. 10,000노트 7년 뒤 전부 삭제 | 부분. **읽는 비용을 LLM 이 낸다**                                                |
| **다시 읽지 않음** — 노트 75%가 쓴 뒤 한 번도 수정 안 됨            | 아니오. 대화가 답을 내므로 페이지를 안 열어도 된다                               |
| **링크 의례** — 링크 만드는 시간이 따라가는 시간보다 김             | 부분. **사용자가 안 달고 LLM 이 단다.** 다만 LLM 이 과잉 링크를 만들면 같은 증상 |
| **분류 어휘 표류** — `#레시피`·`#요리`·`#recipe` 공존               | **예.** LLM 이 태그를 만들면 실행마다 어휘가 달라진다                            |
| **이름 동일성 실패** — "이수현"·"수현 님"·"SH" 가 세 사람으로       | **예, 핵심.** 별칭 수집이 성패를 가른다                                          |
| **도구가 일보다 중요해짐** — 폴더 구조 다듬느라 저녁을 씀           | 아니오. **만지는 면이 노트·대화뿐**                                              |

그리고 통찰이 이렇다.

> **실패의 공통 뿌리는 "쓰는 비용 < 다시 읽는 비용".** LLM 이 대신 읽으므로 이 비대칭을 뒤집을 수
> 있고, **그것이 유일한 차별점이다.**

**PARA 에 대한 판정도 여기 있다** — 가져올 것은 배치 규칙이 아니라 "다시 만났을 때만 한 층
올린다" 는 **지연 원칙**뿐이다.

## 4. 이 레포와 다른 대목 (윤세훈이 정할 것)

**따르라는 것이 아니라 갈림길로 적는다.**

| 축                    | piecepool2                                                       | 이 레포(ADR-0001)               |
| --------------------- | ---------------------------------------------------------------- | ------------------------------- |
| LLM 이 위키를 쓰는 법 | **P2~P7 구조화 파이프라인.** 코드가 조율하고 LLM 은 JSON 만 낸다 | **에이전트가 파일을 직접 편집** |
| 환각 방어             | `quote` 원문 대조를 코드가 한다                                  | lint 가 나중에 관찰             |
| 프론트매터            | 12필드 계약(`type`·`kind`·`aliases`·`hashes` …)                  | **`Fm` 4필드 + 나머지 보존**    |
| 손편집 보호           | 절마다 지문(`hashes`)을 찍어 덮어쓰기를 막는다                   | 볼트 git 되돌리기               |
| 기록 줄               | `- YYYY-MM-DD 사실 ← [[출처]]` 엄격한 문법. 코드가 파싱한다      | 확인 못 함                      |

**한쪽이 옳다고 말하지 않는다.** 다만 각 선택에 딸린 대가를 적어 둔다.

- **구조화 파이프라인**은 환각을 코드가 막을 수 있지만(quote 대조), 프롬프트가 커지고 단계가 많다
- **에이전트 직접 편집**은 유연하지만, **무엇이 왜 바뀌었는지를 사후에만 알 수 있다.** 볼트 git 이
  그래서 안전망으로 필요한 것이다
- **12필드 계약**은 정리 상태를 파일에 담을 수 있지만(`compiledAt`·`hashes`), 남의 옵시디언 볼트를
  열면 그 필드가 없다
- **4필드 + 보존**은 남의 볼트를 안 망가뜨리지만, "이 페이지를 언제 정리했나" 를 파일 밖에 둬야 한다

## 5. 이 포크에서 닫은 결정과 근거

이 레포의 판단과 겹치는 것도 있고 다른 것도 있다. 근거만 옮긴다.

| 결정                          | 근거 요약                                                                                                                                                            |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **모델은 Gemini, 로컬 폐기**  | 무료 한도가 결정적. 로컬은 도구 호출 능력 측정을 전제로 미뤄 뒀으나 **측정 없이 닫았다** — 얻는 것(키·비용)보다 잃는 것(품질·속도·도구 호출 신뢰도)이 크다           |
| **API 키는 사용자 발급**      | 우리가 키를 대려면 서버가 필요하고, 서버가 생기면 **사용자 노트가 우리를 거쳐 간다** — "파일이 원천" 과 충돌                                                         |
| **에디터는 CodeMirror 6**     | ProseMirror·Lexical 계열은 JSON 블록이 진실이라 마크다운과 왕복하며 정보가 샌다. 직접 만드는 길은 AppFlowy 가 비용을 보여 준다(자체 에디터를 처음부터 만들어야 했다) |
| **볼트는 사용자가 고른 폴더** | 위치를 코드에 박으면 기존 옵시디언 볼트를 못 열고 동기화·git 관리도 안 된다. **이 레포도 같은 자리에 도착했다**                                                      |
| **space(하위 공간) 폐기**     | space 를 강제하면 사용자에게 정리를 요구하는 셈이고, 그건 우리가 없애려던 바로 그 비용이다. 나누는 축은 볼트 하나로 둔다                                             |
| **키 없이도 절반이 돈다**     | 노트 쓰기·파일 트리·검색(BM25 는 로컬)·위키 읽기는 키가 필요 없다. 정리하기와 대화만 필요하다. "키 없이도 괜찮은 노트 앱" 으로 먼저 쓰게 할 수 있다                  |

## 6. 아직 아무도 안 푼 것

|                              |                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **손편집 구역 표시**         | 사용자가 위키를 손으로 고쳤을 때 다음 정리에서 덮지 않는 방법. piecepool2 는 절마다 지문을 찍는 방식을 썼으나 **마커 문법은 미결**로 남겼다 |

| **`[[대화/…]]` 링크의 실체** | 대화 기록이 JSON 이면 옵시디언에서 깨진 링크가 된다. 볼트에 마크다운 사본을 둘지 미결                                                       |
| **뜻 검색(임베딩)**          | `recall@5` 0.40. 채점표가 15건뿐이라 아직 이르다                                                                                            |
