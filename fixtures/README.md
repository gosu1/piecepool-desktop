# 픽스처 — 시연과 측정의 기준

`vault/` 는 **실제 사용자의 볼트를 흉내낸 것**이다. 학부 연구생이 강의를 들으며 쓴 노트와, 논문을 읽으며 막힌 기록이 들어 있다.

이 폴더는 두 가지에 쓰인다.

| 무엇     | 어떻게                                                                |
| -------- | --------------------------------------------------------------------- |
| **시연** | 이 볼트에 파이프라인을 돌려 위키가 만들어지는 것을 보여준다           |
| **측정** | ADR-0002 의 미결 세 항목(누락률·임베딩 파라미터·`fact` 이탈률)을 잰다 |

---

## 노트가 왜 이렇게 생겼나

**잘 정리된 노트를 일부러 쓰지 않았다.** 사업계획서 1-1 "나" 절의 문제 정의가 이것이다.

> 노트북 필기자는 **더 많은 단어를 기록하지만 인지적 처리 없이 그대로 옮겨 적으며**, 이것이 학습을 저해한다
>
> 노트를 열자 필요한 내용은 거기 있었다. **그런데 내가 쓴 글인데도 낯설었다.**

노트가 깔끔한 요약이면 이 문제가 재현되지 않는다. 그래서 일부러 이렇게 두었다.

- 필사한 항목들이 이어지고, 이해한 것과 못 한 것이 섞여 있다
- "못 따라감", "감이 안 온다" 같은 기록이 남아 있다
- 슬라이드 번호만 적고 내용은 빠진 자리가 있다
- 같은 개념을 여러 주차에 걸쳐 조금씩 이해한다

## 이 볼트가 시연하는 것 다섯

### 1. 제품의 출발점이 된 문제 그 자체

`2026-09-10-DETR 읽기.md` 에 이 대목이 있다.

> 여기서 막혔다. **디코더가 뭐였는지 기억이 안 난다.**
>
> 8주차에 배운 것 같은데 (...) 노트를 찾아야 한다. 3학년 1학기 딥러닝 폴더에 있을 텐데 **몇 주차인지 모르겠다.**

사업계획서의 개발 동기와 같은 상황이다. 노트는 있고 위치도 대략 알지만, 어느 대목인지 몰라 다시 찾는 비용이 발생한다.

### 2. 글자 일치로는 찾을 수 없는 연결

8주차 노트에는 있고 **DETR 노트에는 글자가 한 번도 나오지 않는** 개념들이 있다.

| 개념        | 8주차 | DETR 노트 | 그런데                        |
| ----------- | ----- | --------- | ----------------------------- |
| 위치 인코딩 | 있다  | **0번**   | DETR 도 위치 인코딩을 쓴다    |
| 멀티헤드    | 있다  | **0번**   | DETR 의 어텐션도 멀티헤드다   |
| 셀프 어텐션 | 있다  | **0번**   | DETR 인코더가 셀프 어텐션이다 |

`위치 인코딩` 페이지가 만들어져 있어도 **글자 일치로는 DETR 페이지와 이어지지 않는다.** 임베딩이 필요하다. ADR-0002 결정 3 이 임베딩을 기반으로 둔 근거를 이 볼트에서 확인할 수 있다.

반대로 글자 일치로 잡히는 것도 있다. "트랜스포머", "디코더", "CNN", "ResNet", "masked 어텐션" 은 DETR 노트에 그대로 나온다. **두 방법이 서로의 빈틈을 메운다**는 것도 같은 볼트에서 보인다.

> 이 표를 만들려고 노트를 고치지 않았다. 시연 포인트를 위해 글자를 빼면 자료가 인위적이 되고, 그러면 시연이 증거가 되지 못한다. 노트를 먼저 쓰고 그 안에서 사례를 찾았다.

### 3. 같은 주제에 노트가 둘

4주차와 6주차가 모두 CNN·dilation·필터 크기를 다룬다. 하나의 위키 페이지에 두 노트의 내용이 합쳐져야 한다. 병합과 `hashes` 를 시연하는 자리다.

### 4. 이해가 시간에 걸쳐 발전하는 과정

| 4주차                                     | 6주차                                            |
| ----------------------------------------- | ------------------------------------------------ |
| "1x1 도 있다는데 이건 왜 쓰는지 모르겠음" | "1x1 컨볼루션도 답해주심 — 채널 방향으로 섞는다" |
| "dilation 이 제일 헷갈린다"               | "dilation 다시 물어봄 — 원소 사이에 간격을 둔다" |
| "보통 3x3 을 쓴다"                        | "3x3 두 번이 5x5 한 번보다 파라미터가 적다"      |

기록 줄이 시간순으로 쌓이면 이 발전이 한 페이지에서 보인다. **요약만 남기면 사라지는 것**이 이것이다.

### 5. 링크 밀도 기준선

사업계획서의 실측이 이렇다.

| 볼트                              | 문서당 본문 링크 수 |
| --------------------------------- | ------------------- |
| 손으로 관리한 한국어 볼트 (132장) | **1.5**             |
| 자동 생성 방식의 이전 시도        | **0.1**             |

이 볼트에서 만들어진 위키가 1.5 에 얼마나 가까운지가 성공 기준이다.

## 원본 PDF

**커밋하지 않는다.** 용량이 크고 저작권 판단이 필요하다. `.gitignore` 에서 제외하고 있다.

시연하려면 아래를 받아 `vault/sources/` 에 둔다.

| 파일                            | 어디서                     |
| ------------------------------- | -------------------------- |
| `Attention is all you need.pdf` | `arxiv.org/abs/1706.03762` |
| `DETR.pdf`                      | `arxiv.org/abs/2005.12872` |

실제 논문을 쓰는 이유가 있다. `CLAUDE.md` §7 이 **"한글 학술 PDF 의 추출 품질은 사람이 원문과 눈으로 대조해야 안다"** 를 사람의 몫으로 지정하고 있고, 그 검증에는 진짜 논문의 2단 조판·수식·표가 필요하다. 가상 PDF 로는 추출기의 실제 한계가 드러나지 않는다.
