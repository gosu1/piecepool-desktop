스레드

- 프로세스 안에서 실행되는 흐름. 프로세스 하나에 스레드 여러 개
- 같은 프로세스의 스레드끼리는 메모리(코드, 데이터, 힙)를 공유한다
- 스택과 레지스터는 스레드마다 따로

프로세스 vs 스레드

- 프로세스 만드는 게 스레드 만드는 것보다 훨씬 무겁다
- 프로세스끼리 통신하려면 IPC 써야 하는데 스레드는 그냥 메모리 공유
- 대신 스레드 하나가 죽으면 프로세스 전체가 죽을 수 있다

컨텍스트 스위치

- CPU 가 다른 프로세스로 넘어갈 때 지금 상태를 PCB 에 저장하고 다음 걸 불러옴
- 순수 오버헤드. 이 동안에는 아무 일도 안 한다
- 스레드 전환이 프로세스 전환보다 싸다. 메모리 주소 공간을 안 바꿔도 되니까

멀티스레드 모델: many-to-one, one-to-one, many-to-many. 리눅스는 one-to-one 이라고.

파이썬 GIL 얘기가 잠깐 나왔다. 파이썬은 스레드 여러 개 만들어도 한 번에 하나만 돈다고. 그래서 CPU 작업은 멀티프로세싱 써야 한다는데 이거 작년에 캡스톤 준비할 때 들었던 것 같다.

과제 1 나왔음. fork 로 자식 프로세스 만들고 파이프로 통신. 다음 주 월요일까지.

컨텍스트 스위치가 정확히 얼마나 걸리는지 물어봤는데 하드웨어마다 다르고 보통 마이크로초 단위라고 하심.
